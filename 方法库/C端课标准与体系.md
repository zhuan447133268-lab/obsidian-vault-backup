## 已沉淀要求

### 交付形态
- **C1 线上交付**：学员自装工具、各自网络环境，无网络 / 环境顾虑 → 平台绑定不必规避，可做成工具专属课。

### 体验与产出硬指标
- **C2 爽感是硬指标**：每个环节必须埋爽点（开场秀成品、亲手出第一份产物、开口改图的掌控感、邻座互看的社交认证、带走感）。
- **C3 当堂出成果是硬指标**：结课必须有学员自己跑出来的产物，不接受"看懂了但没做"。
- **C5 强实操性（线上）**：以动手为主，少讲多干；讲师少站在台上讲，多让学员做。线上课尤其不能变成"听讲座"。

### 内容边界
- **C4 不教学员方法论**：课堂不讲授分析框架 / 理论；学员通过跟做卡直接产出，不在课上花时间讲"为什么 / 框架"。方法可以隐性藏在工具输出和卡片引导里，但不单独成课、不当面教。

### 迁移与交付物
- **C6 可迁移到日常**：每节课选的课题 / 工具必须能迁移到学员日常学习或工作场景，不是一次性 demo。选题先问"学员明天能用上吗"。
- **C7 带走双份**：学员结课既带走"成果"（自己跑出来的产物 / 截图），也带走"跟做卡"（可复用于日常的 step-by-step 卡片）。跟做卡要写得以致换张表 / 换个案也能照做。

### 沿用课程设计铁律（用户定稿，C 端同样适用）
- 开场即产出（0–3 分钟第一份产出）
- 实操 ≥ 85%
- 小步循环（2′演示 + 8′跟做），讲师预制示范 + 学员跟做
- 不当众报课名 / 举手
- 每环节留一个"AI 干不了、必须你来"的动作
- 结课六文件（设计 / 课件 / 讲稿 / 测验 / 交互 HTML / 挑刺报告）

## 每次做 C 端课前 · 自检清单（P7 开干前逐条打勾）
- [ ] **C1** 是线上交付吗？学员自装、无环境顾虑吗？
- [ ] **C2** 埋了几个爽点？列出来（开场秀 / 第一份产物 / 改图掌控 / 互看 / 带走感）。
- [ ] **C3** 结课学员能带走什么具体成果？（截图 / 文件 / 成品）
- [ ] **C5 + 铁律** 实操占比 ≥ 85% 吗？讲师讲话时间压到最低了吗？
- [ ] **C4** 有没有在课上讲方法论 / 框架？有就砍，改由工具和卡片隐性承载。
- [ ] **C6** 课题学员明天能用上吗？工具 / 卡片是否通用（换表也能做）？
- [ ] **C7** 跟做卡写好了吗？学员结课是否同时拿到成果 + 卡？
- [ ] **铁律** 开场 0–3 分钟有第一份产出吗？小步循环（2′演示 + 8′跟做）安排了吗？
