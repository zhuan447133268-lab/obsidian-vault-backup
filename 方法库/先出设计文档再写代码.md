## 适用条件

**触发**：项目满足以下 **任意 2 条** 时，走这套流程：
- 涉及 ≥ 3 张数据库表
- 涉及 ≥ 3 个 API 端点
- 涉及 ≥ 3 个核心模块/服务
- 前后端都有改动
- 有复杂状态机或异步管线

**不触发**：单文件修改、小工具、纯前端页面、配置调整等。

---

## 流程

### 阶段一：让 Claude Code 出明细文档（设计）

> 这个项目先不要写代码。帮我按以下维度分别出设计文档，每份文档独立：
> 1. 数据模型（表结构、字段、关系、状态枚举）
> 2. 后端架构（包结构、文件清单、关键接口签名、状态机）
> 3. 核心管线/流程（入口、队列、分步逻辑、失败处理）
> 4. 运行时行为（路由、上下文构建、协议注入）
> 5. 前端设计（组件树、状态管理、API 封装、UI 变更点）
> 6. API 契约（端点清单、请求/响应 schema、错误码）

每份文档写完后，**停下来让用户确认**，不要继续下一份。

### 阶段二：人工确认（你拍板）

逐份审查，修改不合理的地方。**这一步 Claude Code 不参与决策。**

### 阶段三：按文档写代码（实现）

> 现在按以下文档写代码。**约束**：
> - 只实现文档里定义的内容，不要自由发挥
> - 每次改动后，对照文档验证接口签名/字段名/状态枚举是否一致
> - 偏离文档的地方先问我

### 阶段四：对照校验

> 逐个检查代码实现是否与设计文档一致，列出所有不一致的地方。

---

## 触发方式

- **自动建议**：Claude Code 分析项目复杂度，满足条件时主动建议走这套流程
- **手动触发**：用户直接说"按设计文档流程来"
- **最终决策权在用户**

---

## 核心理念

> 设计文档是人审的，代码是 AI 写的。把"想清楚"和"写出来"拆成两阶段，中间插入人工确认门。
