## 九之三、离线镜像包的三条获取路径（09-20 查官方文档后确认）

官方文档（doc.jygpu.com）关键结论：
- 「保存实例镜像」= 把实例系统盘保存成镜像，供自己的其他实例使用 → 保存成品在 **控制台 → 镜像仓库 → 我的镜像**（以**仓库镜像**形式存在，不是临时快照）
- 「下载已保存的镜像」（`/guide/image-download.html`）给了标准导出流程：在任意 docker 环境里 `docker login` 个人仓库 → `docker pull [仓库地址]/[项目名称]/IMAGE[:TAG]` → `docker save -o example.tar [该镜像]` → 下载到本地
- ⚠️ 文档**没有写镜像保留期限/自动删除**（既没承诺永久，也没说会过期）→ 「十五天后还在不在」只能打开控制台看一眼，30 秒

**路径 A（最快，不依赖 GPU）**：控制台确认 `hy3d-t2i-fixed` 还在 → 开**最小规格实例**（不需要 GPU，CPU 小实例即可，只要能用 docker）→ `docker login` 个人仓库 → `docker pull` 该镜像 → `docker save | gzip` → 下载 tar.gz。**不需要重新下载 18G 权重，也不需要重跑生成**。
**路径 B（最稳，完全绕开云镜像）**：本机装 Docker Desktop（安装包已在 `D:\Docker\Docker Desktop Installer.exe`，且有 `一键安装Docker.bat`；需要 WSL2 + 管理员，可能要重启）→ 按 `reproduction/fetch_weights.sh` 重新拉权重到 `reproduction/weights/{t2i,shape}` → `docker build -t hy3d-repro .` → `docker save | gzip`。实测速率 2.5~4MB/s、合计 30.4GB ≈2.5~3.5h（本机 D 盘余 185G；`modelscope` 未安装需 `pip install modelscope`，`huggingface_hub` 已在）。
**路径 C（推荐执行方式）**：上面任一路径把 SSH 或控制台信息给我 → 我全程接管（pull/build/save/校验/断网实测），你只需要在控制台点几下。

**若镜像仓库里已经没有了，也不卡死**：权重全部是公开可再下载的，我方留有完整清单 —— `D:\hy3d_weights\final_manifest.json`（53 个文件 / 30.4GB，含来源仓库、文件名、字节数）+ `filelist_keep.txt` + `SOP-标准执行手册.md` 第 56~62 行的权重精确清单（含 u2net md5）。按清单重下 + md5 校验即可重建同源镜像。

## 十二、初赛 40 题产物体检（09-21，回答"为什么复用旧 raw / 还能怎么提分 / 还要不要上云"）

**证据文件**：`D:\文本生成3D方案赛\output_test\初赛40题产物体检报告_20260921.md`

### A. 为什么本机 smoke test 复用的 raw 不是 09-07 提交版那一套
09-07 那轮生成的 raw **从未落到本机**：
- 本机 `models_raw/` 只有 `sample_001`（官网示例题的构造测试模型）；本机唯一一套 40 题 raw 是 `models_raw_test/`（5.8G，时间戳 09-05 20:53 起、seeds 42~81、gen_params 与提交版相同）
- 该套 raw 是**VAE 零占位 bug 时代**的产物，三方交叉验证：① 面数 7,143,940 / 9,783,214 / 8,801,976 / 8,267,192 / 7,525,742，而提交版 build_report 同题只有 676,184 / 494,460 / 331,380 / 500,364 / 130,744（差 10~60 倍）；② raw bbox 精确等于 [2,2,2]（填满整个 [-1,1] 立方体 = 噪声特征）；③ 用 `pipeline/render_views.py` 渲染 `models_raw_test/hid_con_001/raw.glb` 得到的是噪声板，而提交包里同题是正常伞状
→ 结论：本机 smoke test 只能证明**复现入口机制可用**（署名/结构/门槛/离线），**不能证明语义正确**。这条边界已写进 `复现提交包/提交说明.md` 的如实段落。

### B. 硬缺陷（在真实提交产物上实测，非推测）
1. **4/40 提交的是多部件**（分离实体）：hid_con_010 = 6 体、hid_dec_005 = 2 体、hid_dec_006 = 2 体、hid_dec_010 = 3 体；部件最小间距 0.351 / 1.623 / 13.241 / 1.596 mm。其中 **hid_con_010 题面明写"两片竖直挡板通过折线形加强肋连接"** → 交分离体直接违背题面结构。
2. **1/40 整体悬空 6.64mm**：hid_sma_001 `z_min = 6.64mm`（其余 39 题 z_min≈0）。根因是后处理顺序（贴地之后又移除碎块）。**本机已验证修复**：重新平移 → z_min 0.00mm，水密保持、仍是单体。
3. **33/40 被 12 万面上限截断**：raw 面数中位 522,810 → 最终中位 120,000，**丢弃约 77% 细节**；GLB 平均 2.13MB → 提到 20 万面约 3.56MB/题。

### C. 被推翻的疑点（避免误判自己）
"法向朝下 >45° 面"筛查曾显示中位 12.1% 面积需支撑（24/40 超 10%）——**该指标高估**。改用逐层切片复核题面明确要求免支撑的 3 题：hid_con_001 **0.22%**、hid_con_010 **0.39%**、hid_sma_002 **0.68%** 面积未被下层支撑 → **基本自支撑，支持性不是失分点**，不要在答辩里宣称"支撑合规"（没有依据）。

### D. 语义弱（MLLM 分主要失分面，肉眼观察，非评分结论）
40 题透视图接触表逐图看：偏弱/模糊 = fun_005/fun_007/fun_009/dec_008/sma_007（呈光板/长方块）、sma_010（细枝小块）、sma_003（平板+球）；破碎/塌陷 = con_001（遮檐塌陷）、dec_003（半圆盘）、dec_007（爆散）、con_010（分离）。形态合理 = con_002/con_004/dec_004/dec_005/fun_003/fun_004/sma_004/sma_005/sma_009。
→ 物理合规（水密 40/40、贴地 39/40、尺寸帽生效）做得不错，**丢分主要在"几何是否像题面描述的东西"**。

### E. 提分杠杆（按 收益/成本 排序）
- **L1 生成-候选 + 自动门禁/语义打分选优**（每题 N=4~6 候选；硬门禁：水密/单体/尺寸/贴地；语义分：中文 CLIP 渲染↔题面相似度）→ 唯一能系统性治 B-1 与 D 的办法。GPU 成本 ×N，4090 上 40 题 ×6 约 2 小时。
- **L2 后处理硬伤修复**（贴地顺序、单体门禁、上限 12 万→20 万面、渲染 1024→1536）→ 纯 CPU，本机可做可验证。
- **L3 t2i 提示词工程**（结构化中文提示词：主体+姿态+单件+白底+视角）→ 零 GPU 增量。
- **L4 答辩 PPT / 最终版方案文档 / FDM 实物打印选题**。
- ⚠️ L1/L2 会让输出与初赛提交不再逐题一致 → `reproduction/`（忠于初赛的复现包）保持冻结；改进项作为可开关参数，仅用于"最终版方案"与决赛材料；能否用于复现评测需在群里确认。

### F. 云端那一轮是否还需要（回答 Q3）
**需要，且建议只安排一轮 3~4 小时**：① 重开极智算实例（镜像 `hy3d-t2i-fixed`，含 18G 权重）→ 云端 `docker build -t hy3d-repro`；② `--network none` 跑官方入口做断网离线实测（复现硬要求，本机无 Docker/无 N 卡做不了）；③ `docker save | gzip` 产出交付镜像；④ 顺便跑改进版的候选生成（时间紧就只对语义弱题/多部件题做多候选）；⑤ 可选装 PrusaSlicer CLI 做真实支撑/耗时体检。本机现在只能做 L2/L3/文档/PPT/CPU 部分。
