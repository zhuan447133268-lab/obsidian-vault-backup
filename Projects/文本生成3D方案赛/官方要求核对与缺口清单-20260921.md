### 4.2 镜像组装卡死的真正根因（两个 session 都栽在这，别再撞）

```
[17:01:31] BASEPATH=[============ CUDA ============CUDA Version 12.1.1Container image Copyright...
[17:01:31] Error response from daemon: Syntax error - can't find = in "CUDA". Must be of the form: name=value
[17:01:31] !! hy3d-code 未生成，中止
```

- 原因：`docker run --rm hy3d-base:py310 printenv PATH` 的输出**前面带 NVIDIA 的 CUDA 横幅**；`asm_a.sh` / `fix_a.sh` 把它 `tr -d '\r\n'` 后拼进 `docker commit -c "ENV PATH=/opt/conda/bin:<横幅>…"` → commit 直接报语法错。**不是网络问题、不是磁盘问题。**
- 修法（二选一）：① commit 时**写死标准 PATH**（与 `asm_b.sh` 尾段 Dockerfile 里那条同值：`/opt/conda/bin:/usr/local/nvidia/bin:/usr/local/cuda/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`）；② 取 printenv 输出的**最后一行**再拼。
- 断点修复已做的部分（容器 `hy3d-code-b` 当前状态）：依赖全部装齐并通过导入门禁（`torch 2.3.1+cu121 / cv2 5.0.0 / PIL 12.3.0 / hy3dgen 管线 OK`，`pip check` 干净）；**已补 `libopengl0`**（pymeshlab 插件此前报 `libOpenGL.so.0` 缺失）；**容器内 `/app` 代码已更新为含 `_logs/` 的最新版**；`/app/run_infer.sh` 的 `bash -n` 通过。
  → 也就是说 **commit 成功即得可用中间镜像，不需要从零重建**；从零重建也安全（`asm_a.sh` 会 `docker rm -f hy3d-code-b` 后重新来）。

### 4.3 体积与上传带宽（**最大决策点**）

- 最终镜像 ≈ 33~35 GB（基础 15 + 权重 18.9 + 依赖/conda），`docker save | gzip` 估 15~25 GB；本机上行**实测 0.22 MB/s** → 20 h+，**百度云盘直传大概率赶不上 9/23 24:00**。
- **关键发现（能直接解开这个结）**：官方 §3.5 模板写的是完整命令序列「**镜像加载 → 权重挂载 → 运行**」——即官方**接受"镜像不含权重、权重以卷挂载"**的形态；§3.2 也明确"开源模型给出国内可直接访问的下载地址 + 许可证"即可。
  → 可行路线：交付**不含权重的精简镜像 tar**（体积小一大截，tar 里只有代码+依赖+系统）+ 权重清单（国内直链 + SHA256 + 许可证）+ `docker run -v <权重目录>:/root/models` 的命令序列。
  → 仍建议问组委会确认**镜像体积上限与提交渠道**（这个开放问题从 09-20 挂到现在，一直没问）。
