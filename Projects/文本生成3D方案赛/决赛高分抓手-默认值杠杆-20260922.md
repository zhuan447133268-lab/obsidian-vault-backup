## 1. 事实基础（代码级引证，非推测）

- `reproduction/run_infer.sh:94` → `MAX_FACES="${MAX_FACES:-120000}"`；`:95` → `RENDER_SIZE="${RENDER_SIZE:-1024}"`
- `pipeline/build_submission.py:276,279` → `FDM_SETTLE_LAST` / `FDM_REQUIRE_SINGLE` **从环境变量读取、默认关闭**，
  而 `run_infer.sh` **不设这两个变量**
- ⇒ **官方那一次跑出来的，就是"12 万面上限 + 1024 渲染 + 未加固"版本**，也就是初赛提交版的那套缺陷：
  **1 题悬空（`hid_sma_001` z_min=6.637 mm）、4 题分离多部件（con_010=6 / dec_005=2 / dec_006=2 / dec_010=3）、
  33/40 被 12 万面截断（丢约 77% 细节）**（来源：`output_test/初赛40题产物体检报告_20260921.md`，
  本日 ZCode 用最终产物级基线独立复算，逐条吻合）
- 我方已有的加固实测（09-21）：开启后 **z_min 归 0**；`require_single` 使 `dec_005` 修成单体、
  `con_010` 丢 4 件后仍 2 体并标 `single_component_failed`；`MAX_FACES=200000` 单题 → **177,372 面 / z_min 0 / PASS**
- 官方 §4 八条自查**不限制面数上限、不规定渲染分辨率** ⇒ 加固/提高上限的产物不违规

## 4. 最小代价的测量方案（今晚 GPU 会话顺带就能拿数，零额外 GPU 成本）

40 题**冻结默认**跑完（拿对拍证据）后，**只重跑阶段 2**（纯 CPU，约 20~40 分钟，用同一批 raw）。
**注意：阶段开关是环境变量 `INFER_PROC_ONLY=1`，不是 `--proc-only` flag**（`run_infer.sh:85`）：

```bash
INFER_PROC_ONLY=1 INFER_PYTHON=/root/lockenv/bin/python \
INFER_RAW_DIR=/root/gpu_verify/raw INFER_WORK_DIR=/root/gpu_verify/work_ab \
MAX_FACES=200000 RENDER_SIZE=1536 FDM_SETTLE_LAST=1 FDM_REQUIRE_SINGLE=0 \
  bash /root/gpu_verify/pkg/reproduction/run_infer.sh \
       /root/gpu_verify/prompts40.jsonl /root/gpu_verify/out_ab
```

（`run_infer.sh` 自身不 export `FDM_*`，但 `VAR=x cmd` 前缀赋值会进入子进程环境，`build_submission.py:276,279` 能读到。
**这两条命令只是临时覆盖，不写回任何文件**。）

拿到三个数就能定 ①~④ 的去留：① 面数分布（是否真的用满 20 万）② `z_min` 是否 40/40 归零
③ 单题阶段2 耗时（对照现基线 **中位 28.5 s / 最大 43.3 s**，**只比倍数、不比绝对值**）。

**本机也能先做耗时缩放近似**（需在 WSL 的交付镜像内跑，约 30 分钟）：拿初赛 40 题成品 `model.glb` 当阶段 2 输入
（`INFER_PROC_ONLY=1` 那套），在 200k/1536 下跑一遍看耗时倍数——不必等 GPU（但对"面数是否用满"无意义，因为成品已减过面）。
