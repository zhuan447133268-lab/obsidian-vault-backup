## 本次讨论内容

### 1. 自动同步
- **需求**：每月2号和16号早上8点自动从Oracle同步数据
- **方案**：Go内置cron（robfig/cron/v3），后端直接调用SyncService.SyncData
- **触发规则**：2号同步上月full月报，16号同步当月half半月报
- **执行身份**：新建SYSTEM用户（role=group_admin），与人工操作区分
- **自动同步开关**：数据库system_configs表 + 前端开关，即时生效
- **方案对比**：数据库+前端开关 vs 配置文件，选择了数据库方案（理由：集团管理员前端即可操作，无需运维介入）

### 2. 集团总览导出
- **接口**：新增 `GET /api/v1/balance/group/export`
- **模式**：支持合并模式(merged=true)和明细模式(merged=false)
- **CSV格式**：园所编码、开户单位、账号名称、所属区域、账面金额、实际金额、差异、状态
- **权限**：仅group_admin可导出
- **实现模式**：复用CompanyHandler.Export的CSV导出模式（BOM头+Content-Disposition）

### 3. 本地验证方案
- **前端**：`npm run dev`（端口5180），Vite已配置代理转发/api到后端
- **后端**：`go run ./cmd/server`（端口8094）
- **数据库**：Docker只启动MySQL容器，init_db.sql自动建表+种子数据
- **认证**：使用 `POST /api/v1/auth/dev-login`，输入ADMIN工号即可获得JWT Token
- **Oracle同步**：网络能通则直连，不能则用SyncDataFromRows方法构造Mock数据
- **默认用户**：ADMIN(group_admin)、REGION01(region_admin)、CASHIER01(cashier)

### 4. 认证体系分析
- **生产环境**：企业微信OAuth2 → 本地用户匹配 → JWT签发 → 中间件验证
- **企微Token**：三级缓存（内存→数据库→企微API）
- **JWT载荷**：userID + username + userRole，HS256签名，24h过期
- **角色模型**：支持逗号分隔多角色（如"cashier,region_admin"）
- **安全问题**：JWT密钥占位符、DevLogin生产未禁用、Logout不撤销Token、Token存localStorage

### 5. 数据同步流程分析
- **数据源**：NC系统Oracle BI，表`nccbi_dw.ai_bank_fact`
- **同步方式**：集团管理员手动点击触发，直连Oracle查询
- **去重键**：period + syncType + code + zhCode（联合唯一索引）
- **金额选择**：half取H_AMOUNT，full取Z_AMOUNT
- **状态初始**：同步后fill_status="pending"
- **状态流转**：pending → draft → submitted → region_confirmed → region_submitted

### 6. 经营分析思路（后续迭代）
- **四个分析方向**：
  - 差异分析（账面vs实际差异排行、趋势、原因分布）
  - 资金趋势（园所/区域多期余额变化）
  - 流程效率（填报完成率、审核周期、异常率）
  - 银行分布（各银行存款分布、账户属性分布）
- **落地策略**：第一步做好CSV导出让财务用Excel分析，第二步在系统内嵌分析页
- **分析页设计**：ECharts图表，新增/analysis路由和/api/v1/analysis/*接口族

### 7. 待确认事项
- Oracle的H_AMOUNT和Z_AMOUNT业务含义需与财务确认
- 自动同步的period计算逻辑：2号同步上月full，16号同步当月half — 待确认
- 月报(full)是否也需要自动同步？目前方案仅half自动同步
