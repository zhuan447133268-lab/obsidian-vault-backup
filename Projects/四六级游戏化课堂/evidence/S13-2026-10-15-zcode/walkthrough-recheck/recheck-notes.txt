【A｜窄屏反馈条遮住选项】 FAIL（核心问题仍在）
 判据：选项底的 y ≤ 面板顶的 y（允许 0 重叠）；另用 elementFromPoint 做遮挡命中测试。
 390x844：
   反馈面板 .feedback.show  position:absolute; bottom:0; z-index:8
     panelTop = 524.9  panelBottom = 844  panelHeight = 319.1  (max-height: 56%)
   正确选项 .answerpanel .optzone .opt.right（key = I）
     top = 602.0  bottom = 650.0  h = 48.0
   选项底 − 面板顶 = 650.0 − 524.9 = +125.1 px（> 0，不满足判据）
   重叠高度 = 48.0 px（= 选项整个高度，完全重叠）
   命中测试：elementFromPoint(选项中心 105.5, 626) -> P.fbtext（面板内），
             panelContainsPoint = true，isOptionOrDescendant = false
             => 该选项在视觉与点击上都被面板盖住
   App 确实尝试滚动：答题前把 .optzone.scrollTop 归零，提交后变成 104.0
     （= 该容器最大可滚距离 480 − 376 = 104，即已经滚到底），
     但最大滚距仍不足以把该选项抬到面板上方（差 125.1 − 104 = 21.1 px）。
   同一关第 3 题（正确项 F，第 3 行）在 scrollTop=104 下：F 占 490~538，
     面板顶 502.8 -> 仍被压住 35.3 px，命中测试同样落在 .fbtext 上。
 390x700（短屏）：
     max-height 计算值 = 46%（命中 @media (max-height:780px) 规则，确认生效）
     面板 top = 380.9 / height = 319.1 / 占视口 45.6% / bottom = 700
     选项顶 602 底 650 -> 选项底 − 面板顶 = +160.0，重叠 48px，命中测试被盖
     （短屏下更糟：面板几乎盖住整个选项区）
 结论：提交后选项没有被滚到面板上方可见处，判定 FAIL。
 附带记录：A~O 全部 15 个选项中，提交后唯一「部分露出」的只有中间行
   （E/F 行 490~538，露出约 12.8px）；其余（G 行及以下）完全被盖，
   而最上面两行（A~D）在 scrollTop=104 下被 .optzone 裁掉、不可见。

 面板高度 / 限高（题目要求附带报告）：
   基础规则  .feedback { max-height: 56% }   （无 media 条件）
   短屏规则  @media (max-height: 780px) { .feedback { max-height: 46% } }  —— 存在且生效
   844 高时 780 的 media 不命中 -> 采用 56%；实测渲染高度 319.1~341.9px
     （占视口 37.8% ~ 40.5%），即 56% 未被顶到，高度由内容决定
   700 高时 media 命中 -> max-height 46%（实测 45.6%，319.1px）
   面板自身不滚动：.feedback clientHeight == scrollHeight（319/341）；
     其内层 .fbtext 也是 clientHeight == scrollHeight（187），overflow-y: visible
     => 「反馈面板的滚动容器高度」= 面板自身高度，面板不会内部滚动，
        内容变长时只会把面板撑高到 56%（或短屏 46%）上限。

4. 没测到 / 存疑的点（不粉饰）
====================================================
1) .strip 未能实测。当前试点数据里没有任何 practice=true 的单元，
   地图上 .paperbox/.strips/.strip 元素数为 0，本账号下根本无法渲染出该元素。
   只拿到样式声明 .strip { min-height: 44px }，未做活体测量。
   想实测需要先有「老师发布的练习卷」（practice 单元）挂到该班级。
2) level=4（第 9 周 · 第 4 关 · 阅读·选词填空）无法进入。
   直链 /s/quiz/4 能打开预览页，但页面明确显示「还没解锁：先通过上一关。」，
   「开始答题 →」按钮为 disabled，Playwright 报
   "Timeout waiting for click actionability (disabled)"。
   因此 B 项只在 level=15 上做了完整验证，level=4 未验证。
3) 真机移动端行为无法验证：无触摸事件（maxTouchPoints=0）、无移动 UA、DPR=1.0。
   本次所有 ≥44px 结论只代表「CSS 视口 390x844 下的 CSS px 高度」。
   另外 -- 因为 DPR=1，若真机 DPR=2/3，「物理像素」会更大，但 CSS px 判据本身不受影响。
4) A 项在 844 高（>780）时走的是基础 56% 限高，不是 46%；46% 只在 ≤780 高时生效。
   如果验收标准是按「短屏 46%」来写，请注意 390x844 这一常见机型高度并不会触发 46%。
5) 反馈面板「滚动容器高度」这一项：面板内部不滚动（clientHeight==scrollHeight，
   .fbtext overflow-y: visible），所以只能报告面板自身渲染高度与其 max-height 上限，
   不存在一个「面板内滚动容器」可测。
6) 复盘页翻页只能靠作答后点「下一题 →」；该按钮位于底部导航之上会被 .navbar 遮挡，
   常规 Playwright 点击会报 "covered by <a>… from <nav class="navbar">"，
   本次改用页面内直接 .click() 完成翻页（不影响考点文本的读取结论）。
7) 复盘页作答不像关卡内那样弹出反馈面板，只在选项上打 right/wrong 标记；
   我最初对「第1题正确项」的判断（先以为 I，实为 G）来自这个标记，已在报告中修正。
8) 顺手发现（不属于本次四项，仅供参考，未做修复）：
   a. 关卡内 .optzone 的滚动位置在切题时不重置（第 1 题滚到底后，第 2 题仍是 104）。
   b. 第 1 题答题时 .optzone 滚到最大后，第 1~2 行选项（A~D）会被裁出可视区、完全看不见。

   d. 关卡内计时器读数异常：从 07:58 在数十秒内跳到 01:59、随后显示 00:00
      （未确认是倒计时计算问题还是我停留过久；结算由「爱心用尽」触发，不是超时）。
