## 本轮踩坑与修正（自查出来并已修的自身缺陷）

1. **2 班学生没有关卡可玩**：首跑 `03-seed` 直接崩在「学生 S7D 看不到关卡 25」——只有 1 班挂了 unit（4 个专题），2 班学生 `levels` 返回 0 条。这是**产品事实**（2 班没排课），不是脚本 bug；已把 S7D 改成"一关不打"、只承担跨班隔离用例，另加 **S7E**（1 班、5/5）承载验收②的页面侧证据；脚本遇到某关不可玩时改为**列出该生可玩的关卡 id 后报错**，不再模糊崩溃。
2. **浏览器取证动作本身崩过一次**：`expect_response(...).json()` 读响应体偶发 `Network.getResponseBody: No resource with given identifier`（导航时响应体被浏览器回收），导致 `07` 整步崩、并连带 post 相与截图清点失败。已改为**响应监听只记 url+status**（证明页面确实请求了）+ **数据自己带 token 再取一次**（接口回执）——页面证据与数据证据分开取证。
3. **清点脚本自己假绿过一次（最该抓的）**：`11-shots` 里"重复截图"报告分支把 `{}` 与 `%` 混用抛 `TypeError`，而函数退出码又被后一段 python 覆盖 → 崩溃被吞、`step 11` 报"退出码 0 · 失败 0"（首跑就是这个假绿，实际上 solo/unlocked 两个场景根本没验）。已修：格式化改正、**每条缺陷都印成 `[CHECK] … ❌`**（纳入失败计数）、场景数不齐即失败、两段 python 的退出码汇到函数返回值；同时修掉 member 场景 navbar 截图被记两次的记账笔误。修后 4 个场景 30 张截图全部逐张验过。
