## 新引入的决策 / 偏差（需评审）

1. **XP 入账口径：逐题入账 + 结算奖励 + 失败撤销**（本阶段最大的口径决定）。
   - 每次 `submit` 把本次答对的题按 `单题答对 + 速度 + 连击` 逐条写 `xp_ledger`（`reason` 可解释），**这样断点续答分次提交也不丢分**；
   - 通关 / 三星 / Boss 满分的奖励只在整场结束时写（`通关 +30`、`三星 +20`、`Boss 满分 +50`）；
   - 整场失败（爱心扣完）时写**一行等额负数** `attempt_voided`，账本净额 0 —— 因为账本 append-only，不能回删。
   - 结果：`SELECT SUM(delta)` 永远是唯一权威，且「刷到一半就退」拿不到通关奖励。
2. **首刷是"派生"出来的，没有加 `first_attempt` 列**。任务书 §7 红线禁止改表结构，所以 `firstResult` = 该关 `attempts` 里 id 最小且 `status=finished` 的那条（`quiz_service.go` 里按 id 升序扫描时第一次遇到即首刷）。星级另按 max 取历史最好（原型口径）。
3. **学情维度靠 JOIN `questions`，不新增列**。`attempt_answers` 只落 `question_id / picked_idx / is_correct`；题型、`knowledge_tag`、`difficulty` 从 `questions` 关联即可（S6.5 / S10 的输入），「S3 起 `attempt_answers` 必须落知识点/题型维度」这条按"可 join 得到"实现（同一条红线不许改表）。
4. **710 分制只发 Boss 卷**。任务书 §6 写的是「Boss 卷 710 分制 = round(正确率×710)」，原型也只有 Boss 关显示成绩单；非 Boss 关 `score710 = 0`，前端不显示。实测见 `05`（非 Boss 0）与 `08b`（Boss 710 / 533）。
5. **选项洗牌只在"洗了不影响语义"的题型上做**：`match`（段落匹配 A~L 段）不洗选项、恒等置换；其余题型用 `OptionSeed(attempt.shuffle_seed, question_id)` 洗。题目**顺序**始终打乱。`picked_idx` 一律换算回**题库坐标系**存库，前端展示序与库内序解耦（前端之后自己按同一 seed 还原即可）。
6. **速度加成依赖客户端上报 `elapsedMs`**。原型就是"每答一题上报耗时"，且 S3 的提交接口允许一次交多题（断点续答），服务端无法在整场结束后重建单题耗时，所以按客户端上报计算。副作用：**可以刷**（把耗时都报 0 → 每题多拿 10 分）。这是原型语义，登记为已知遗留（第 3 条），要不要收口请评审决定。
7. **诊断抽样权重是下限，不是配额**：`词汇 4 / 语法 3 / 阅读 3`，不足 10 题时从补齐池（同班同分套的其余题）按确定性置换补到 10。**本阶段修掉一个真 bug**：原实现没有按档收口，实测抽样 10/10 全是词汇——现已在 `diag_service.go` 加每档 quota 收口，并补了 3 个单测（`diag_service_test.go`）。
8. **`maxStemLen 4000 → 8000` 这一行按任务书裁定留给 S4 并入**，所以 `7fa0447` **不含**这一行（提交前把该行改回 4000、提交后再在工作区改回 8000）。当前工作区只留这一个未提交改动 + 一份用户素材目录（`2026年6月四级 真题+解析+听力音频 （全三套）/`，157 MB，不入库）。
9. **爱心固定 3**、扣完即 `status=failed`（失败当题的回执照发）。原型语义，无开关。
