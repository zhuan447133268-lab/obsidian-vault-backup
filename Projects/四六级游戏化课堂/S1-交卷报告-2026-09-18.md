## 新引入的决策 / 偏差

1. **「首次登录强制改密」的状态编码在 `pwd_hash` 前缀里**（`init$` + bcrypt 哈希 = 未改密；纯 bcrypt = 已改密）。
   理由：开发方案 v1.0 §4 的 `users` 没有 `must_change_pwd` 列，任务书 §7 红线规定不得擅自加字段。该方案零 schema 改动，读写只经过 `internal/auth/password.go` 的四个函数（`HashInitialPassword` / `IsInitialPassword` / `VerifyPassword`）。
   **需确认**：是否接受该编码；若 S2/S3 允许加列，可平滑迁移（一次性 `UPDATE` 后删前缀逻辑）。
2. **统一响应信封 `{code,message,data}`** 覆盖所有接口（含 `/health`），错误码 5 位：`40101` 学号或密码错误、`40301` 无权访问、`40302` 首登未改密、`40002` 导入不合规、`40901` 冲突。参照 `textbook-analysis-tool` 的既有约定；前端 `web/src/shared/http.ts` 同步加了 `unwrap()`。
3. **导入为"全有或全无"单事务**：一份名单出现坏行则整份不落库 + 返回行号清单。理由写在 `import_service.go` 顶部注释（只导一半比失败更糟）。
4. **默认初始密码 = 学号**（名单留空时），改密后失效；教师重置密码也回到该规则。
5. **`classes.name` 不加唯一索引**（v1.0 §4 未给）：导入按名称显式查重，同名复用；历史上没有归属教师的班级在导入时"认领"给导入者。
6. **新增两个本地 CLI**（不在任务书 API 清单里，但属必要引导）：
   - `cmd/seed-teacher`：创建/重置第一个教师。理由：`/api/admin/*` 需要教师角色，而 `POST /api/admin/users` 本身也需要教师登录，第一个教师没有别的入口；命令幂等。
   - `cmd/import-users`：`-template` 生成导入模板、`-convert` CSV→xlsx、`-file` 导入。与 HTTP 接口共用同一个 `service.ImportService`，校验规则完全一致（证据里① ② 用 CLI、⑥ 用接口，输出同源）。
7. **JWT 参数**：HS256、issuer `cet46`、TTL 7 天、密钥取 `SECRET_KEY`（.env，未进 git；`main.go` 缺失时启动即失败）。鉴权中间件每请求回查数据库取角色与改密状态，不吃 token 里的陈旧状态。
8. **DB 日志收敛**：关掉 GORM 的 `RecordNotFound` 日志与 ANSI 颜色。理由：查不到记录是业务分支（班级不存在则新建、登录学号不存在），默认日志会打成红色 error，教师在导入输出里会误读成失败。
9. **与原型的关系**：原型是纯前端单文件（含手机端/教师端两套界面）。S1 交付的是数据契约（接口 + 字段 + 状态标记），教师端界面按任务书排在 S10；学生端"重置后首次进入"的跳转与目标弹窗排在 S6。
10. 任务书 §6 数值对拍表（XP/连击/三星等）**S1 未涉及**，按约定自 S3 起回归。

### 补丁2 证据：/api/admin/users 教师行级隔离

实现：`UserService.List` 增加 `ListFilter.TeacherID`，命中时加子查询 `class_id IN (SELECT id FROM classes WHERE teacher_id = ?)`（不改表结构，MySQL/SQLite 双驱动通用）；单查新增 `GetForTeacher`，越权回 **404**（不用 403——403 等于告诉对方"这个 id 存在，只是不给你看"，属可枚举信号）。**`TeacherID` 取自登录态（`middleware.CurrentUser`），不读请求参数**，教师改 URL 也越不出去。未分班学生（`class_id IS NULL`）不属于任何教师，对教师不可见。
