### 新引入的决策/偏差（**需拍板**）

| # | 决策 | 理由 | 需确认 |
|---|---|---|---|
| 1 | `questions.answer_idx` 用 **varchar(255)** 而非 int | 单选存单下标；选词填空(cloze)/段落匹配(match) 要存多空序列与配对序列（PRD v1.3 #12 已拍板进一期）。若先用 int，S4 必改字段 | **S4 定稿前请确认序列格式**（如 `"2"` / `"1,3,0"` / `"0-3|1-5"`） |
| 2 | `attempt_answers.picked_idx` 同用 **varchar(255)** | 同上，与题目的答案形态对齐，避免答题流水和题目表类型打架 | 同上，随 #1 一起定 |
| 3 | `.env.example` 放 **`server/`** 而非仓库根 | `go run ./cmd/server` 的 cwd 是 `server/`，godotenv 只在该目录找 `.env`；且与公司现成项目 `textbook-analysis-tool` 的 `backend/.env.example` 布局一致 | 知悉即可 |
| 4 | `vite.config.ts` 用 `host: '127.0.0.1'`（参照项目是 `0.0.0.0`） | **本机踩过真坑**：本机 5173 端口上还跑着另一个无关的 Express 应用（`0.0.0.0:5173` 是我，`127.0.0.1:5173` 是它）。Windows 下这两个可以同时监听同一端口，而 `127.0.0.1` 更具体 → 我所有请求都被静默转发给了别的应用，`/api/health` 返回的是别的系统的 JSON。改成只绑回环后，占用冲突会直接报错/顺延端口，不会连错。真机联调用 `npm run dev -- --host` | 知悉即可（部署走 Nginx，不受影响） |
| 5 | `diagnoses.start_level` 按 `levels.id` 外键建模 | 开发方案 v1.0 §4 写的是"起始关卡"，结合上下文是关卡主键 | 知悉即可 |
| 6 | 仓库根 `index.html` 做成**纯落地页**（链接到 /s/ 和 /t/），**不用** meta refresh 跳转 | 踩坑：原来写 `meta refresh content="0; url=./s/"`，在 SPA fallback 下 `/s/` 也被 `index.html` 兜住，相对路径 `./s/` 解析成 `/s/s/` → 无限跳转 `/s/s/s/s/...` | 知悉即可 |
| 7 | 前端 Vite 绑回环后，`/s`、`/t` 的路由重写用自定义插件模拟 Nginx `try_files` | 让 dev/preview 与线上 Nginx 路由行为一致（任务书要求前端对齐原型、部署走 Nginx） | 知悉即可 |

**表数量 17 已复核**（开发方案 v1.0 §4 实际是 17 张，主索引里"18 张"是笔误，v2.0 已修正）——未加表、未改字段。
