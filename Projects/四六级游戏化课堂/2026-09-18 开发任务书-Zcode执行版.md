## 0. 怎么用这份任务书

1. **严格按 S0→S13 顺序推进，一次只做当前阶段**。前一阶段未通过验收，不得开工下一阶段。
2. 每阶段做完，**按 §8 交卷模板输出交卷报告**，交给用户转 Claude 验收。
3. Claude 验收时会**亲自复跑你报告里的每条验收命令**——只写"通过"不给证据 = 不通过。
4. 任务书里没说的事，**停下来问，不要猜**（ especially：需求歧义、技术选型变更、范围新增）。
5. 仓库根目录：**`D:\claude-work\cet46-game\`**（S0 创建）。本地 git 仓库，每阶段交卷 = 一个 commit，**不推远程**（除非用户明确指示）。

## 1. 项目一句话

课堂嵌入式游戏化四六级备考 H5：学生手机端闯关攒 XP 换福利券，教师 PC 端看板+课中实时大屏。原型 6 页已上线（效果=需求基线），本产品化重写。**"重画不重想"——交互、文案、数值全部继承原型，不得自行发挥改设计。**

## 2. 硬性技术栈（不得更换，无需再选型）

| 层 | 定死 |
|---|---|
| 学生端 | Vue 3 + Vite + TypeScript + Vant 4（`/s/*` 入口） |
| 教师端 | Vue 3 + Vite + TypeScript + Element Plus + Pinia（`/t/*` 入口） |

| 定时任务 | Go 内嵌 robfig/cron（周榜/赛季/备份），不引入独立调度组件 |
| 导出 | excelize 生成 .xlsx |
| 部署 | Nginx 反代（`/api/*`→Go 8080；静态托管 dist）；参考 `D:\claude-work\textbook-analysis-tool\deploy\nginx.linux.conf.example` 的套路 |
| AI 批改 | 一期不做，只在代码里留接口位置 |

## 3. 工作铁律

1. **只做当前阶段任务单里写的"做"清单**；"明确不做"清单里的事项碰了 = 返工。
2. 不顺手重构、不"改进"无关代码、不加任务书没有的功能和配置项。
3. 交互/文案/数值与原型不一致时，**以原型为准**，并在交卷报告里列出差异点。
4. 每阶段配测试，且测试必须可重复执行（脚本化）。**数值相关测试是红线，必须跑在 CI/验收流程里。**
5. 数据库迁移用 GORM 迁移，可重复执行、幂等。
6. 凭证（JWT secret、DB 密码）走 .env，不进 git；仓库附 .env.example。
7. 代码注释/提交信息用中文，提交信息格式：`S<n>: <一句话>`。
8. 遇到阻塞（环境装不上、需求矛盾、依赖版本冲突）→ 停下来在交卷报告里写清楚，**不要绕过**。
9. 前端效果对标原型：手机视口 390×844 是验收视口；PC 端 ≥1024px 教师端布局。
10. 每阶段结束工作区干净：无临时文件、无调试残留、无跳过的 TODO。

## 5. 阶段任务单（S0~S13）

> 每阶段固定五栏：**做 / 对齐 / 明确不做 / 交付 / 验收（Claude 将逐条复跑）**。工期是参考，超期可以，降标准不行。

### S0 仓库+开发骨架（2天）
- **做**：创建 `D:\claude-work\cet46-game\` 单仓（`/web` 双入口 Vite + `/server` Go Gin）；docker-compose 起 MySQL 8（库 `cet46`，utf8mb4）；GORM 迁移建 17 张表（结构见开发方案 v2.0 §4 / v1.0 §4）；CI 配 lint+test+build；.env.example。
- **对齐**：无（纯骨架）。
- **不做**：任何业务接口、任何前端页面。
- **交付**：可运行的空骨架 + README（起环境命令）。
- **验收**：①`docker compose up -d` 一键起（MySQL 健康）；②迁移幂等（连跑两次不报错）；③`go test ./...`、`go vet`、`npm run build` 全绿；④17 张表存在（SHOW TABLES 输出贴报告）。

### S1 登录+班级/学生导入（3天）
- **做**：users/classes CRUD；学号+密码登录（bcrypt 哈希）发 JWT；首次登录强制改密；xlsx/csv 批量导入班级+学生（导入模板随交付）；users.target（'4'/'6'）字段就位。
- **对齐**：原型 index.html"重置后首次进入"流程。
- **不做**：目标切换的前端联动（S6 再做）；找回密码。
- **验收**：①导入脚本灌 1 班 40 人零报错（附脚本输出）；②重复学号/缺列等坏行返回行号清单（造 3 类坏行各 1 条演示）；③正确密码返回 JWT、错误密码 401（curl 实录）；④首次登录未改密时业务接口一律 403。

### S2 题库后端（3天）
- **做**：units/levels/questions CRUD + xlsx 批量导入（模板随交付）；band 分套（4/6）；type 支持 vocab/grammar/reading/**cloze/match**（listening 字段预留不实现）；`exp`（答案解析）/tip/knowledge_tag/difficulty/enabled 全支持。
- **对齐**：quiz.html 题库结构 + PRD v1.1 §3.5 题型对齐表。
- **不做**：题目编辑器 UI（教师端题库管理 UI 可命令行/Postman 级，页面级管理 UI 二期）。
- **验收**：①四级 33 题+六级 33 题（从原型题库 JSON 转 xlsx）灌入零报错；②按 band+level 取题过滤正确（接口实录）；③`enabled=false` 题目不下发。

### S3 答题引擎后端（5天，全程最重）
- **做**：诊断卷下发/判分/起始关卡（diag）；`GET /quiz/paper` 生成 shuffle_seed 存 attempt；`POST /quiz/submit` 服务端判分 + **XP 按 §6 数值表重算写 xp_ledger**；attempt/attempt_answers 流水；wrong_book 收录；`GET /quiz/levels` 解锁链。
- **对齐**：quiz.html 判分/爱心/连击/星级/Boss 逻辑。
- **不做**：前端页面。
- **验收**：①**§6 数值表每一条都有 Go 单测且全绿（贴 go test 输出）**；②XP 只从 `SELECT SUM(delta) FROM xp_ledger` 聚合——直改 attempts 表分数后总 XP 不变（演示实录）；③同一 attempt 刷新/重复取卷 seed 不变、题目顺序不变；④错答进 wrong_book、答对 mastered。

### S4 新题型 cloze + match（4天）
- **做**：选词填空（15 选 10：options_json 存 15 词、answer 存 10 空序列）与段落匹配（段落-题连线对）的存取格式、判分、XP 口径（与阅读题一致）。
- **对齐**：PRD v1.3 #12 拍板。**原型无此交互，属净新增**——下发格式要让前端"拿到就能渲染"，不确定的格式设计写进报告请确认，不要自创后闷头做完。
- **验收**：①两题型各 3 组判分单测（全对/半对/全错）全绿；②判分结果正确落 attempt_answers 并进错题本；③paper 接口下发 JSON 结构在报告里贴样例。

### S5 学生端·地图页（3天）
- **做**：Vant 端 A 搭起（登录态、路由、axios 封装）；闯关地图（解锁链/星标/毕业横幅/目标切换入口）；个人信息栏接真实 XP。
- **对齐**：**index.html 1:1**（动态解锁、四/六级首次弹层+顶栏切换、390px 全屏自适应、≥1024px PC 演示台面板——原型自适应三档都要）。
- **不做**：答题页。
- **验收**：①390×844 与 1440×900 两视口截图各一张，与原型并排（Claude 走查清单比对）；②解锁状态与后端 levels 接口一致；③未登录访问跳转登录。

### S6 学生端·答题+结算+解析（5天）

## 6. 数值对拍表（S3 起每阶段回归必跑）

| 项 | 公式/规则 |
|---|---|
| 单题答对 | 20 分起，连击 `20+(n-1)×5` |
| 通关奖励 | +30 XP |
| 三星 | +20 XP（正确率 ≥90%） |
| Boss 卷 | 对×25 + 满分 50 |
| Boss 成绩单 | `round(正确率×710)` |
| 爱心 | 3 颗，答错扣 1，扣完失败可重试 |

XP 唯一权威来源 = `xp_ledger` 聚合。客户端提交的只是作答内容，XP 一律服务端重算。
