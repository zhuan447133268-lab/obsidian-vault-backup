## 本轮发现（附带说明，不需拍板）

1. **"分组安全守卫"自己有假阳性**：S10 留下的机械守卫（DryRun SQL + `select 项 vs GROUP BY` 正则）在本阶段第一次跑就红——`aa.question_id` 报"既没分组也没聚合"。查下来是 **GORM 会把限定列名前加反引号**（``GROUP BY `aa`.`question_id` ``），而守卫的正则只认不带引号的 `a.b`。**修的是守卫**（选择项与 GROUP BY 两侧统一去反引号，同口径），不是改查询——查询本身 MySQL 侧是安全的（`ONLY_FULL_GROUP_BY` 下也过）。两个包的既有守卫测试此后全绿。
2. **我自己的"整页截图"闸门原来是个假绿机器**（本轮连修三处，都被负向控制当场抓出）：①第一版要求"整页图高 > 900"，而本页实测 `scrollHeight == 900`（**恰好一屏**）→ 按原规则永远红，改成"`|图高 − 文档实测 scrollHeight| ≤ 4px` + `noInnerScroll` + 四板块矩形都在文档高以内"；②**闸门的 Python 结论没接到 bash 退出码**（`rc=$?` 拿的是必为 0 的 python 退出码）→ `SHOTS_MISMATCH` 也会"看起来绿"，改成走 `PIPESTATUS`；③**补偿证据的匹配把失败断言自己算了进去**——失败文案里通常也含那些关键词（它正在解释现象），于是"我自己说自己没事"被当成证据、四条豁免全卡死，改成"只认 `ok=true` 的断言提供补偿"。**三次都是负向控制（故意注入缺陷看闸门会不会红）发现的**：验收脚本本身也要有"会红"的证据。
3. **活日志不能写进交付物**：`run-acceptance.sh` 原先把**仍在运行的**服务 stdout 直接写进 `evidence/`——句柄不关、跑完继续写，Windows 下文件还删不掉，交卷后的工作区会被它反复弄脏。改成"服务 stdout 写临时目录 + 需要留档时复制一份**冻结快照**（`00-server-boot.txt`）"，并在 `.gitignore` 里显式排除活日志。
4. **顺带把 S10/S10.5 的复验证据入了库**：S10.5 报告"本轮发现"第 6 条曾把 `cet46-server-s10-claude.exe`（25MB）与 `evidence/S10-2026-10-13-claude-rerun/`（2.4MB）挂出来请用户决定去留。本轮按开工说明"evidence 必须进仓库"的要求，把 **`evidence/S10-2026-10-13-claude-rerun/` 与 `evidence/S10.5-2026-10-14-claude-rerun/`（只入 JSON 结果，`.log` 仍被忽略）** 一并纳入 commit；那个 25MB 的 exe **仍未跟踪、未删除**（不是我建的，留给用户决定）。
5. **大屏页面在 1440×900 恰好一屏**：三指标一行 + 榜单卡片网格，`scrollHeight == 视口高`，四个板块矩形都在 0~702 之间。对投影场景这是好事（不用滚动），但也意味着"整页截图"和"视口截图"覆盖范围相同——所以 ⑧ 的证据价值靠 `noInnerScroll` + 板块矩形，而不是靠"图比一屏高"。
6. **夹具是"纯读侧"的**：只造 `attempts`/`attempt_answers` 行，**不写 `xp_ledger`、不碰联赛/赛季**。好处：①"评分关键文件未改动"这条回归成立；②CRV/CRC 与底账不受影响；③S8 的两条遗留（赛季结算自动开下一赛季、晋级名额是名次线）**本轮压根没碰到联赛数据，按开工说明顺延 S12**。
7. **给后续阶段留一条：自动化浏览器会节流"首个实例"的定时器**。本轮走查第一次量自动刷新得到 **20.009s**（稳定的 2× 慢），同页裸 `setInterval(1000)` 探针却仍是 1.000s/次；经应用自身导航重挂载一次后立刻恢复正常（10.004s）。**教训**：将来任何"测轮询/心跳间隔"的走查，都要么先重挂载一次再测，要么同时放一个裸探针做对照——否则会把浏览器伪影记成产品缺陷（或反过来，把真缺陷当成伪影放过去）。
8. **`02-accept.txt` ⑨ 段那行「今天 attempt：16 条」是全库口径**（脚本里 `where started_at >= CURDATE()` 没按班过滤）：16 = 我的 10 条 + `S10.5验收1班` 今天 5 条 + `S10.5验收2班` 今天 1 条。**本班口径**是"今天 10 条 + 昨天 1 条 = 11 条 attempt / 20 条 attempt_answers"（`99-summary.txt` 99-3 的每生 3/3/2/2/1 即此 11 条）。手算与所有断言都按本班口径，别被那行全库数吓一跳。
