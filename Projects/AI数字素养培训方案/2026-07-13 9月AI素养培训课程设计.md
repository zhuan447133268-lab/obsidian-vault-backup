# 2026-07-13 9月AI素养培训课程设计

## 一、项目背景

高校教师已普遍具备通用 AI 工具使用能力（通义、DeepSeek、Kimi、即梦、ima 等），但尚未系统掌握将 AI 深度工具化、产品化的能力。

本次 9 月培训聚焦：**让教师从"会用 AI 工具"进阶到"能用 AI 改造工作与课程"**，并形成可验收、可展示的过程性成果。

**核心定位**：不是教教师"用更好的 LLM 写东西"，而是教教师"用 AI Agent 把反复做的事变成可运行的工具/网页"。

---

## 二、9月培训课程总览

| 课次 | 主题 | 核心目标 | 形式 |
|---|---|---|---|
| 第一次 | AI Agent 全景体验 + WorkBuddy 入门 | 感受"AI 长出手脚"，区分 Agent vs LLM | 机房实操 |
| 第二次 | 用 WorkBuddy 做教学/办公小工具 | 用自然语言生成可运行工具 | 机房实操 |
| 第三次 | ima 知识库 + 钉钉跨系统办公 | AI 接入知识库和办公系统，跨系统办完一件事 | 机房实操 |
| 第四次 | AI Agent 工作流方法论工作坊 | 从真实痛点到可运行工具 + 颁证 | 分组 workshop + 路演 |

**设计原则**：
- 每节课可独立参加，不依赖上一节课的具体产物。
- 第一次课教授 WorkBuddy 基础操作，后续课程不再重复教工具。
- 强调真实工作场景，强调 Agent 能做 LLM 做不到的事（操作电脑、接系统、发钉钉）。

## 三、第一次课：AI Agent 全景体验 + WorkBuddy 入门

### 3.1 定位

让老师知道 Agent 能干什么，并掌握 WorkBuddy 基础操作。核心是**感受"AI 长出手脚"**。

### 3.2 两个体验式案例

#### 案例一：文件整理（AI 能动手）

- 课前由讲师在每台电脑桌面预置样例：`样例_学生作业` 文件夹，内含 11 个文件名混乱的学生作业文件。
- 课上老师使用 WorkBuddy 执行整理任务：按【学号_姓名】重命名、新建 `学生作业_已整理` 文件夹、生成 `名单.xlsx`。
- 关键体验：让老师亲眼看到"乱 → 整齐"的转变。

**讲师课前提示词（生成样例，留存）**：

```
请在桌面创建一个文件夹，路径为桌面/样例_学生作业。

在这个文件夹里创建 11 个学生作业文件，文件名要混乱、真实，混合以下类型：
- 纯编号型：001.docx、003.pdf
- 姓名+混乱后缀型：张三_final.docx、李四_提交版.docx、王五_new.pdf
- 系统默认型：新建 Microsoft Word 文档 (2).docx、文档1.txt
- 看不出姓名的型：作业.docx、未命名.pdf

文件内容随便写一句占位文字即可，例如"这是学生作业示例内容"。

最终输出：列出你创建的所有文件名，并确认文件夹路径。
```

**老师上手提示词（整理）**：

```
桌面上有一个文件夹 样例_学生作业，里面文件名非常混乱。

请帮我完成以下整理：
1. 按【学号_姓名】的格式重命名所有文件，学号从 2026001 开始递增；
2. 姓名能从原文件名中识别出来的，用识别到的姓名（如张三、李四）；识别不出来的，写"未知姓名"；
3. 重命名后，把所有文件移动到桌面新建的文件夹 学生作业_已整理 中；
4. 在 学生作业_已整理 文件夹中生成一个 Excel 文件 名单.xlsx，A 列为"原文件名"，B 列为"新文件名"。

完成后请告诉我：整理了多少个文件，未知姓名的有几个，并列出前 3 个重命名示例。
```

#### 案例二：调研报告（AI 能查证）

- 先让纯 LLM（网页版 Kimi/DeepSeek）生成调研报告并现场点链接验证，展示 LLM 链接可能编造。
- 再用 WorkBuddy 生成带真实来源链接的 Markdown 报告，现场点击验证。
- 老师上手：自选专业课题（教改政策、竞赛政策、专业认证、课程建设等），生成带链接的简报。

**演示用提示词**：

```
请调研近三年国内高校"人工智能通识课"的建设政策和典型案例，整理成一页 Markdown 简报。要求：
1. 包含 5-8 个要点；
2. 每个要点必须附上可点击的来源链接；
3. 标注每个来源的发布日期；
4. 优先引用教育部、省级教育厅、知名高校官网的公开信息。
```

**老师上手提示词**：

```
请调研【你的专业/课题】近三年的相关政策或典型案例，整理成一页 Markdown 简报。要求：
1. 包含 5-8 个要点；
2. 每个要点必须附上可点击的来源链接和发布日期；
3. 优先引用政府官网、教育厅、高校官网等权威来源。

完成后，请自己逐条点击链接验证是否能打开。
```

### 3.3 课堂流程（2.5 小时）

| 阶段 | 时长 | 内容 |
|---|---|---|
| 开场 + 目标介绍 | 10 min | 今天体验 AI 的两个超能力：动手 + 查证 |
| 能力全景秀 | 15 min | 快速展示 WorkBuddy 能做什么 |
| 案例一：整理文件 | 60 min | 演示乱文件 → AI 整理 → 老师上手 → 展示成果 |
| 案例二：调研报告 + LLM 对比 | 60 min | LLM 对比演示 → 老师自选主题调研 → 点链接验证 → 展示讨论 |
| 总结 Agent vs LLM | 15 min | 两个案例共同说明 Agent 的不可替代性 |
| 下节课预告 | 5 min | 下次用 WorkBuddy 做一个自己的教学工具 |

### 3.4 课前准备清单

- 在机房每台电脑桌面预置 `样例_学生作业` 文件夹。
- 测试 WorkBuddy 文件重命名/移动/生成 Excel 能力。
- 准备演示用的 LLM 网页（Kimi/DeepSeek）。
- 准备 5-8 个专业课题方向供老师选择。

### 3.5 保底成果

每位老师完成：
- 一个整理后的学生作业文件夹 + 名单表
- 一页带真实来源链接的 Markdown 调研简报

## 四、第二次课：用 WorkBuddy 做教学/办公小工具

### 4.1 定位

让老师体验"用自然语言生成可运行工具"，并处理真实工作材料。

### 4.2 三大模块

#### M1：作业提交网页工具（前后端分离）

**目标**：老师用 WorkBuddy 生成一个前端上传页面，看到后端真实运行效果。

**流程**：
- 讨论平时收作业的痛点（5 min）
- 讲师演示前端生成（10 min）
- 老师上手做前端（20 min）
- 后端真实效果演示（10 min）
- 成果展示（5 min）

**老师用提示词**：

```
帮我做一个网页版"作业提交"页面，保存为桌面 作业提交.html。

要求：
1. 页面标题为"作业提交"；
2. 学生输入姓名、学号；
3. 选择要提交的作业文件，支持 .doc、.docx、.ppt、.pptx、.pdf 格式；
4. 点击"提交作业"按钮后，显示"提交成功"提示；
5. 页面样式简洁美观，适合课堂使用。

注意：提交时调用的后端接口地址先留空或用占位符，我会课后自己配置。
```

**进阶提示词**：

```
在刚才的作业提交页基础上，增加：
1. 提交前检查姓名和学号是否为空；
2. 提交时显示上传进度；
3. 提交成功后清空表单。
```

**课后延展**：提供后端代码模板（Python Flask / Node.js）和部署说明，老师可选补全后端。

#### M2：课堂随机点名工具

**目标**：老师用 WorkBuddy 生成一个可本地运行的随机点名网页。

**老师用提示词**：

```
帮我做一个网页版"课堂随机点名"工具，保存为桌面 随机点名.html。

要求：
1. 页面标题为"课堂随机点名"；
2. 可以上传一个 Excel/CSV 班级名单（至少包含"姓名"列），也可以手动输入名单；
3. 有一个"开始随机点名"大按钮，点击后随机抽取一个名字并高亮显示；
4. 显示本次抽取记录；
5. 可以导出抽取记录为 CSV；
6. 页面样式美观，按钮明显。
```

**进阶提示词**：

```
在随机点名工具基础上增加：
1. 已被抽过的名字短期内不再重复抽取；
2. 可以设置一次抽取几人；
3. 显示全班总人数和已抽取人数。
```

#### M3：零散报名信息整理成总表

**目标**：老师用 WorkBuddy 读取截图和文档，提取信息并整理成 Excel。

**课前准备**：桌面 `报名` 文件夹，内含 1 张微信截图、1 个 Word 文档、1 个 PDF 文档。

**老师用提示词**：

```
桌面上有文件夹 报名，里面有家长发来的微信截图和几个文档，内容是学生报名信息（姓名、电话、志愿等）。

请帮我：
1. 提取所有报名信息；
2. 整理成一张 Excel 表格 报名总表.xlsx；
3. 表格列包括：姓名、联系电话、报名志愿、信息来源文件名；
4. 如果截图中的文字识别不清，请在对应单元格标注"需人工核对"。

完成后告诉我：共提取到几条报名信息，有几条需要人工核对。
```

### 4.3 课堂流程（2 小时）

| 阶段 | 时长 |
|---|---|
| 开场 + 回顾第一次课 | 10 min |
| M1：作业提交网页工具 | 50 min |
| M2：随机点名工具 | 35 min |
| M3：报名信息整理 | 35 min |
| 总结 + 下节课预告 | 10 min |
| 合计 | 2 小时 20 分钟 |

### 4.4 课前准备清单

- 每台电脑桌面预置：
  - `收到的作业` 空文件夹
  - `花名册.xlsx`
  - `报名` 文件夹（含截图、Word、PDF）
- M1 后端预部署：上传接口、名单接口、下载接口、后台管理页面
- 准备后端代码模板和部署说明
- 准备 1-2 个备用前端页面

### 4.5 保底成果

每位老师完成：
- 一个作业提交前端页面
- 一个随机点名工具
- 一张报名总表

## 五、第三次课：ima 知识库 + 钉钉跨系统办公

### 5.1 定位

AI 接入个人知识库（ima）和办公系统（钉钉），跨系统取资料、生成方案、真实交付。

### 5.2 核心认知

1. **持久记忆**：ima 是长期留存、跨设备可调的资料库。
2. **跨系统取数**：AI 能从 ima 读资料，也能从钉钉读文档。
3. **真实动作与交付**：成果落到电脑，还能通过 WorkBuddy 发到钉钉成员。

### 5.3 四段任务

#### Task A：接入 ima + 检索

**提示词**：

```
在我 ima 知识库里找出所有关于"课程思政"的内容，整理成 5 条要点，并注明分别来自哪份文件。
```

#### Task B：基于 ima 生成 PBL 项目方案

**提示词**：

```
基于我知识库里的专业资料和教学大纲，生成一份《XX 课程建设项目申报书》初稿，正文引用知识库具体文件，文末列出用到的资料。
```

或：

```
基于知识库，生成一份面向学生的 PBL 项目方案（主题/任务/产出/评价），引用相关资料。
```

#### Task C：接入钉钉取数并入方案

**提示词**：

```
读取我钉钉里[文档名]的内容，提取和本项目相关的要点，补充进刚才的项目方案。
```

**注意**：不碰钉钉群聊记录，只读钉钉文档。

#### Task D：把生成的文件发到钉钉成员

**提示词**：

```
把桌面上生成的项目方案.pdf 通过钉钉发送给[测试成员姓名]，附一句说明。
```

### 5.4 课堂流程（2.5 小时）

| 阶段 | 时长 | 内容 |
|---|---|---|
| 开场 + 三课弧回顾 | 15 min | 演示"ima 取资料 + 钉钉取文档 → 生成 → 发钉钉"完整流程 |
| 准备 | 20 min | ima 登录绑定 + 钉钉连接确认 |
| Task A：ima 检索 | 20 min | 从知识库找内容并标注来源 |
| Task B：生成 PBL 方案 | 40 min | 基于知识库生成方案，引用具体文件 |
| Task C：接入钉钉取数 | 25 min | 读取钉钉文档，补充进方案 |
| Task D：发钉钉 | 25 min | 把文件发到指定测试成员 |
| 收尾 | 10 min | 分享 + 边界提醒 |

### 5.5 课前必须验证

1. ima 在机房每台电脑上登录/授权正常。
2. WorkBuddy 能读取指定 ima 知识库内容。
3. 钉钉 Connector 已连接，能读取指定钉钉文档。
4. WorkBuddy 能把文件通过钉钉发给指定测试成员。
5. 准备培训测试钉钉群/测试接收人，**严禁使用真实学生或敏感数据**。
6. 准备 ima 样例知识库资料包，作为老师自带文件的兜底。

### 5.6 风险提示

- ima 授权容易过期，建议课前统一登录或使用培训账号。
- 钉钉文件发送可能有权限/大小限制，需课前实测。
- 隐私合规：只用公开/自有文档与测试对象。

### 5.7 保底成果

每位老师完成：
- 一份基于 ima 知识库生成的 PBL 项目方案
- 一次把生成的文件发送到钉钉的真实体验

## 六、第四次课：AI Agent 工作流方法论工作坊

### 6.1 定位

9 月培训收官。分组研讨 + 协作生成工具 + 小组路演 + 颁发认证证书。

### 6.2 核心目标

让老师带走三样东西：
1. 一套可复用的 AI Agent 工作流方法论。
2. 一个小组共同完成的可运行工具。
3. 一份 AI Agent 能力认证证书。

### 6.3 分组与角色

- 每组 3-4 人，跨学院/跨专业分组。
- 每组至少配 1 位会用 WorkBuddy 的老师。
- 角色分工：
  - 组长：把控方向，协调讨论，拍板题目。
  - 痛点分析师：把问题拆成 AI 能做的步骤。
  - 提示词工程师：把任务写成 WorkBuddy 提示词。
  - 测试汇报员：测试工具并准备路演。

### 6.4 完整流程（3-3.5 小时）

| 阶段 | 时长 | 内容 |
|---|---|---|
| 开场 + 方法论串讲 | 30 min | 回顾 9 月三次课，讲解四步工作流 |
| 分组研讨找痛点 | 30 min | 小组填 AI Agent 工作画布，确定题目 |
| 用 WorkBuddy 生成工具 | 80 min | 小组写提示词、生成、测试、迭代 |
| 准备路演 | 20 min | 每组准备 5 分钟展示材料 |
| 小组路演 + 互评 | 60 min | 每组 5 分钟展示 + 2 分钟提问 |
| 颁证 + 总结 | 20 min | 颁发证书、宣布优秀小组、10 月预告 |

### 6.5 AI Agent 工作画布（小组版）

```
我们要解决什么问题？
├── 这件事谁遇到？（我/学生/同事）
├── 多久发生一次？（每天/每周/每学期）
├── 现在我怎么做的？（手动步骤）
├── 最烦人的一步是什么？
├── 理想结果是什么？
├── 需要 AI 做什么？（读文件/生成页面/发钉钉/整理数据）
└── 输出应该是什么？（Excel/网页/报告/图表）
```

### 6.6 路演评分标准

满分 40 分，四个维度各 10 分：
1. **痛点真实性**：是否是真实工作场景中的问题。
2. **AI 适用性**：AI 是否比传统方法明显更好。
3. **工具完成度**：现场能否跑通，功能是否完整。
4. **展示清晰度**：问题、方案、演示是否讲清楚。

加分项：
- 使用了 ima 知识库或钉钉（+3 分）
- 工具可以跨系统完成真实动作（+3 分）
- 有明确的课后使用计划（+2 分）

### 6.7 认证证书规则

- **发放标准**：完成 9 月培训至少 3 次出勤 + 参加第四次 workshop 并完成小组任务。
- **额外激励**：优秀小组奖、最佳创意奖、最佳技术奖、最佳展示奖。
- 证书建议加盖总部/学校印章，增强仪式感。

### 6.8 PLAN B 兜底机制

如果小组找的痛点不适合 AI：
1. **AI 适合解决的痛点菜单**：从菜单里勾选或改编。
2. **通用改造题库**：提供 6-8 个可直接做的题目。
3. **9 月工具箱模板改造**：从第一次/第二次/第三次课模板选一个改造。
4. **助教快速分流**：每组填完画布后，助教 1-2 分钟判断是否适合 AI。

### 6.9 课前准备清单

- 分组名单提前 1 周公布。
- 每组 1-2 台电脑，场地可投影。
- 物料：AI Agent 工作画布、痛点菜单、评分表、证书、小奖品。
- 助教：1 名助教负责 2-3 个小组。
- 评委：高校领导 + 转转/聂斌 + 1 位教师代表。
