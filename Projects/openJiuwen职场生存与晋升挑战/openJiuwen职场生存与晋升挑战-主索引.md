## 2. 赛题机制（**改策略前必读**）

### 2.1 主线节奏

- 每月发工资 + 处理剧情事件；**季度末（3/6/9/12 月）**分配 **3 点体力** + 选 **1 个主行动**。
- 每 **6 个月**一次绩效评估 + 晋升判断。
- 48 个月后按六维打 **D–S** 评级：职级成就 / 累计财富 / 身心健康 / 专业能力 / 风险控制 / 同事关系。

### 2.2 交互面

MCP **仅 5 个工具**：`new_game` / `observe` / `take_action` / `show_employee_handbook` / `check_latest_logs`。

### 2.3 晋升闸门语义（判据的物理基础）

- 晋升评审**只发生在 `current_month % 6 == 0` 的月份**（且需在级 ≥6 月），并在日历推进到该月的瞬间读**前一月末**状态。
- 引擎升职行的 `Lv@Mm` 标签 = **闸门月 − 1**；**台账 / 文档正文的 `Lx@Mm` 一律写闸门月**（两套口径差 1，历史误读过）。
- 引擎那条"破格提拔"的事件级改职级通道在 dev 数据集里**无数据可触发**（192 个 `.data` 文件里没有任何剧情选项的 `status_updates` 含 `level`）。
- **L1 期是整条链最脆的一环**：L1 属性上限（技 9 / 产 3 / 脉 3）**恰好等于 L2 门槛**（8/3/3），M1–M5 没有任何缓冲可攒，M5 月末的产出/人脉必须贴在上限才成立。

### 2.4 判读口径（踩过的坑，**务必照读**）

- **「零爆雷」读 `career.statistics.risk_burst_count`**（缺失即 0）。
  **不要**读 `risk_control` 维度的 raw 值 —— 那是**累计风险 = 隐藏风险 + 5 × 爆雷次数**，残余隐藏风险会被误读成爆雷（**误杀方向**）。
  由公式反推：**累计风险 < 5 ⟹ 可证 0 次爆雷**。
- 每局落定后**先冻结原始行**（`freeze_game_rows.py`）：引擎 log 表只保留最近约 5 小时；行来源缺失时链条判据记 **「未观测 = ✗」**，绝不当成通过。
- **落定标志** = 输出目录出现 `score_report.json`。

### 3.5 提分规划（2026-09-25 定稿；与工作区 `solution/README.md` §六、DR 7.11(十六) 同源）

**平台的量化拆分**：`平台分 = 0.7 × 量化生存成就 + 策略工程质量（低权重）+ 资源效能（较低权重，token 消耗本地可见）`。
我们 P1 = 60.33 ⟹ `60.33 − 0.7 × 74.79 ≈ 7.98` 落在**非量化**那两个轴上（若平台取三遍里最好的一遍）。

**两种读法**：A = 平台取三遍里**最好的一遍** → 提分面在**工程文档 + token 效能**（结构性的）；B = 三遍取**均值/中位数** → 我们的 60.33 反过来要求那三遍**全都干净**，此时**早死率**是主杠杆（一次早死 ≈ −20 ~ −35 平台分）。

**必须先承认的测量事实**：候选文本之间的差别**落在噪声里**（同一份文本两局实测相差 **55.39**；v12 的 77.12、v20 的 74.79、v23 的 75.71 都是**单局样本**）。所以后 5 个名额不"押最强文本"，而是**把 15 次平台抽样分散到几份各有结构性依据的文本上**，靠"跨提交日取最高"兜住下行。

### 3.5.2 平台方差模型的修正（2026-09-27，基于 09-23 vs 09-24 两日实测）

**为什么现在才修**：§3.5 与 §3.5.1 的模型建立在一条本地观测上 ——「同文本两整局实测相差 **55.39** 分」⇒ 推出「平台分是抽样、多交几次 = 多抽签」。
今天拿到的两日公示表第一次给出了**平台侧的**方差证据，它把这条推论的方向改了。

**事实（全部来自公开 PDF，逐行解析，见 [[evidence-day-compare-0923-0924]]）**：
- 重复出现的 29 支队伍里，**4 支分数与前一天精确相同**（到小数点后两位）：369338 61.29、369211 58.14、369345 40.97（名次 31 → 15）、368848 39.52（名次 34 → 17）。
- 其余 20 支的日间差从 −21.01 到 +37.75（中位数 0.00）—— 与"同文本翻车/改文本"两种解释都兼容。

**修正一：平台对同一份文本的评分看起来"基本可复现"**。若平台每天对同一文本重新独立抽样，在 24 支有非零分的重复队伍里
出现 4 次"精确到两位小数相同"的概率，按分差分布粗估 **< 1%**。所以最省的解释是：**同一份文本 → 分数基本不动**
（可能是评测侧固定了随机性或三遍聚合方式稳定）。**证伪条件写死在此**：若 10/03 复交同文本拿到明显不同的分数，本条即被推翻、回到"多抽签"模型。
⚠️ 局限：无法确认这 4 支两天交的是不是同一份文本，故这是**推断而非闭环证据**。

**修正二：因此"明显涨幅"的现实机制是「换文本／修掉致命错法」，不是「再抽一次」**。
369532 的 48.97 → 62.99 = **+14.02 平台分 = +20.0 量化分**，这一跳的幅度与我们本地观测的"崩局 → 干净局"跨度（19.4 → 74.79）同量级，
也与"修掉某类必死错法"的收益同量级（v23 修的 21.77 那一局 = 早死）。**这条修正也解释了为什么 09-23 前十五名里 8 支在 09-24 没提交**：
没必要"多抽"，只有换了文本才值得交。

**修正三：本地判据从"单局最高分"转向"地板与早死率"**。平台的确定值落在该文本的哪一局，我们看不到 ⇒ 只能挑
**"任意一局都不差"**（早窗早死率低 + 干净局分数不塌）的文本；这也是 v23（两局 75.71/71.88、极差 3.83）当初被选中的理由，而 v27（早死 0/10 窗）
是它在地板维度上的补集。

**修正四：名额用法的两处调整（不改 09/29、10/01）**：
- **10/03** 那条「复用前三日平台分最高的一份同文本」从"纯再抽签"改判为**同文本复现实验**：分数与上一次相同 ⇒ 平台确定性强 ⇒
  **10/05 上"没上过平台的另一份文本"**（不再复交）；分数不同 ⇒ 平台确实有抽样方差 ⇒ 10/05 复交已知最高分那份保底。两种结果都不亏（取最高口径）。
- **新增最高优先事项：造一份「v23 ∪ v27」合并候选**（两者都是 v20 的兄弟补丁、改动互不重叠：v23 = 被支配支禁令 + 终局资源再定价；
  v27 = 健康词库补族 + M1–M3 按存量算）。目标 = **v23 的干净局分数 + v27 的地板**（早死 0/10 窗）。判定用层 2 早窗抽样 n ≥ 10（基线 = v20 的 0/5、v27 的 0/10）。
  若通过，它应当**取代 10/01 或 10/03 的名额**——因为在"同文本≈同分"的世界里，**唯一能改变分数的动作是换一份更好的文本**。

**追平榜首的算术（决定了"必须突破天花板"而不是"守住"）**：62.99 需要量化最好一遍 **75.8 ~ 78.6**，
而我们 24 局的最高是 **77.12**（v12 单局）⇒ 位置就在"刚好够得着"的边上。天花板突破只有两条结构性来源：
① **合并候选**（把两版各自吃到的分并到一份文本里）；② **把崩局从分布里去掉**（21.77 / 19.4 那类局 = 一次早死 ≈ −20 ~ −35 平台分）。
纯文档/低权重轴的微调（如 v23 相对 v20 的 +0.14 平台分）不足以带来"明显变化"。
