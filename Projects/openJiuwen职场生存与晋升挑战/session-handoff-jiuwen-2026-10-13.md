## 四、结论三：真正的差距是「可测性」，不是分数

| 维度 | 对手（`observe-decide-review` v4.7.5） | 我们（`career-strategy` v44） |
| --- | --- | --- |
| 架构 | `mode: team`（Leader ＋ 5 个指标专家）；**末次 commit 已退回 `mode: "agent"` 串行** | `mode: "agent"` 单 agent |
| 语义→数值 | **显式翻译层**：每指标一个专家，产出 −3..+3 整数增量；官方 `status_updates` 直接采纳 | 散文判据，隐式权衡 |
| 决策引擎 | `numeric-policy.py` 确定性价值函数 ＋ 季度组合穷举 | 五步排除法 ＋ 阶梯否决权 |
| 不确定性 | 误差模型 ＋ 32 组扰动算「决策稳定率」，**<0.5 弃权交回语义判断** | 无弃权概念 |
| 机制常数 | 写死 `STAT_CAPS`（门槛×1.2）／晋升比例／绩效拟合式／月薪表 | 刻意不写（合规口径） |
| 迭代方式 | **离线回放台**：官方引擎、**零 LLM 调用**、128 局×7 档 = **896 局** | 整局实跑 ≈ **8 500 万 token/局** |
| 评测集 | 翻译基准（加权符号余弦，R 权重 5，65% 验收线） | 只验「包能不能跑通」（离线 3/3、引擎 14/14） |
| 成绩轨迹 | 43.34 → 38.09 → 29.62 → 49.78 → **57.21**（末段 +7.43，无清零） | 60.33 → 53.03 → **0.00 → 0.00** → 56.72 → **60.33**（末段 +3.61，清零两次） |

**根因**：他的循环闭环且廉价（改规则 → 896 局离线 → 看中位数 → 再改）；我们的循环开环且昂贵（改规则 → 8 500 万 token 一局 → 单局噪声大到判不出优劣）。
**共同边界**：他的离线回放同样是**公开 Dev 剧本**；`Test 剧本` 下本地/离线分数都不外推 —— 57.21 与 60.33 都是 Test 读数。

## 五、可借鉴 / 不可照抄

**可借鉴三条（若继续参赛或复现，按序做）**
1. **语义与数值分离**：决策前先产出一份结构化属性增量，再让规则择优 —— 否则「判错了」和「选错了」无法区分。
2. **先建官方引擎离线回放台，再谈策略迭代**：目标是零 LLM 调用批量跑局，把「改一次策略」的成本从 8 500 万 token 压到 0。**没有这一步，任何策略改动都是抽签。**
3. **给决策留弃权出口**：候选分不出高下、或所有选项都触发否决时，显式标记低置信度并退回最保守的可行支。

**不可照抄两条（风险提示）**
1. **「把机制常数写进脚本」没有被证明安全**：他写了各级上限、晋升比例、绩效拟合系数、月薪表且 5 次提交未被点名；但同届 `365713` 因「写死**引擎配置**」被判 `0.00`。**样本两份、判语不同 ⇒ 不得据此放宽我们的合规口径**（我们已被清零两次）。
2. **team / 并行不是免费杠杆**：五专家并行 = 每事件 5 倍调用 ＋ 成员/交接/隔离复杂度；**他自己末次已退回单 agent 串行**（理由写在 `manifest-README.md`：阶段间有因果依赖）⇒ **我们保持单 agent 是对的，不要因为「他用 team」就改回 team。**
