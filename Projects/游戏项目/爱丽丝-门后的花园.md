## 起点：为什么要重做

桌面上原本就有一套爱丽丝素材（Godot 工程 + 模型贴图），但做出来的东西是"走一段路看一段字"：情节简单、场景基础、关卡几乎没有挑战，整体没有让人玩下去的意愿。

重做时的取舍：

- **不加剧情量，加规则**：与其塞更多对白，不如让同一个场景在三种身高下有三个答案
- **不用新素材**：模型、贴图沿用原素材，缺的家具花瓶茶杯一律程序化补齐（`src/art.js`）
- **不加战斗与死亡**：压力来自"该多高"的判断，而不是操作精度
- **每章必须有一次"规则反转"**：糖块从障碍变阶梯、水从地面升到花心、颜色从花上被抽走

**推荐（离线双击）**：`dist\爱丽丝_门后的花园_单文件版.html`
单个 20.4 MB 的 HTML，three.js、GLB 模型、贴图全部 base64 内联，**零外部请求**，断网可玩。

**开发版**：

```

python -m http.server 8123
```

重新构建：`node build.mjs` → `dist/bundle.js` + `dist\爱丽丝_门后的花园_单文件版.html`。

## 三档身高 = 三张地图

身高 = `1.25 × factor`（`src\player.js` 的 `SCALES`）：

| 档位 | 比例 | 实际身高 | 能做什么 | 不能做什么 |
|---|---|---|---|---|
| 小小爱丽丝 | 0.115× | ≈0.14 m | 钻门缝、走糖块阶梯、爬花茎、进老鼠洞 | 推不动重物、上不了桌 |
| 正常 | 1× | ≈1.25 m | 对话、扳阀门、走正门、开花园栅门 | 钻不过小门、够不到高处 |
| 巨大 | 2.55× | ≈3.2 m | 转水泵轮、够书架顶、把整排门推开 | 进不了任何小门，移动很"钝" |

镜头的距离、移速、跳跃力、抬脚高度都跟着档位走，所以**同一个台阶在三种身高下是三种手感**。变大时有安全检测：头顶或脚下空间不够会提示，不会把角色卡进墙里。

## 四章流程（每章一个"哇"点）

| 章 | 场景 | 核心机关 | 规则反转 |
|---|---|---|---|
| 序章 | 兔子洞与钥匙大厅 | 书架围成的竖井坠落 → 落进全是门的大厅；先**变大**够钥匙，再**变小**钻小门 | 同一把钥匙，两种身高才够得着 / 用得上 |
| 第一章 | 茶话会桌面 | **变小**钻桌下顶翻糖罐，55 块方糖滚落自动垒成阶梯；爬上台面给停摆的怀表上弦 | 糖块从障碍变成楼梯 |
| 第二章 | 玫瑰园 | **巨大**转水泵 → **正常**把三个阀门扳到 `235` → **变小**沿花茎里的花瓣台阶爬到花心 → 倒色奇观 | 水从地面升到花心；满园颜色被抽走、再化作彩屑落回 |
| 尾声 | 门后的花园 | 沿花径走到石桌前，**变小**推开那扇 1 米高的薄荷色小门（序章那扇门的回声） | 门后不是别处，是你走过来的路 |

- **花瓣收集**：实装 **19 片**（序章 5 / 茶话会 5 / 玫瑰园 5 / 尾声 4），但 HUD 与结局判定写的是 15 片（见「已知限制」）；结局文本按 `n≥15` / `n>0` / `n=0` 三档变化
- **时长**：3–6 分钟/章，全流程约 15 分钟
- **不软锁**：`R` 回本章出生点，`Esc` 有当前提示

## 成片是怎么做出来的（可复用流程）

**画面：确定性逐帧导出，不是录屏。**

1. 桩掉 `requestAnimationFrame`，改成手动 `game.tick(1/24, false)` + `engine.render()`，游戏看到的 `dt` 恒定，帧号可复现
2. 每帧 `renderer.domElement.toDataURL('image/jpeg', 0.86)` → base64 POST 给本地接收器（写成 `frames/f%05d.jpg`）
3. 剧情演出会自己 tween 相机 → 设 `player.cameraLocked = true`，再用每帧执行的 camera hook 覆写 `camera.position` + `lookAt`，关键帧之间用 smoothstep 插值
4. 素材约 900 帧，按叙事重排成 13 段 626 帧；绿屏故障帧（668–669 一带）整段避开，被角色挡住的彩雨近景换成全景彩屑镜头

**声音：原创，无版权风险。**

- Node 里合成 3/4 拍（90 bpm）音乐盒圆舞曲：加法合成泛音 + 铺底和弦 + 低音拨弦 + 沙锤 + 延迟回声 + `tanh` 软削波
- 归一化 `loudnorm=I=-15:TP=-1.5:LRA=9`，48 kHz 立体声 AAC 192k

**封装：**

```bash
ffmpeg -framerate 24 -i cut/f%05d.jpg -i bgm.wav \
  -vf "eq=saturation=1.14:contrast=1.03,fade=t=in:st=0:d=0.5,fade=t=out:st=25.08:d=1.0,
       scale=in_range=full:out_range=tv:out_color_matrix=bt709,format=yuv420p" \
  -c:v libx264 -preset slow -crf 18 -profile:v high -level 4.1 -pix_fmt yuv420p \
  -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709 -movflags +faststart \
  -af "loudnorm=I=-15:TP=-1.5:LRA=9,aresample=48000" -c:a aac -b:a 192k -ar 48000 -shortest out.mp4
```

**验收数据（2026-11-24）**：`ffprobe` 参数一致；`ebur128` 综合响度 −15.2 LUFS、LRA 2.3；浏览器内实际播放并拖动进度（21.2s 帧正确），播放 1.3 秒后 `webkitAudioDecodedByteCount = 58 949`，解出的音轨 2 声道 / 48 kHz / 26.07 s / 峰值 −4.6 dBFS / RMS −21.3 dBFS——**确证有声、不是静音片**。

## 技术要点 / 踩过的坑

> [!warning] InstancedMesh 的包围球会过期，整段阶梯被"画没了"
> 糖块阶梯是 InstancedMesh，包围球只在创建时算一次。方糖一块块垒高后包围球还停在原处，整段阶梯被视锥剔除——碰撞体在、人走得上，但屏幕上什么都没有，看起来像"阶梯没生成"。修法：`cubeMesh.frustumCulled = false`。凡是"实例化 + 运行时改实例矩阵"的物体都要想到这一条。

> [!warning] 录屏得不到可复现的帧
> 用屏幕录制或 Playwright 截图，掉帧、鼠标抖动、后期抖动全在里面，且某个镜头拍坏了只能整段重来。把 rAF 换成手动 tick 之后，任意一帧都能单独重拍、时间轴精确到 1/24 秒。

> [!warning] 剧情会抢相机
> 章节里的 `tween()` 每帧写相机，外部直接改 `camera.position` 会被下一帧盖掉；如果靠"停止推进剧情"来定格，画面里的粒子、光环、角色动画也跟着停。正确做法是让剧情照跑，只在渲染前覆写相机。

> [!warning] 剪辑点要逐帧核，别按直觉卡时间
> 倒色的演出是"2.2s 抬升 + 2.6s 抽色 + 0.7s 等待 + 3.4s 彩屑"，只按"大概 3 秒"剪，剪出来的是空镜。核对方式：`signalstats` 扫异常帧（这次揪出 666–669 的绿屏）+ 逐段抽帧看内容。

> [!warning] yuvj420p 和 96 kHz 是两个静默坑
> JPEG 序列是全范围色彩，直接编码会得到 `yuvj420p`、颜色发灰；`loudnorm` 会自己升到 96 kHz。两处都要显式写：`scale=in_range=full:out_range=tv:out_color_matrix=bt709` + 四个 `-color_*` 标签；音频加 `aresample=48000` 和 `-ar 48000`。

> [!warning] `python -m http.server` 不支持 Range，会让成片"看起来坏了"
> 它的响应没有 `Accept-Ranges`，`<video>` 的 `seekable` 为空，`currentTime = 9.5` 设了还是 0，截图永远是第一帧——像是编码失败。换成 30 行带 206/Range 的 node 静态服务就正常，`seekable` 立刻变成 `[0, 26.08]`。

- **阀门谜题要 `235`**：三个阀门每次 +1 mod 5，**同次数循环永远等值**（实测日志 `222/333/444/555/111`）。必须非对称地拧（1 次 / 2 次 / 4 次）才落在 235
- **机关有前置条件**：水泵要求已接水且 `factor ≥ 2`；花心入口要求阀门已解且 `factor ≤ 0.2`——录制脚本必须排好"巨大 → 正常 → 变小"的顺序
- **页面会自我重载**（章节切换），注入的录制对象会被清空：每段录制前先查 `location.href` / `hasRec`，没有就重新注入
- **调试口**：`window.__alice` 有 `goto(n) / scale('small'|'normal'|'giant') / teleport(x,y,z) / interact() / sim(秒) / petals()`，每章另有 `game.chapter.debug()` 返回关卡状态；录制与验收全靠它

## 已知限制

- **花瓣数两套数（未修）**：四章实装 19 片，但 `ui.petals(n, total = 15)`、`main.js` 的 `petals(…, 15)` 与结局判定的 `n >= 15` 都写死 15——集满会显示 `19 / 15`，结局台词仍是"十五片"。两个口径二选一：把 total 提到 19，或每章各减一片
- **手机不能玩**：全库零 `touchstart` / `pointerdown`，只能电脑键鼠。要上手机得先补虚拟摇杆与按钮
- **体积大**：单文件 20.4 MB（模型贴图全内联换来的离线能力），首次打开要几秒
- **没有存档**：刷新即重来，只有章节级 `?chapter=` 跳转
- **没有关卡编辑器**：四章是硬编码的场景，改关卡要动 `src/chapters/*.js`
- **成片只有 26 秒**：四章各给了一个镜头，是"预告"不是"通关流程"
