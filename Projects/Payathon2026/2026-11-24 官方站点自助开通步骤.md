## 3 五步动作

### 3.1 先备齐材料，再进流程（避免来回断）

| 材料 | 具体要求 |
|---|---|
| 首页截图 | 站点首页，能看出你在卖什么 |
| 商品页截图 | 有具体商品/规格/价格 |
| 支付页截图 | **展示支付宝付款方式、等待用户去支付的页面**；不是支付成功页，也不能拿成功页顶替 |
| 应用公钥 | 由本人提供。私钥自己用官方密钥工具生成并保存，**不外发、不截图、不进对话** |
| 特殊资质 | 若页面提示该类目需特殊资质，按页面列出的组合补；页面没列就不用准备 |

> 三张截图用真实站点，不要用设计稿。当前 `pay-demo` 是本机 127.0.0.1 的沙箱基线，**不能**当线上站点截图交。

### 3.2 签约（产品开通节点）

1. 登录后选 **AI 网页应用收款**；
2. 经营类目选 **3C数码/家用电器**（页面上类目名若与本机记录不完全一致，取最接近的二级类目；**不要选"软件/技术服务"**，那与本轮答复的经营内容不符）；
3. 上传 §3.1 的三张截图；
4. 提交。

判据：**提交成功只表示申请已受理，不等于签约生效**。生效状态以页面显示为准；未生效前不要对外说"已可收款"。

### 3.3 新建应用并设公钥

1. 开放平台新建应用，类型 **网页应用（WEBAPP）**；
2. 用官方密钥工具生成 RSA2 密钥，私钥留本机，公钥填到"设置应用公钥"；
3. 公钥确认页会要求支付宝扫码确认；确认完记下 **APPID**；
4. 提交应用审核。应用未上线时不能复用候选，只能新建。

### 3.4 生效与费率

费率、额度、可收款时间**一律以商家平台页面为准**——Skill 侧明文禁止承诺这三项，本文件同样不给数字。若页面展示费率，只记录不推断。

### 3.5 回来交给我四样东西（恢复点）

| 要交回 | 用途 |
|---|---|
| 签约状态（页面文字或截图，写明"已生效/待生效/审核中"） | 决定能不能做 L3 |
| APPID | 换掉沙箱配置，接生产网关 |
| 公钥是否已确认（页面状态） | 应用侧是否可提审/已上线 |
| 三张截图的最终版本 | 存档，后续对外材料复用 |

**只交这四样。不要交登录密码、支付密码、短信验证码、应用私钥。**

## 4 安全核对点（扫码/授权时逐条对）

| 核对项 | 判据 |
|---|---|
| 域名 | 必须是 `aipay.alipay.com` 或 `b.alipay.com`，且是 `https://`；不是这两个域名的"授权页"一律关掉 |
| 链接时效 | 授权链接**10 分钟内有效**，过期即作废；不要转发到群聊/朋友圈 |
| 确认码 | 页面显示的确认码要与当前这次请求一致（本轮生成的是 428152，**已过期**；下次以新生成的为准） |
| 授权范围含义 | `app:all` + `fast_instant_trade_pay:write` = 该应用的交易接口写权限（下单、查询、退款、关闭）。**不含**转账、提现、改密码、改绑定手机 |
| 真实风险点 | 谁拿到这条授权链接，就能以你的应用身份发起交易与退款 ⇒ 链接本身等同一次性凭据，外发即失控 |
| 事后可撤 | 授权完成后可在支付宝"授权管理"里撤销该应用授权；撤权后应用侧接口即失效 |
| 我方边界 | Agent 全程不接触：登录密码、支付密码、短信验证码、生产私钥、token |

## 6 回来后我这边接着做什么

1. 核对签约状态 → 若 `SIGNED_EFFECTIVE`，把 `pay-demo` 从沙箱网关切到生产网关（配置项切换，不动业务代码）；
2. **L3**：线上一笔 **0.01 元**真实交易 → 取支付宝账单里的交易号 → 走官方「验证交易」；
3. **L4**：买家 ≠ 卖家，权益按订单核销；
4. 同步做选题定稿（一句话：谁、在什么截止日前、花多少钱买什么）。

> L3 之前，对外材料一律不写"已跑通支付"。
