# 接入校准单 · 第一步

> **本步目的**：在写任何产品代码、任何页面、任何定价文案之前，先拿到**官方侧可核验的一笔交易**，并把"跑通"定义成一张能打勾的表。
> **为什么是它**：这是智擎杯三条教训在这场比赛上的直接移植（见 §1）。抄的是方法，不是内容。
> **产出一页**：官方口径核对表（§3）＋ 跑通判据（§4）＋ 今天两小时的动作表（§5）。

## 0 一句话

**第一步不是做产品，是做"收款基线"。** 基线没拿到之前，任何"我的应用能收钱了"都是本地代理解释，不是官方事实。

## 1 智擎杯三条教训 → 这场怎么落

| 教训（可复核） | 原文出处 | 移植到 Payathon |
|---|---|---|
| **把关键情报读反了**，而且读反的那一条恰好决定整周方向 | 复盘 §7 失误 1（10-16 把官方基准图读成"机器读图、别按美术图做"） | 这场的关键情报是"支付怎么算成功"。官方已明文：**"页面返回不等于支付成功，需查询确认权益"**、**"支付结果必须以异步通知或查询接口返回为准，不能依赖同步跳转"**。⇒ 前端跳回成功页 = 假成功，不能当跑通证据 |
| **代理指标当 KPI**，5 发以上在噪声里打转 | 复盘 §7 失误 2、§6 噪声带 | 这场唯一真指标是**官方侧可查的交易记录**（交易号 / 金额 / 时间 / 状态）。"本地下单成功""payUrl 有返回"只是代理指标，必须标注"代理谁、验过没有" |
| **判死刑不分通道**，50 张已做好的图一张没用上 | 复盘 §7 失误 3、§5 L1 | 收款有四个通道：**同步跳转 / 异步通知 / 主动查询 / 对账下载**。四通道分开记账，任一通道不成**不许**判"整条链路没用"；只有一个通道不成，先补那个通道 |

> 再加一条本次制度性的：**官方文档会自相矛盾，按最严读法准备**（复盘 §12.2）。本文已抓到一处：沙箱网关在接入指南里**未载**，在赛事页里写的是 `openapi-sandbox.dl.alipaydev.com`。这类矛盾不猜，实测。

## 4 跑通判据（四级，逐级过；上一级没过不许做下一级）

| 级 | 判据 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| **L1** | 下单调通，拿到 `payUrl` | 接口参数与签名对了 | 与"收到钱"无关 |
| **L2** | 沙箱完成支付，`alipay.trade.query` 读到 `trade_status`，且 `out_trade_no` / `total_amount` 与下单一致 | 下单→支付→查询这条链是通的 | 与"真实资金"无关（沙箱是模拟数据） |
| **L3** | **线上**一笔真实支付（0.01 元），在**支付宝账单**里按交易号查到该笔，金额与时间一致，且**把交易号粘贴回官方页点"验证交易"通过** | 真能收到钱，且官方认这笔 | 不能证明"交付绑在付款上" |
| **L4** | 买家账号 ≠ 卖家账号；**权益按订单核销**（未查到订单则不放行），不是前端判断 | 收款与交付绑上了 | 不能证明"有人愿意付第二次" |

**四条纪律**

1. **L3 之前，任何材料里不许出现"已跑通支付"**——只能写"沙箱链路已通"。
2. **L2 之前，不许开始做页面文案与定价**——页面是装饰层，装饰层先做会掩盖链路问题（智擎杯"换皮不动骨"的反向教训）。
3. 每级证据单独存档：截图 + 订单号 + 时间 + 接口返回原文。**截图不带时间戳等于没有**。
4. 出现"设置成功但查不到订单"，按智擎杯的队列延迟纪律处理：**≥30 分钟后复读一次再判**，不当天判死。

|---|---|
| 现象 | `sandbox summary webpay <项目> NodeJS …` 退出非 0：`MESSAGE_RENDER_ERROR:变量 environmentRows 不是合法沙箱摘要行` |
| 根因（已证） | Skill 托管的 jq（`~/.local/bin/jq.exe` 1.7.1）在 Windows 上写 stdout 时把 `\n` 转成 `\r\n`；`sandbox_config.sh` 的 `jq -r` 生成的四行摘要每行尾带 `\r`，renderer 的行正则 `^\| ([^|]+) \| ([^|]+) \|$` 逐行失配 ⇒ 整条消息渲染失败 |
| 证据 | `jq -n -r '"a\nb"' \| od -c` → `a \r \n b \r \n`；`jq --help` 里确有 `-b, --binary` 开关，脚本未使用 |
| 影响 | Skill 流程明文规定"摘要展示失败时不得进入沙箱测试或付款体验，也不得改用 Agent 自写表格"⇒ **沙箱付款入口这一步按流程不能做**，L2 停在这里 |
| 可用修法 | `sandbox_config.sh` 里两处 `jq -r` 改成 `jq -rb`（`-b` 即 jq 的 binary/LF 输出）；本机无第二份 jq，WSL 未装发行版，无干净替代 |

### 9.2 沙箱网关间歇性 502 —— 与请求方法无关，重试即恢复

| 项 | 事实 |
|---|---|
| 现象 | 商户页自动提交 `pageExec(...,'POST')` 生成的表单 → 落在 `502 Bad Gateway`（Tengine，`Server: iopengw-35386.sggz00b.dev.alipay.net`），页面里报的 URL 是 `http://` 而非 `https://` |
| 追查（含一次误判） | 先按"应用内浏览器 POST 特有"处理：同一笔签名的 POST 从 Node `fetch` 发出 200，同一参数的 GET 在浏览器里正常出收银台。**随后同一节点在 `alipay.trade.query`（Node 侧 POST，与浏览器无关）上也返回 502，紧接着原样重试即 200** ⇒ 前后证伪了"方法特有"的解释 |
| 结论 | 沙箱网关 `iopengw-35386` 节点**间歇性** 502，与请求方法、客户端类型都无关；重试即恢复 |
| 对策 | 服务端查询加一次 800 ms 重试（`queryTradeWithRetry`，`pay-demo/server.js:55`）；浏览器提交表单遇 502 时回退再提交，最多 3 次 |
| 副作用 | 探测期间留下 5 笔 `CREATED` 空订单，已在 §6 标注剔除 |
| 未解 | 502 是否绑定特定网关节点、是否与并发量相关，本轮未做统计（对 10 天赛程不构成风险，不追） |
