> **📌 来源（2026-10-25 用户反馈立）**：用户指出「每次我给你反馈之后，你再去核对才发现漏了信息」——
> 复盘归因结论：**"读过"≠"掌握"**。读取是一次性、按需、摘要式的，而事实（平台行为、工具副作用、
> 工作区新增文件、复现基线）会漂移。本协议把"靠记忆"改成"靠核查"，每条核查必须留下证据而非引用记忆。
> **每次复盘的新教训必须落成下面的协议条目或表格行，否则该次复盘不算完成。**

## 触发条件（满足其一就执行全文）

1. 任何新会话开始（智擎杯相关）；
2. 用户说「继续科目一/三/四」或任何恢复性指令；
3. 任何一次提交动作之前；
4. 任何"我基于 XX 记录认为 YY"的判断即将写进交付物之前。

## 第 0 步 · 全量读取 + 状态回显（防旧快照）

- 读：主索引顶部「新 session 先读」指向的**全部**最新交接（≥2 份）+ 两科**分数复盘日志全文** +
  本文件两张表。**通读，不是关键词检索。**
- 读完向用户回显 ≤6 行「本次工作状态摘要」（两科当前版本线 / 平台最近行为 / 本次计划动哪些面），
  **让用户有机会在动手前纠正**。回显不是走形式：摘要里每个数字都必须来自本次读到的文件。

## 第 1 步 · 工作区增量盘点（防"用户放了新东西我不知道"）

- 按 mtime 扫 `D:\智擎杯大赛\`（两层）48h 内新增/修改的文件，与台账/Obsidian 记录比对。
- 教训来源：10-24 官方新版 `案例集.zip` 出现在工作区 3 小时后才被后台任务偶然发现。

## 第 2 步 · 平台行为表核对（防"平台漂移"）

- 本次会接触哪些平台面（详情/数据页/提交页/榜单/FAQ/API），逐面查下表最近一次观察值；
- **任何"上次是这样"的面，本次活动要么实测再依赖，要么标注【未复核，勿依赖】**。
- 平台已证会漂移的事实：匿名 API 10-25 起 e40104；`fileSize` 字段两次证伪；错误状态是通用兜底。

## 第 3 步 · 工具副作用核对（防"工具会自己做事"）

| 工具 | 已知副作用 / 依赖 | 对策 |
|---|---|---|
| `组装提交.py` | **无条件给两组写回 `rankings` 键**（v2「其他错误」嫌疑） | 组装后剥离再过闸；以后修好组装器前不得省略 |
| `render.save()` | `optimize=True`——字节与裸 `img.save` 不同 | 任何逐字节比对必须同参数 |
| 24 项门禁 E1 | 依赖 `D:\tmp\zqb\repro-a50`（上次复跑的落盘） | 改版后**先刷新该目录再跑门禁**，否则假 FAIL 误导归因 |
| `eval/ocr_readback.py` | rapidocr 1.x 不收 PIL 要 ndarray；stdout 重定向下有缓冲（跑完前日志为空属正常） | — |
| win32 heredoc | `\\` 转义会被吃掉（两次事故：`\n` 成真换行、正则断言失败） | 文件手术一律用 Edit 工具，不用 heredoc |
| 科目一 rerank 开关 | 只有 `rscore_norm` 进 `pick_for_section` 排序键才生效 | 任何"优化开关"必须有输出 diff 或分数证据 |
| sentencepiece/opus-mt | 非 ASCII 路径崩溃 | 镜像 `D:\tmp\zqb\mt-ascii` |
| 主题/时间/地点抽取 | 历史标记词勿放"历史"单词（demo2 误杀）；动词黑名单需随新语料扩充 | 每次改完跑 6 真值 + 114 项 + 抽样对回原文 |

## 第 4 步 · 改动生效证明（防"写了=生效"）

- 每个"优化/开关/修复"必须有**二选一**的证据才算存在：① 输出 diff（改了哪些行/字段/像素）；
  ② 评测分数变化。**没有证据 = 未生效，按未生效汇报**（rerank 钩子无效的教训）。
- 任何根因结论标置信度：【定论】需双重证据；【假设】必须同时写出"下一步什么观测能证伪它"。

## 第 5 步 · 提交前指纹四件套

- md5 / 字节数 / 条目清单（A 榜 50 张；科目一 JSON 结构）/**与上一版的 diff 摘要**（哪些事件哪些字段变了）。
- 尺寸类新变量（包体积、单图大小）必须与"已知能过/已知失败"的历史版本对照后写入平台行为表。
