## 五、踩坑记录（可复用）

1. **Chrome 出 PDF 会把 Noto Sans SC 可变字体转成 Type3，中文全部丢失**（132 个 Type3 过程，只剩 Segoe UI 嵌进去）。
   → 处方：CJK 用**静态 TTC/TTF**，出 PDF 后必须验 `Type3 = 0` 且 `可抽取字符数 > 0`。
2. **Chrome 写中文路径会报"拒绝访问 (0x5)"**。→ 先渲染到 `%TEMP%` 纯英文目录，再拷进中文交付路径。
3. **SVG 里中文字体不能只靠根节点 `font-family`**：Chrome 渲染和 Illustrator 导入都会丢。
   → 处方：每个 `<text>` 显式带 `font-family`（本生成器用 `T()` 统一注入）。
4. **`text-rendering="geometricPrecision"` 对本图无影响**（A/B 像素对比过），已移除。
5. 字体曾误判为 SimHei（靠像素差自证：mean|Δ| 3.529/2.63% vs 21.355/13.67%），**别凭观感改字体**。
6. **本机字体实况**：`NotoSansSC-VF.ttf` 是可变字体（禁用）；可用静态件 = `msyh.ttc/msyhbd.ttc`、`simsun.ttc`、`STSONG.TTF`（PDF 内显示为 STSong / NSimSun）、`consola.ttf`、`segoeui.ttf`。本机**没有** Noto Serif SC / 思源宋体，中文衬线只能靠宋体 / STSong。
7. **版面纵向自检**：生成器里有三处 `assert`（页脚落在版心底线 1728、收口面板不与页脚重叠、落地块不与收口面板重叠）。改字号/块高后若 assert 触发，说明纵向预算被吃穿，必须重排而不是硬压。

## 八、尺寸适配结论（回应"可拉伸调整"）

- **2:3 竖版原生可等比缩放**到 90×135 / 120×180 / 80×120 cm，清晰度无损（矢量）。
- 若组委会给的是**易拉宝 80×200cm（1:2.5）**：**不要非等比拉伸**（字会扁）。正确做法二选一：① 整幅居中、上下留 10cm 底色；② 在 SVG 里拉大**三段容器之间的段间距**（三段等距堆叠，垂直拉伸不影响阅读，横向不要动）——这张图当初就是按"垂直可拉"设计的。
- 出血：喷绘/写真 3–5cm，KT 板 2–3cm，本图四周留白 72mm，直接加边即可。
- 底色：整幅暖浅灰 `#f5f4f2`（**刻意不用纯白**）。若场地/印厂要求纯白，把 SVG 最外层那个 `fill="#f5f4f2"` 的矩形改成 `#ffffff` 再重出 PDF 即可。
