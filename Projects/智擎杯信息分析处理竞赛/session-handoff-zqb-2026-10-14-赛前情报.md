### 5. 昇腾 910B 适配专项调研（本 session 新增）

针对第三节识别的 #1 技术风险做了专项调研，产出《昇腾910B适配技术备忘》。**核心纠偏**：

> 网上 2024 年及更早的说法"PyPI 没有 aarch64 wheel、必须源码编译 torch_npu"**已经过时**。2026-10-14 逐个实测 PyPI wheel 标签：`torch-npu 2.12.0.post2`、`mindiesd 3.1.0`、`vllm 0.31.0`、`triton-ascend 3.2.0` **均有 aarch64 wheel**。

关键结论：
- **推荐栈**：vLLM-Ascend v0.23.0.post1 + CANN 9.1.0 + torch 2.10.0 + torch_npu 2.10.0.post4 + Python 3.11/3.12
- **科目三文生图**：首选 `mindiesd`（MindIE-SD）；离线最稳用 vLLM-Omni + MindIE-SD 官方 aarch64 镜像（`docker save` 搬走）；SDXL 官方权重+脚本在魔乐社区 `modelers.cn/models/MindIE/stable-diffusion-xl`
- **必须避坑**：`xformers` / `flash-attn` / `deepspeed` / `paddlepaddle` / `llama-cpp-python` 在 aarch64 **无 wheel 或需编译**；MindSpore 本体 aarch64 走私有索引
- **容器权限坑**：`--device=/dev/davinciN:rwm` 权限**必须 `rwm`**，用 `rw`/`r` 会导致 `torch.npu.set_device()` 失败
- **x86 开发机验证手段**：`docker buildx build --platform linux/arm64` + QEMU 跑 import 冒烟（能验证依赖/wheel，验证不了 NPU 与性能）
- **显存锚点**：8×910B（512GB）稳妥跑 **7B–72B dense**；70B 官方要求 8 卡；671B MoE 需 16 卡（两台机）
- **两周适配路线**（备忘第九章）：10-15 锁版本 → 10-17 在 x86 跑通设备无关版 → 10-20 真机点亮 → 10-25 打包离线包 → 10-27 断网演练

⚠️ **真机问题已澄清（2026-10-14 用户确认）**：用户**拿不到昇腾真机**，但**可按需租云服务器**。结论是——**这不构成参赛障碍**，详见 §五 的「重要认知修正」。

## 六、本 session 使用的方法/工具（可复用）

- **Vue SPA 站点情报采集**：WebFetch 失效 → 必须走 `browser-use:control-browser` 渲染 + `domSnapshot()` 全文读取。本项目官网即属此类。
- **二维码验证**：`cv2.QRCodeDetector().detectAndDecode()` 二进制解码，不靠肉眼比对；注意 Windows 下 cv2 读中文文件名会失败，需先复制成 ASCII 文件名。
- **docx/pptx/PDF 批量提取**：`python-docx` / `python-pptx` / `PyMuPDF(fitz)`；Windows Git Bash 下 stdout 中文会乱码，**必须写 UTF-8 文件再用 Read 工具读**。
- **GitHub 资源检索（本 session 新增）**：本机**无 `gh` CLI** → 改用 **GitHub Search API 经 WebFetch**：
  `https://api.github.com/search/repositories?q=<关键词>&sort=stars&order=desc&per_page=15`
  → 返回**真实** repo 名/URL/star 数，**避免编造地址**。⚠️ **未认证限流约 10 次/分钟，会 403 `rate limit exceeded`**；中文关键词需 URL-encode；`in:name,description` 可提高精度。
- **Obsidian 资产检索**：委派 Explore 子代理跨 10+ 项目文件提炼能力画像，避免主上下文被长文档淹没。
- **技术调研**：委派 general-purpose 子代理做 2026 时效性核查（网上大量 2024 教程已过时），要求逐条标注来源链接与抓取日期。
