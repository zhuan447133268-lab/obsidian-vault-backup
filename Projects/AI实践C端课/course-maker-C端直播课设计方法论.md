# course-maker C端直播课设计方法论

> 本方法论来自 [[course-maker-skill-refined|course-maker skill]]，用于把任何知识/工具/经验变成一门面向 C 端用户的直播变现课。
> GitHub 仓库：https://github.com/zhuan447133268-lab/course-make-skill

---

## 一、核心定位

不是做「知识课」，而是做「 transformation 产品」。

学员买的不是操作步骤，而是：
- 一个能解决问题的**方法**
- 一个值得自称的**身份**
- 一套可以复用的**系统**

---

## 二、三种课程模式

| 模式 | 付费决策者 | 节奏特点 | 核心目标 |
|---|---|---|---|
| 大众线上录播课 | 个人 | 可自主控制 | 学完即可 |
| **C 端直播变现课** | **个人** | **每 15 分钟一个爽点** | **意犹未尽，续报下一期** |
| 企业内训课 | 公司 | 稳扎稳打 | 解决工作问题 |

本项目聚焦 **C 端直播变现课**。

---

## 三、C 端钩子公式

```
C 端钩子 = 具体痛点场景 + 身份转变承诺 + 稀缺方法暗示
```

**示例**：
- 痛点：「你是不是收藏了 100 个提示词，真到用时还是不知道选哪个？」
- 方法：「这节课不教你更多提示词，而是教你一套『需求 → 拆解 → 匹配工具 → 验证』的 AI 应用决策流。」
- 身份：「上完你会从『追新工具的人』变成『能判断什么场景该用什么 AI 的人』。」

## 四、7 步工作流

### Step 1：锚定受众与商业定位
- 确认课程模式（三选一）
- 确认受众画像、基础、痛点、付费能力
- 确认售卖形式、时长、定价锚点

### Step 2：提炼灵魂一问 / C 端钩子
- 列出 3 个替代方案
- 用 C 端钩子公式写出一句话钩子
- 验证：对方听完愿意问「多少钱？什么时候开课？」

### Step 3：设计闭环结构与直播节奏
- 按「起点 → 实操 → 迁移 → 拔高 → 带走」画骨架
- 70%+ 时间给动手
- 系列课必须埋开放环

**90 分钟直播节奏模板**：

| 时间 | 环节 | 目标 |
|---|---|---|
| 0–5min | 热场 + 上节课成果 | 建立信任 |
| 5–15min | 今天唯一大承诺 | 让学员知道能得到什么 |
| 15–70min | 讲→做→讲→做 | 每 15 分钟一个爽点 |
| 70–80min | 迁移练习 | 证明方法可复用 |
| 80–85min | 总结最重要认知 | 强化记忆锚点 |
| 85–90min | 预告下节课 + 作业 | 制造意犹未尽 |

### Step 4：提取核心干货
每门课必须提炼 3–5 个核心干货，至少覆盖：
1. **决策框架** — 什么时候用什么
2. **排错清单** — 出问题先查什么
3. **审美标准** — 什么是好的 AI 输出
4. **提示词模板** — 可直接复用
5. **误区纠正** — 最常见的错误认知

### Step 5：编写提示词模板集
- 3–5 个模板
- 每个模板含：触发语 + 角色 + 输入 + 输出 + 检查点 + **背后原理**
- 5 分钟内能让新手出成果

### Step 6：产出样例与素材包
- Demo 版（3 页）+ 正式版 + PDF
- 样例素材包 README 明确：「优先用你自己的素材」

### Step 7：设计 C 端 Offer 与转化路径
- 课程名（transformation 导向）
- 正价 + 早鸟价 + 老学员价
- Bonuses（资料包、社群、加餐、点评）
- 转化路径：试听 → 低价 → 正价 → 进阶/社群
- 风险逆转：退款 / 返现 / 重修

## 五、直播课「意犹未尽」设计

### 开放环类型
1. **问题开放环**：这节课解决 A，B 更复杂，下节课讲。
2. **案例开放环**：今天讲普通案例，下节课讲「翻车救回来」的真实案例。
3. **工具开放环**：今天用基础功能，下节课解锁高级组合技。
4. **身份开放环**：这节课你是初学者，下节课你能教别人。

### 结尾公式
```
今天最重要的 1 个认知 + 你现在已经能做出 X + 下节课我们将解决 Y
```

## 六、抗过时设计

AI 工具迭代快，课程保质期取决于内容比例：

- **界面截图 ≤ 20%**
- **决策框架 ≥ 40%**
- **排错清单 ≥ 20%**
- **审美/质量标准 ≥ 20%**

---

## 七、课件制作工具

- **默认**：`bento-deck` skill → `.bento.html`
- **PPTX / 交材料**：`ppt-master` skill
- **不直接手写 HTML/CSS**

---

## 八、交付物清单

每门课必须产出 6 类文件：

1. **课程方案.md** — 受众、钩子、结构、时长、核心卖点、Offer
2. **提示词模板集.md** — 3–5 个可复制模板
3. **教用课件** — bento / PPT，按「讲→做」设计
4. **样例成品** — demo + 正式版 + PDF
5. **样例素材包** — README + 素材 + 空白采集清单
6. **结课自查与迁移卡** — 带走清单 + 迁移填空 + 设计系统卡

---

## 九、持续优化机制

每次课程定稿后执行：

1. **提取**：把方案取舍、反馈、踩坑写入 `references/cases/<课程名>.md`
2. **反哺**：新原则写进 `methodology.md`，流程问题调整 `SKILL.md`
3. **校验**：运行 `package_skill.py`
4. **推送**：`git commit` + `git push`
