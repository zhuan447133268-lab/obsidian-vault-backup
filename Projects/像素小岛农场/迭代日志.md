## 第 1 轮 · 项目骨架

- **诉求**：创建一个 Vite + TypeScript + Phaser 3 的项目。
- **做法**：Vite 起项目，`main.ts` 配 Phaser，`BootScene` 负责生成贴图后切主场景。
- **留下的坑**：`erasableSyntaxOnly` 下不能用构造函数参数属性，字段要单独声明（后面一直遵守这条）。

## 第 2 轮 · 复刻文章 ①《搭世界》

**诉求**：按公众号文章做一座 Sprout Lands 风格的小岛农场。

**做了什么**

**验证**：真实浏览器里走位、锄地、播种、收获、捡蛋、挤奶逐项跑通。

## 第 3 轮 · 铺满整个窗口

- **原话**："游戏画面怎么还有个蓝色的背景呢，不是整个画面就是游戏画面？"
- **判断**：不是贴图问题，是缩放模式留了等比黑边（当时 `FIT` + 固定 480×270）。
- **改动**：改成等比铺满、不留最大尺寸限制，画布撑满窗口。
- **后续**：这一轮其实埋下了第 6 轮的模糊问题 —— 铺满靠的是"整块画布拉伸"。

## 第 4 轮 · 复刻文章 ②

**诉求**：`https://mp.weixin.qq.com/s/op3n8UGEOwJmad4I3QmKcA` 继续。
文章范围：滤镜层（四季/晨昏/天气）、土地层（autotile，挖一小片田）、地图层（水、岛的底座、岛的泥土、深浅草皮）、还有 E 键喝牛奶。

**做了什么**

| 主题 | 实现 |
| --- | --- |
| autotile | 新增 `art/autotile.ts`，`上1 下2 左4 右8` → 0–15 号边角砖；苗床看田的矩形，翻过的土看邻格 |
| 地图层 | 岛底座（沙滩朝下露泥土断面）、岸线泡沫（离陆 3px 内）、草皮散点过渡 |
| 滤镜层 | 天色关键帧表、天气粒子共用一套配置、闪电白屏 + 电弧 + 120ms 再白 |
| 挤牛奶 | 并入统一交互，进背包，14 秒冷却提示「牛在休息」 |

**这一轮修掉的真 bug**

1. 竖栅栏碰撞体只有下半截 → 角色能从两根横栏之间钻出去（改成整根 16px）。

1/2/3/4 逐个切天气截图；冻结 tween 抓到闪电帧。

## 第 6 轮 · 大屏清晰度重构

- **原话**："大屏打开后，像素风格看不清楚字，也看不清楚角色。"
- **判断**：不是审美问题，是分辨率问题 —— 画布固定 480×270 被浏览器拉伸 4–8 倍，而且倍数不是整数。
- **改动（三层）**：
  1. 画布 = 窗口 CSS 尺寸 × 设备像素比（上限 2），`Scale.NONE` 自己接管；
  2. HUD 字号/边距/面板统一乘 `画布高 / 270`，按真实像素渲染；
  3. 相机倍数取整（`min(宽/240, 高/135) × 手动倍数`），滚轮 / `-` `=` 可调。
  顺带让 `Scale.Events.RESIZE` 触发 HUD 重排、天空层改尺寸、雨水范围重铺、相机重算。
- **验证**：
  - 1280×720 / 2560×1440 / 2 倍屏三档截图，字与像素边缘都锐利；
  - 运行中把画布从 1280 切到 2560：HUD 字号 27→53px、遮罩 1280×720→2560×1440、相机 6→13，全部即时生效；
  - 回归：锄地 → 播种链路正常。
  - 另：重新打包离线单文件，仍是同一路径。

## 第 8 轮 · 农场经营（把钱这一环接上）

- **原话**："后续我希望这个农夫可以有更多的活动空间，比如可以养动物，可以种植农作物和收获农作物，可以做商人去卖农作物，卖的钱再买种子，这样的游戏。就是一个内容丰富的农场游戏。可以实现吗？"
- **判断**：能，而且不用推翻任何东西 —— 上一版已经有"种 → 收"，缺的是**钱**和"为什么还要再种一轮"。
  所以这轮不是加装饰，是把原本断开的链路接成环：
  `买种子 → 种 → 收 → 卖 → 更多种子 / 更多鸡`。上一版"背包只记四个数字、不做经济"的判断，这轮被这条需求推翻了。

**做了什么**

| 主题 | 改动 |
| --- | --- |
| 农田扩容 | 4×3 → **6×4（24 格）**；先复算高度场确认 20–25 列 × 12–15 行全是草地，围栏随之扩到 19–26 × 11–16，门挪到 21–22 列，小路终点南移一格 |
| 四种作物 | 新增 `economy.ts`：草莓 4/9/7s（春夏）、番茄 6/16/11s（春夏）、玉米 10/28/15s（夏秋）、南瓜 14/46/22s（秋），开局 24 金 + 草莓种 3 + 番茄种 2 |
| 三阶段生长 | 幼苗 → 半高（进度 0.45 换贴图）→ 成熟（结果 + 弹一下），每档都有对应贴图；错季、冬天、没种子都给出明确文案 |
| 种子摊 | 农田北边一个摊位，`E` 开面板，`1`–`5` 买（4 种种子 + 一只鸡 45 金）；**只有钱不够才置灰**，每行行尾写 `· 春夏` / `· 夏秋` / `· 秋`，反季的种子照样能囤 |
| 收购箱 | 围栏门口一个木箱，`E` 一次性卖光背包，飘字报总价 |
| 动物经济 | 鸡蛋 8 金、牛奶 20 金；蛋在地上最多囤 `3 + 鸡数` 个 |
| HUD | 左上加金币与当前种子，右上收成改成六格（草莓/番茄/玉米/南瓜/蛋/奶），商店面板单独一块 |
| 长按 E | 320ms 一步连续操作，`interact()` 返回 `false` 就停 —— 锄完接着种、成熟了连着收，但不会把金币点成负数 |
| 存档 | `save.ts`：localStorage 存天数/金币/种子/背包/选中种子/鸡数/每格田的状态与进度，8 秒一次 + 过天 + 每次买卖 + 关页面；`0` 键清档 |

**这一轮修掉的真 bug**

1. 商店面板变成一个盖住半个屏幕的黑方块 → 底板与遮罩默认 origin 是 0.5，却按左上角坐标摆，`setOrigin(0)` 才对。
2. 商店行文字参差不齐 → 中文用 `padStart` 对齐是错的（一个汉字两个字符宽也不算），改成每行拆「名字 / 价格右对齐 / 备注」三个 Text 固定 x。
3. 右上背包把「玉米 0」裁掉了 → 面板加宽、字号降到 8u、改左对齐。
4. 1280 宽下 `[E] 提示` 压住左下操作提示 → 提示与飘字整体上移一行，叠三层也不重叠。
5. 树冠挡住半个摊位 → `reserved` 支持 clearance 半径（摊位 56、木箱 44），树只在这个圈外撒。

**验证**

- 生产包 + 真实键盘事件跑完整闭环：24 金买草莓（→20）→ 长按 E 锄地/播种/浇水 → 7 秒成熟 → 收获进背包 → 木箱卖出（20 → 29）→ 刷新页面，金币、种子、田的状态全部还在。
- 重新打包离线单文件，用 `file://` 打开复跑一遍：开局 24 金 / 24 格田 / localStorage 可用、买种子 24→20、田变成 `seeded + watered`、控制台零异常。
- **终版复跑（离线单文件，清空 profile）**：摊位买 2 包草莓（24 → 16，库存 1 → 3，飘字「买了 1 颗草莓种子 · -4 金」）→ 两格锄地/播种/浇水 → 7.0 秒后两格 `grown + watered` → 连收获，背包草莓×2 → 收购箱一次卖出 `+18 金`（16 → 34）→ 刷新后金币仍是 34、两格田还在。全流程 `errors: []`。
- 截图存档：整块农田、商店面板（含季节提示）、三个生长阶段、离线版复跑、卖货飘字。

**学到的两条**

1. 长按交互必须给"能不能继续"的信号，否则批量操作一定会在资源不足时把数值点穿。
2. 数值和状态机分开（价格全在 `economy.ts`），改平衡时不用碰场景代码 —— 这一轮加数值几乎没动 `FarmPlot` 的逻辑分支。

## 第 9 轮 · 像素感与面板首行（2026-11-06）

- **原话**："如果想把这个游戏的像素感减少一些，不要看起来那么模糊，有没有更好的办法？另外，长方形框里面的文字，都太靠近最上面的边框，导致第一行文字显示都不全，包括买种植时，弹出来的长方形框里面的文字也是一样。"
- **判断**：两件事，一句"再加分辨率"都解决不了。
  1. 模糊的根不是画布分辨率（第 6 轮已经修过），是**相机倍数的公式**：`min(画布宽/240, 画布高/135)` 让窗口一大就把 16px 瓦片放到 5 倍以上，
     草地的细节（草茬、花、碎石）全被放大成色块 —— 放大得越多，看起来越"糊"，也越像马赛克膏药。
     要的是"**画得更小、更清楚**"，不是"继续放大"。
  2. 首行被裁是 **Phaser Text 的纹理高度按行高紧算**，中文的头顶正好顶在纹理第 0 行，渲染时就被切掉 1–2px；
     面板高度当时又是写死的（`44u` / `52u`），字号一变大文字就往上顶到边框。

**做了什么**

| 主题 | 改动 |
| --- | --- |
| 缩放公式 | 换成 `WORLD_SCALE(3) × 设备像素比 + zoomStep`，再压一条 `fill = ceil(画布宽 / 世界宽)` 的下限（镜头再远也不露出岛外）；仍取整 |
| 缩放档位 | `zoomStep` 是整数档（-2 … +6），滚轮一次一档，永远不会出现"有的像素占 5 点、有的占 6 点" |
| HUD 基准 | `HUD_H` 从 270 改到 **360**：镜头拉远后画面里的东西变小了，面板也得小一档，否则比农田还大 |
| 文字留白 | 所有面板文字（状态栏 / 背包 / 商店标题 / 每一行 / 页脚）统一 `setPadding(0, 4u)`，给字纹理留出头顶空间 |
| 面板高度 | 不再写死，`fitPanels()` 按 `text.height + 8u` 反算，换字号也不会压到第一行 |

**根因是怎么确认的（不靠肉眼）**

把 `Text` 底下那张 canvas 抠出来，逐行扫 alpha，找墨迹的第一行：

| 状态 | 字号 | 纹理高 | 墨迹起始行 |
| --- | --- | --- | --- |
| 修之前 | 27px | 54 | **0**（贴在第 0 行，说明头顶已经被切） |
| 加 `setPadding(0, 6)` | 27px | 56 | 4 |

2 倍屏复测（`DPR = 2`）：状态栏墨迹从第 12 行进（pad 16）、背包 13、商店标题 2（pad 8）—— 全部 > 0，首行不再缺。

**验证**

- 1258×720、DPR 1：相机倍数 **5 → 3**，世界视野从 252×144 变成约 419×240（多了 66% 的地看得见），瓦片在屏幕上是 48px，农夫 96px 高。
- DPR 2 复测：倍数 6（`3 × 2`），CSS 相对大小与 DPR 1 完全一致 —— 高分屏不会"东西变小"。
- 面板几何随文字走：状态栏 196u 宽、高度由文字算出，商店面板 587×259（2 倍屏下），标题与四行都在框内。
- 离线单文件重打包（1.19 MB）后 `file://` 全流程复跑：`errors: []`，开局 24 金 / 倍数 3 / 种子 3 →
  种两格 → 收 2 颗草莓 → 收购箱卖 18 金（24 → 42）→ 开摊买 1 包（42 → 38，库存回到 1）。
- 截图：默认视角、状态栏裁切对比、商店首行、滚轮拉近/推远、离线版全流程。

**学到的两条**

1. "像素感太重 / 太糊"通常不是分辨率不够，而是**放大倍数太大**。像素画的清晰度靠"每个世界像素占整数个屏幕像素"，不靠把画布画得更大。
2. Phaser 的 Text 是**贴图**，不是排版引擎：中文（以及任何有上伸部的字形）都可能被自己的纹理切掉顶部。
   凡是"字挨着框"的地方，要么给 `setPadding`，要么把框按 `text.height` 反算 —— 后者更保险，改了字号也不会回归。

## 第 10 轮 · 画面为什么"突然变暗"（2026-11-06）

- **原话**："另外，还有在玩游戏的时候，画面会突然变暗，这是怎么回事。"
- **判断**：不是 bug，是两个没控制好的节奏叠在一起，让人以为出了事。
  1. **一天只有 120 秒 = 一个游戏小时 5 秒**。正午到天黑只要二十秒，
     玩家正在田里连收几格，抬头一看天已经黑了一半 —— 主观上就是"突然变暗"。
  2. **天气只在换天那一刻重掷**（每天 0 点）。抽到暴雨时，那层蓝色遮罩是 `setFillStyle` 一帧换掉的：
     0 → 0.24 的不透明度在 16 毫秒里完成，整块屏幕"啪"地暗一下。
  3. 顺带发现：光照遮罩的重设阈值是按"小时差 0.03"判断的，配合新的时钟会把夜色分成大格跳。

**先量清楚再改**（同一套状态探针，只读 `lighting.fillAlpha` / `weatherTint.fillAlpha`）：

| 指标 | 修之前 | 修之后 |
| --- | --- | --- |
| 一个游戏小时 | **5.0 秒** | **10.0 秒**（一天 4 分钟） |
| 16:30 → 21:00 的遮罩 | 0.05 → 0.50，用了 **20 秒** | 0.07 → 0.39，用了 **45 秒** |
| 单次采样最大跳变 | 明显成段 | **0.009**（每 0.7 秒采样一次） |
| 换天切到暴雨 | 0 → 0.24，**1 帧** | 0 → 0.24，**1.6 秒淡入** |
| 深夜最暗 | 0.74（田几乎看不清） | 0.62（能看清田，仍是夜） |

**做了什么**

| 主题 | 改动 |
| --- | --- |
| 一天的长度 | `DAY_SECONDS` 120 → **240**（一小时 10 秒）：黄昏铺满 50 秒，一季 3 天 = 12 分钟 |
| 关键帧 | 10 档加密到 **14 档**，相邻两档只差 0.06–0.09 的不透明度；深夜封顶 0.62 |
| 夜色重设 | 从"小时差 0.03"改成"透明度差 0.002"，避免时钟变慢后一次跳一大格 |
| 天气转场 | 颜色立刻换、不透明度走 1.6 秒 `Sine.easeInOut` tween，从**当前值**补间到目标值 |
| 初始化 | 遮罩出生时是透明的（原来固定在 0.62），第一帧就由真实时辰接管，不会闪一下暗 |

**验证**

- 生产包逐帧采样：`hourPerSecond = 0.0997`，一天 **4.01 分钟**；黄昏 16:30 → 21:00 共 44.9 秒，单次最大跳变 0.009。
- 天气淡入：在页面里用 rAF 连采 132 帧，0 → 0.24 走完约 1.5 秒，无单帧跳变。
- 跨天（23:59 → 00:00）：遮罩 0.618 → 0.618，不闪。
- 离线单文件重打包（1.19 MB）+ `file://` 复跑：`errors: []`，18:03 遮罩 0.152、21:04 遮罩 0.392；
  玩法回归照旧（种两格 → 收 2 颗 → 卖 18 金 → 开摊，面板 587×259）。
- 截图：19:30 与 23:00 的前后对比、21:00 的黄昏离线版。

**学到的两条**

1. 昼夜这类"氛围系统"的**速度本身就是体验**。同一套颜色，5 秒一小时就是"闪黑"，10 秒一小时就是"天黑了"。
2. 凡是"换状态就整屏变色"的地方，都要问一句"这一帧会不会让玩家以为出 bug"。给一个 1.5 秒的 tween，成本几乎为零。

## 第 11 轮 · 让每位老师当堂带走一个 demo（2026-11-06）

- **原话**："但是，培训课相当于就是实操课，要求培训的学员，当堂课就要出一个游戏demo，课后学员们再去丰富自己的游戏"
- **判断**：这一句把上一版培训方案的交付物判掉了 —— 原来的落点是"改一处参数、说清为什么"，那是"体验过"；
  用户要的是"**交付了**"。差别很实在：下课的时候，每个人手上得有一个能双击打开、别人能验证的东西。
  2 小时教不会任何人从零写游戏，但"改数据 → 看到变化 → 交付一个文件"完全做得到 ——
  前提是游戏本身要能被别人改。**这一轮改的不是玩法，是"可改性"**。
- **三条保命设计**（课堂上一定会踩到的三个坑，全部在代码层解决）：
  1. 写坏配置不能白屏。语法错时浏览器会丢掉那一段 `<script>`，全局就没有配置对象 → 自动走默认值；
     类型写错（数字写成文字）只回退那一项，并在开场提示"配置有 N 处没看懂"。
  2. 改配置必须当场生效。存档里带**配置指纹**，配置一变老存档自动作废 ——
     否则"我改了金币怎么还是 24"会成为全场最高频提问。
  3. 成品和模板必须是同一条代码路径。没有配置块时 `isCustom = false`，标题与文案保持原样 ——
     不给正式版本分叉出第二套逻辑。

**做了什么**

| 主题 | 改动 |
| --- | --- |
| 配置层 | 新增 `config.ts`：读 `window.__FARM_CONFIG__`、逐项校验与夹范围（`daySeconds` 60–1800 等）、把错误翻成人话 |
| 可改项 | 游戏名字 / 开局金币 / 走路速度 / 一天多少秒 / 四种作物的名字·种子价·卖价·生长秒数 |
| 规则开关 | `rules.rainWaters`（下雨自动浇水）、`rules.nightNoSow`（天黑 19 点后不能播种）—— 不写逻辑就能多出一条规则 |
| 接线 | `economy.CROPS` 由 `CFG.crops` + 写死的季节拼成；`Player` 用 `CFG.playerSpeed`；`TimeSystem` 用 `CFG.daySeconds`；`FarmPlot` 检查夜间规则 |
| 存档 | `SaveData.config` 存配置指纹，指纹对不上就 `clearSave()` 开新局 |
| 打包 | `build:offline` 一次出两个文件：成品 `像素小岛-离线版.html` 与 `像素小岛-课堂模板.html`（模板在 `<head>` 里多一段带注释的配置块） |
| 课堂材料 | 重写 `培训方案-2小时…md`（变成 demo-first）+ 新增 `学员任务卡-A4.md`（三档任务 / 验收公式 / 互测表 / 常见问题 / 课后清单） |

**验证**（全部在真实 Chrome 里跑，成品与模板分开验）

- 模板 22 项断言全过：默认值不变（24 金 / 80 速度 / 0.1 小时每秒）；改配置全生效
  （标题变、99 金、走路 160、一天 60 秒、草莓改叫"金草莓"且 2 秒熟、南瓜改叫"大南瓜"）；
  天黑拒绝播种（21:13 按 E → 状态仍是 `tilled`，飘字"天黑看不清种子"）；
  关掉自动浇水后雨天不浇水就一直不发芽。
- 写坏配置：5 处错误（标题写成数字、金币写成"很多"、`daySeconds: 5`、种子价写成字符、规则写成字符串）
  → 游戏照常启动，逐项回退并把 5 秒夹到 60 秒，控制台有明细。
- 成品回归：标题、24 金、240 秒、3 倍缩放、7 秒成熟收 1 颗 —— 与改动前完全一致。
- 存档：同一份文件重开能读回 40 金；换成开局 99 金的配置后老存档被清掉，直接新局。

**学到的两条**

1. "让别人能改"和"自己能写"是两件不同的工程活。前者要做的是**容错**（写坏不许崩）、**入口**（改哪一行）、
   **即时反馈**（改完立刻看见），而不是把代码整理得更漂亮。
2. 课堂产品的第一敌人不是难度，是**"我改了怎么没反应"**。这类问题一次就能击穿信任，
   所以它必须在代码层被消灭（配置指纹），不能写进 FAQ 里让人自己查。

## 第 12 轮 · 从零做出一个游戏：90 分钟中小学版（2026-11-06）

**诉求**

> "这次培训暂定是 90 分钟，参与的老师主要是小学和初中的老师……但是我们要把这次我们做这个游戏的过程拆分成阶段，
> 帮助老师们跟 AI 协作，一起来做出来。让老师感受到做游戏的思路的同时，也能借用 AI Agent 把游戏思路做出来。"
> 追加三条：**纯从 0 开始**（不是发模板改数）；**统一像素农场**；老师**只用过聊天、没改过代码**。

**判断**

第 11 轮那套（发模板、改配置）解决的是"人人有 demo"，但老师改的是**别人做好的游戏**，
感受不到"一个游戏是怎么长起来的"。用户这次要的正是后者，所以方案必须换成从零分阶段建。
90 分钟从零做，唯一成立的路径是**把规模压到 1/10**：一块草地、一个方块小人、三块田、一种作物、一条规则，
全程单文件 Canvas，不引框架、不装任何东西。

**做了什么**

| 主题 | 改动 |
| --- | --- |
| 阶段切分 | 按我们自己的开发顺序切成五段：世界 → 动作 → 循环 → 规则 → 手感；每段只让 AI 做一件**能看见**的事；其中"循环"拆成 ③-A 闭环 + ③-B 种子经济两步 |
| 协作方法 | 四段式提示词（现在 / 这一版只加 / 不要动 / 怎么算成功）＋ 三步协作（定位 → 小步改 → 验收）＋ 翻车三步 |
| 硬节点 | 24′ 能走 / 38′ 能站上田 / 51′ 完整闭环 / **59′ 能自己买种继续种** / 71′ 自己的规则可见 / 79′ 文件可双击 |
| 循环闭合 | 开局 6 金币 + 2 颗种子，播种消耗 1 颗，第 4 列第 5 行一个种子摊（3 金币 / 颗）——金币有了出口，"投入 → 等待 → 回报 → 再投入"才成环 |
| 规则三选一 | 浇水（默认、最省时）/ 天黑 40 秒一轮 / 连收 8 秒内第 3 次翻倍 —— 这是"我的游戏"和"AI 的游戏"的分界线 |
| 讲师保底版 | `我的农场-保底版.html`：单文件 Canvas，能走、能种、能买种、能收，三条规则切一行常量就换；开场演示"90 分钟后你手上的东西"+ 救场 |
| 课堂材料 | `培训方案-90分钟-中小学-从零做像素农场.md` + `学员任务卡-A4-90分钟-从零版.md`（五张可直接复制的提示词卡） |
| 课后 | 三条路线：接水果（小学）/ 扫雷打地雷（初中）/ 闯关答题（最适合带回课堂） |

**验证**（真实 Chrome + CDP，模拟真实按键，22 条断言全过）

- 走路：走到指定格子（用读状态纠偏，不靠按键时长）；边界钳制不出界。
- 闭环：荒田 → 翻土 → 播种 → 浇水 → 3 秒出苗 → 3 秒成熟 → 收获 +5 → 田回到翻土。
- 种子经济：开局 6 金币 / 2 颗种子；播一次种子减 1；0 颗时播种被拒；种子摊 3 金币买 1 颗；钱不够（2 < 3）被拒。
- 浇水规则：不浇水等 4 秒仍是种子；浇水后 3 秒出苗。
- 天黑规则：24 秒入夜，按 E 被拒绝，种子不扣、田停在翻土。
- 连收规则：6 + 5 + 5 + 10 = 26，第三次翻倍。
- 截图 101–108 存档在 `04-过程截图与验收/screenshots/`（含归档路径自检 107）。

**学到的三条**

1. **"从零"和"人人出 demo"不冲突，冲突的是"从零做一个像样的游戏"。** 把规模压到十分之一，
   五个阶段各自都能在 10 分钟内看到结果，"从零"就成立了。规模是唯一要妥协的东西，流程不用妥协。
2. **教 AI 协作，必须让每一步都有"可看见的失败"。** 因为"不要动上一段"这句话，只有在老师亲眼见过
   AI 顺手把走路改坏一次之后，才会被真正遵守。所以讲师的示范里要留一次故意做坏。
3. **循环 = 投入 → 等待 → 回报 → 再投入。少了"投入"，就只剩按一下给个奖励。**
   第一版保底版金币只涨不花，那是个计数器，玩家没有任何决定可做；补上"种子要花钱买"之后，
   老师第一次会问出"我该先种还是先攒钱"——那个问题就是游戏设计的入口。
   这也是为什么阶段③必须拆成 ③-A（闭环成型）和 ③-B（循环闭合）两段，并各设一个硬节点。
