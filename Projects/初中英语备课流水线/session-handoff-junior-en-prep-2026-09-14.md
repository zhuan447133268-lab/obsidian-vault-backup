## 本次会话做的事（按依赖顺序）

### A. 事故返工（最重要，先看这段）

1. **版本年级搞错事故**：原版把 **外研版九上 Unit 2「On the money」** 当 **北师大七上** 出（难度按七年级压、每页 85 字、学情写"初次接触状语从句"）→ 老师反馈"太简单了，而且是九年级外研社的" → **整节课作废**。
   - 修法三层：① 铁律 1（只许核实不许猜，无据先问）② 查 5 版本一致性机器卡 ③ `textbook_map.md` 重写为取证优先级 + 判据表。
2. **对齐本校课件**：老师提供了平时上课的 PPTX（**Unit 2 Developing ideas · Reading for writing 读写课件，21 页**）。逐页 dump 比对后确认**不是同一节课**（我 = Using language 语法课，老师 = Developing ideas 读写课），但**环节骨架与难度标尺必须一致**。
   - 比对出 4 处缺口：方法支架前置 / 成篇产出 + 句型支架 / 自评量表 + 范文 / 结束页。
   - 定位"太简单"根因：**不是页数不够，是产出层级低一档**——旧版停在"认规则 + 单句填空"。
   - 结果：课件 18 → **22 页**，新增 P07 方法支架 / P19 写作任务 / P20 自评量表+范文 / P22 Thank You。
3. **时长一致性**：发现设计稿 45 分钟但课件角标加总 47 分钟（P17/P19 漏改、P21 无角标）→ 修，并新增**查 1b 课件时长加总**机器卡。

## 可沉淀 Skill / 概念卡（候选，待确认后写入 02_/03_ 库）

- **候选 1 · 概念卡｜交付类工具的三层防错**：用户踩坑类教训，只加注释 = 没加。必须三层同落：**规则层**（写进铁律）+ **机器层**（校验脚本卡住）+ **知识层**（把错的写法从 knowledge base 里删掉）。本次版本年级事故即此模式的典型。
- **候选 2 · 概念卡｜"太简单"的判定口径**：课件被判"太简单"，根因通常不是页数，而是**产出层级**——停在"认规则/单句操练"而未上升到"成段表达 + 自我评价"。对标法：拿本校老师课件逐页 dump，映射不上的空位就是漏掉的环节。
- **候选 3 · Skill 卡｜跨课件难度对标法**：dump 两份 PPTX → 逐页映射 → 空位即缺口；同时数练习形态种类（形态 <3 种基本判"练不够"）。
- **候选 4 · Skill 卡｜"先问再点"演示设计法**：交互演示是讲解器不是练习题；每模块必须"教师提问 → 学生先猜 → 点击验证 → 结论固化"。
- **候选 5 · 概念卡｜教材插图风格要有实证依据**：不凭印象定风格，用教材多模态分析数据反推规格（构图/视角/景别/情态），再写进 skill 当硬规格。
- **候选 6 · Skill 卡｜HTML 演示的真实截图验收**：Playwright `channel='chrome'` 绕过版本不匹配 + 查 `scrollWidth == clientWidth` 防投屏横向被切。
