## 2. 设计目标与原则

### 2.1 设计目标
- **对齐需求**：每个技术模块都能追溯到需求文档中的 FR/BR/US 编号。
- **开发可落地**：方案细化到表结构、接口、关键算法、页面组件，开发团队可直接执行。
- **移动优先**：学生端主要在手机钉钉上使用，页面必须适配移动端。
- **数据安全**：成绩、证书、考试次数等关键数据必须保证一致性和不可篡改。
- **异常可控**：断网、刷新、退出等场景必须有明确的数据恢复和交卷策略。

### 2.2 设计原则
| 原则 | 说明 |
|------|------|
| 单一职责 | 按业务域拆分模块，避免大单体服务 |
| 权限最小化 | 数据查询默认带 scope 过滤，禁止越权 |
| 显式优于隐式 | 组卷规则、证书编号规则、有效期计算全部配置化 |
| 防御式计时 | 考试时间以服务端为准，客户端只做展示和兜底 |
| 做+验分离 | 关键业务（组卷、判分、证书生成）写独立校验逻辑 |
| 缓存非真相 | Redis 只作为缓存/锁/会话，MySQL 为唯一状态真相源 |
| 状态机闭环 | 所有 Paper 状态转换必须显式、可逆、可审计 |

## 3. 技术栈选型

### 3.1 推荐技术栈

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| 前端框架 | Vue 3 + Vite + TypeScript | 生态成熟，TypeScript 保证类型安全，团队学习成本低 |
| 移动端 UI | Vant 4 | 专为移动端设计，适配钉钉内置浏览器 |
| 状态管理 | Pinia | Vue 3 官方推荐，简洁易调试 |
| 后端框架 | NestJS (Node.js) + TypeScript | 模块化、装饰器语法、企业级项目常用，与前端同语言 |
| ORM | Prisma | 类型安全、迁移方便、支持 MySQL |
| 数据库 | MySQL 8.0 | 学校环境常见，支持 JSON、窗口函数、事务 |
| 缓存 | Redis 7 | 会话、分布式锁、限流、缓存（非状态真相源） |
| 容器化 | Docker + Docker Compose | 便于开发环境和测试环境统一部署 |
| 反向代理 | Nginx | 静态资源、HTTPS、负载均衡 |

| 组件             | 不采用原因                                   |
| -------------- | --------------------------------------- |
| 学校实时数据接口       | 用户确认基础数据通过公司数据库导出文件导入，不对接实时接口           |

### 4.2 服务分层

| 分层 | 职责 | 代表 |
|------|------|------|
| 接入层 | HTTPS 接入、静态资源、限流 | Nginx |
| 表现层 | 页面渲染、用户交互、本地状态 | Vue 3 SPA |

### 4.3 核心时序（学生考试）

```

    │
    ▼

    │
    ▼
后端用 authCode 换取钉钉 userId
    │
    ▼
根据 userId 查询/匹配本地用户（未绑定则跳转 CAS）
    │
    ▼
返回 JWT Token + 用户角色
    │
    ▼
学生查看可考列表
    │
    ▼
进入考试 → 校验次数 → 创建新 Paper → 锁定题目
    │
    ▼
前端每 10 秒同步答案 + 剩余时间到后端
    │
    ▼
学生提交 / 超时 / 断网超 10 分钟 → 后端事务内判分 + 增加次数
    │
    ▼
成绩 ≥ 80 → 生成证书
    │
    ▼
学生查看成绩/证书
```

## 5. 模块/页面级技术方案

### 5.1 认证与登录模块

#### 5.1.1 对应需求
- FR-01 ~ FR-04：钉钉工作台入口、CAS 统一身份认证、重名展示、用户信息来源。

#### 5.1.2 页面清单
| 页面 | 路径 | 说明 |
|------|------|------|
| 入口页 | `/login` | 钉钉内打开，调用 JSAPI 获取 authCode |
| CAS 回调页 | `/auth/cas/callback` | CAS 登录成功后跳转 |
| 角色首页 | `/` | 根据角色重定向到不同首页 |

#### 5.1.3 前端实现
- 使用 `dd.runtime.permission.requestAuthCode` 获取钉钉 authCode。
- 调用后端 `/auth/dingtalk` 接口。
- 后端返回 `{ token, user, needBind }`：
  - 如 `needBind=true`，跳转 CAS 绑定页面；
  - 否则存储 JWT，进入首页。
- JWT 存储方案（二选一，优先推荐 httpOnly Cookie）：
  - **推荐**：`httpOnly` Cookie + CSRF Token，安全性最高；
  - **备选**：Bearer Token 存内存（Refresh Token 存 httpOnly Cookie），避免 localStorage XSS 风险。

#### 5.1.4 后端实现
- **DingTalk Auth Service**：调用钉钉服务端 API，用 `appKey` + `appSecret` + `authCode` 换取 `userId`。
- **User Service**：根据 `userId` 查询本地用户：
  - 存在 → 生成 JWT；
  - 不存在 → 标记 `needBind=true`，前端引导 CAS 登录。
- **CAS Callback**：CAS 返回 ticket 后，服务端验证 ticket，获取用户基本信息（姓名、学号/工号），根据学号/工号匹配本地已导入用户并绑定钉钉 userId。
- **JWT Payload**：`{ sub: userId, role, collegeId, classId, iat, exp }`。

#### 5.1.5 关键设计点
- 学生和教师第一次使用时必须完成 CAS 绑定，绑定关系写入 `user.dingtalk_user_id`。
- 重名处理：所有下拉框展示 `studentNo/name` 或 `staffNo/name`。
- 角色通过 `user_roles` 关联表管理，支持一人多角色。
- **若 CAS 返回的学号/工号在本地不存在，禁止登录并提示联系管理员导入数据**。

### 5.2 题库管理模块

#### 5.2.1 对应需求
- FR-05 ~ FR-09：题目类型、分类、学院绑定、分值、CRUD。
- US-SA-01：学校管理员维护题库。

#### 5.2.2 页面清单
| 页面 | 路径 | 角色 |
|------|------|------|
| 题库列表 | `/questions` | 学校管理员 |
| 新增/编辑题目 | `/questions/create` `/questions/:id/edit` | 学校管理员 |
| 批量导入 | `/questions/import` | 学校管理员 |

#### 5.2.3 前端实现
- 列表页支持按题型、分类、学院、关键字搜索。
- 编辑页动态显示选项（单选/多选显示选项输入，判断题固定“正确/错误”）。
- 批量导入支持 Excel 模板下载与上传。

#### 5.2.4 后端实现
- **Question Entity**：
  ```
  id, type(SINGLE|MULTIPLE|JUDGE), category(GENERAL_SAFETY|PROFESSIONAL|GENERAL_EDU),
  collegeId?, content, options(JSON), answer(JSON), score(default 4), enabled, createdAt, updatedAt
  ```
- **API**：
  - `GET /api/questions`：分页查询，带 scope（学校管理员可查全部，其他角色不可访问）。
  - `POST /api/questions`：创建题目。
  - `PUT /api/questions/:id`：更新。
  - `DELETE /api/questions/:id`：逻辑删除（enabled=false）。
  - `POST /api/questions/import`：批量导入，返回成功/失败明细。

#### 5.2.5 关键设计点
- 题目变更不影响已发布考试的试卷（Paper 快照保存题目副本）。
- 专业题必须绑定学院；通用安全题和通识教育题不绑定学院。
- 答案用 JSON 存储：单选 `["A"]`，多选 `["A","C"]`，判断 `["TRUE"]`。

### 5.3 组卷与发布模块

#### 5.3.1 对应需求
- FR-10 ~ FR-14：组卷比例、随机抽题、预览、重新组卷。
- FR-15 ~ FR-18：选择学生、发布考试、3 天时间窗口。
- US-T-01 ~ US-T-03：教师选择学生、组卷预览、发布。

#### 5.3.2 页面清单
| 页面 | 路径 | 角色 |
|------|------|------|
| 考试列表 | `/exams` | 教师/学院管理员/学校管理员 |
| 创建考试-选择学生 | `/exams/create/students` | 教师 |
| 创建考试-组卷预览 | `/exams/create/preview` | 教师 |
| 创建考试-发布设置 | `/exams/create/settings` | 教师 |
| 考试详情 | `/exams/:id` | 教师/管理员 |

#### 5.3.3 前端实现
- **选择学生**：
  - 调用 `/api/students?classId=xxx` 获取学生列表；
  - 支持按班级/年级筛选、全选、批量选择；
  - 已选学生写入创建流程的 Pinia store。
- **组卷预览**：
  - 调用 `POST /api/exams/draft` 生成试卷草稿；
  - 展示 25 道题及正确答案（教师视角）；
  - 提供“重新组卷”按钮，重新调用 draft 接口。
- **发布设置**：
  - 选择开始时间，系统自动计算结束时间 = 开始时间 + 3 天；
  - 发布按钮调用 `POST /api/exams/:id/publish`。

#### 5.3.4 后端实现
- **组卷服务（PaperGenerationService）**：
  - 输入：学院 ID、题目数量（默认 25）、规则配置；
  - 输出：题目 ID 列表（含顺序）。
  - 算法：
    ```typescript
    async generatePaper(examId: string, studentId: string, isMakeup = false): Promise<Paper> {
      const exam = await this.examRepo.findById(examId);
      const college = await this.collegeRepo.findById(exam.collegeId);
      const rules = college.isSpecial ? SPECIAL_RULES : DEFAULT_RULES;

      const selectedQuestions: Question[] = [];
      for (const rule of rules) {
        const poolIds = await this.questionRepo.findAllAvailableIds({
          category: rule.category,
          collegeId: rule.collegeId || exam.collegeId,
          enabled: true,
        });
        if (poolIds.length < rule.count) {
          throw new InsufficientQuestionsException(rule.category, rule.count, poolIds.length);
        }
        const shuffledIds = fisherYatesShuffle(poolIds).slice(0, rule.count);
        const questions = await this.questionRepo.findByIds(shuffledIds);
        selectedQuestions.push(...questions);
      }

      const finalOrder = fisherYatesShuffle(selectedQuestions);
      const paper = await this.paperRepo.create({
        examId,
        studentId,
        isMakeup,
        status: 'DRAFT',
      });

      await Promise.all(
        finalOrder.map((q, idx) =>
          this.paperQuestionRepo.create({
            paperId: paper.id,
            questionId: q.id,
            seqNo: idx + 1,
            contentSnapshot: q.content,
            optionsSnapshot: q.options,
            answerSnapshot: q.answer,
            score: q.score,
          }),
        ),
      );

      return paper;
    }
    ```
- **组卷规则配置（Configurable）**：
  ```json
  {
    "default": [
      { "category": "GENERAL_SAFETY", "count": 13 },
      { "category": "PROFESSIONAL", "count": 12, "collegeId": "xxx" }
    ],
    "special": [ // 汽车/电气/智科
      { "category": "GENERAL_SAFETY", "count": 8 },
      { "category": "PROFESSIONAL", "count": 9, "collegeId": "xxx" },
      { "category": "GENERAL_EDU", "count": 8 }
    ]
  }
  ```
- **发布考试**：
  - 创建 `Exam` 记录；
  - 为每个学生生成 `Paper` 草稿（状态 DRAFT），题目已锁定；
  - 设定 `startTime` 和 `endTime = startTime + 3 天`。

#### 5.3.5 关键设计点
- **试卷快照**：发布时把题目内容、选项、正确答案复制到 `paper_questions` 表，避免题库变更影响已发布考试。
- **时间窗口**：发布后学生只能在窗口期内进入考试；教师不能修改已发布考试。
- **抽题失败处理**：如果某类题库数量不足，返回明确错误，禁止发布。
- **真正随机**：先查全部可用题目 ID，Fisher-Yates 洗牌后取前 N 个，保证全库均匀随机。

### 5.4 考试作答模块

#### 5.4.1 对应需求
- FR-19 ~ FR-24：30 分钟倒计时、答题、修改、二次确认、即时出分。
- FR-25 ~ FR-28：断网/退出/刷新恢复、10 分钟限制、自动交卷、机会消耗。
- US-S-01、US-S-04：学生考试、断网恢复。

#### 5.4.2 页面清单
| 页面 | 路径 | 角色 |
|------|------|------|
| 待考列表 | `/student/exams` | 学生 |
| 考试页面 | `/student/exams/:id/take` | 学生 |
| 考试结果 | `/student/exams/:id/result` | 学生 |

#### 5.4.3 前端实现
- **待考列表**：展示进行中的考试，显示考试名称、剩余时间窗口、状态（未考/已考/缺考）。
- **考试页面**：
  - 进入时调用 `POST /api/papers/start`，后端返回试卷题目、已答答案、剩余秒数；
  - 顶部倒计时显示；
  - 每道题选择答案后写入 localStorage 并每 10 秒同步到后端；
  - 提交前弹窗确认；
  - 监听 `beforeunload` 事件提示“离开将消耗考试机会”。
- **断网恢复**：
  - 页面隐藏/显示时调用 `POST /api/papers/resume`；
  - 如果后端返回剩余时间 ≤ 0，自动跳转结果页；
  - 如果后端返回考试已关闭（超过 10 分钟），跳转结果页。

#### 5.4.4 后端实现
- **考试开始（start）**：
  - 校验考试窗口、考试次数、学生权限；
  - 原子判断并递增次数（见 8.4）；
  - 创建新的 `Paper`（状态 DRAFT → IN_PROGRESS）；
  - 记录 `startTime` 和 `serverEndTime = startTime + 30 分钟`；
  - 返回题目（隐藏正确答案）、已答答案、剩余秒数。
- **答案同步（sync）**：
  - 接收 `{ paperId, answers, clientRemainingSeconds }`；
  - 服务端计算真实剩余时间 = `serverEndTime - now`；
  - 更新 `paper.answers` 和 `lastSyncTime`；
  - 如果 `now > serverEndTime`，自动调用判分并交卷。
- **恢复考试（resume）**：
  - 校验 Paper 状态为 IN_PROGRESS；
  - 计算 `lastActiveTime = max(startTime, lastSyncTime)`；
  - 如果 `now - lastActiveTime <= 10 分钟` 且 `now < serverEndTime`：返回试卷和剩余时间；
  - 如果 `now >= serverEndTime`：自动交卷并返回 TIMEOUT；
  - 如果 `now - lastActiveTime > 10 分钟`：自动交卷并返回 AUTO_SUBMITTED。
- **提交（submit）**：
  - 校验考试仍在窗口期内且未超时；
  - 在数据库事务内：
    1. 查询 Paper 状态，仅 IN_PROGRESS 可提交；
    2. 调用判分服务；
    3. 更新 Paper 状态为 SUBMITTED / TIMEOUT / AUTO_SUBMITTED；
    4. 如果通过且没有已有证书，生成证书。

#### 5.4.5 关键设计点
- **时间权威源**：服务端 `serverEndTime` 是唯一权威，客户端倒计时只做展示。
- **双写机制**：答案同时写 localStorage 和服务端，断网时 localStorage 兜底，恢复后批量同步。
- **机会消耗**：任何交卷（submit、timeout、auto-submit）都在同一事务内调用 `incrementAttemptCount`。
- **每次尝试新建 Paper**：正常考试不修改已提交的 Paper，新的 start 创建新 Paper。
- **并发控制**：start、submit、timeout 都使用数据库状态机 + 原子更新防止竞态。

### 5.5 成绩与证书模块

#### 5.5.1 对应需求
- FR-29 ~ FR-33：80 分通过、证书生成、证书编号、证书与 CAS 登录绑定、10 次机会。
- US-S-02：学生查看证书。
- US-SA-04 / US-CA-03：学校管理员/学院管理员导出电子证书图片。

#### 5.5.2 页面清单
| 页面 | 路径 | 角色 |
|------|------|------|
| 成绩详情 | `/student/exams/:id/result` | 学生 |
| 我的证书 | `/student/certificates` | 学生 |
| 证书展示页 | `/certificates/:id` | 学生 |
| 证书导出管理 | `/admin/certificates/export` | 学校管理员/学院管理员 |

#### 5.5.3 前端实现
- **学生端**：
  - 成绩页展示分数、通过状态、错题概要（可选）。
  - 证书页以精美 DOM 展示证书（姓名、学号、学院、证书编号、发证日期），支持长按/右键保存为图片（浏览器原生能力）。
  - 学生端不调用后端图片生成接口。
- **管理员端**：
  - 学校管理员/学院管理员可在证书导出管理页按学院/班级/考试筛选通过学生。
  - 支持单张下载和批量导出电子证书图片（PNG/PDF）。
  - 导出为异步任务，大批量时返回下载链接。

#### 5.5.4 后端实现
- **判分服务（GradingService）**：
  - 遍历 Paper 中每道题，对比 `paper.answer` 与 `paper.correctAnswer`；
  - 单选/判断完全匹配得分；多选完全匹配得分，少选/多选/错选不得分；
  - 总分为答对题数 × 4。
- **证书生成服务（CertificateService）**：
  - 触发条件：成绩 ≥ 80 分且该学生还没有证书；
  - 证书编号：`LAB-${year}-${collegeCode}-${random8}`（Base62，见 8.3）；
  - **无 expiry_date：证书可见性与 CAS 登录状态绑定**；
  - 写入 `Certificate` 表。
- **证书图片生成服务（CertificateImageService）**：
  - 输入：证书数据（姓名、学号、学院、证书编号、发证日期）；
  - 输出：PNG/PDF 图片文件；
  - 实现方案（二选一）：
    - 方案 A：Puppeteer + HTML 模板渲染后截图；
    - 方案 B：Node Canvas / Sharp 直接绘制；
  - 推荐使用 Puppeteer，证书样式与前端 DOM 展示保持一致。
- **证书导出服务（CertificateExportService）**：
  - 按角色数据范围查询通过学生证书；
  - 单张导出：直接返回图片流；
  - 批量导出：异步生成压缩包（ZIP），返回下载链接；
  - 大文件采用 Bull 异步队列。
- **API**：
  - `GET /api/certificates`：我的证书列表；
  - `GET /api/certificates/:id`：证书详情；
  - `GET /api/certificates/:id/image`：下载单张证书图片（管理员）；
  - `POST /api/certificates/export`：批量导出证书（管理员），返回异步任务 ID；
  - `GET /api/certificates/export/:taskId`：查询导出任务状态与下载链接。

#### 5.5.5 关键设计点
- 证书编号生成需保证唯一性：数据库对 `certificate_id` 加唯一索引，冲突时重试。
- **证书无固定过期日期，只要学生 CAS 账号有效、能登录系统即可查看**。
- 如果学生已有证书，再次通过考试不重复发证（一个学生一生成一次证书）。
- 学生端不调用后端图片生成，学生自行保存证书图片。
- **管理员端需要后端生成证书图片**：采用 Puppeteer 或 Canvas 绘制，支持单张下载和批量导出 ZIP。
- 批量导出需加数据范围过滤，学院管理员只能导出本学院证书。

#### 5.7.1 对应需求
- FR-01 ~ FR-04、FR-43 ~ FR-45：用户角色、数据范围、基础数据导入。
- US-SA-02、US-SA-05：指定学院管理员、导入基础数据。
- US-CA-01：管理本学院教师。

#### 5.7.2 页面清单
| 页面 | 路径 | 角色 |
|------|------|------|
| 学校管理员设置 | `/admin/school/admins` | 学校管理员 |
| 学院管理员设置 | `/admin/school/college-admins` | 学校管理员 |

- **RBAC 模型**：
  - `users` 表不直接存角色，通过 `user_roles` 关联表管理。
  - `CollegeAdmin` 表：`userId + collegeId`，一人可管多个学院。
  - `Teacher` 表：`userId + classId + canCreateExam + canProctor`。
- **数据范围 Service（DataScopeService）**：
  - 每个查询自动注入 `collegeId` / `classId` / `teacherId` 条件；
  - 学校管理员返回 `null`（表示无限制）。
- **Guard/Interceptor**：
  - NestJS `@Roles()` 装饰器 + `RolesGuard`；
  - 接口级权限控制 + 数据级权限控制双重校验。
- **数据导入服务（DataImportService）**：
  - 解析 Excel/CSV；
  - 校验必填字段、学院/班级关联关系；
  - 事务批量写入 `colleges`、`classes`、`users`、`user_roles`、`teacher_classes`；
  - 返回导入成功/失败明细。

#### 5.7.4 关键设计点
- 权限校验必须同时做：接口权限（能不能调）+ 数据权限（能不能看这条数据）。
- 教师选择学生时，只能从自己负责的班级选。
- 学院管理员指定教师时，只能选本学院人员。
- 导入文件模板可下载，字段与 `users` 表对应。

#### 5.8.1 对应需求

#### 5.8.2 页面清单

#### 5.8.3 后端实现
- **缺考处理（AbsenceService）**：
  - 考试窗口结束后的定时任务扫描所有 DRAFT 状态的 Paper；
  - 标记为 ABSENT，并记录 `absentAt`。
- **补考处理（MakeupService）**：
  - 教师选择学生，点击“重新抽题补考”；
  - 生成新的 Paper，标记 `isMakeup=true`；

#### 5.8.4 关键设计点
- 补考 Paper 与正常 Paper 共用统一状态机，通过 `is_makeup` 字段区分。
- 缺考标注由定时任务完成，也可在教师查看时实时计算（窗口结束且状态为 DRAFT）。
- 提醒功能异步发送，避免阻塞主流程。

## 8. 关键业务逻辑实现

### 8.1 组卷算法

```typescript
// paper-generation.service.ts
async generatePaper(examId: string, studentId: string, isMakeup = false): Promise<Paper> {
  const exam = await this.examRepo.findById(examId);
  const college = await this.collegeRepo.findById(exam.collegeId);
  const rules = college.isSpecial ? SPECIAL_RULES : DEFAULT_RULES;

  const selectedQuestions: Question[] = [];
  for (const rule of rules) {
    const poolIds = await this.questionRepo.findAllAvailableIds({
      category: rule.category,
      collegeId: rule.collegeId || exam.collegeId,
      enabled: true,
    });
    if (poolIds.length < rule.count) {
      throw new InsufficientQuestionsException(rule.category, rule.count, poolIds.length);
    }
    const shuffledIds = fisherYatesShuffle(poolIds).slice(0, rule.count);
    const questions = await this.questionRepo.findByIds(shuffledIds);
    selectedQuestions.push(...questions);
  }

  const finalOrder = fisherYatesShuffle(selectedQuestions);
  const paper = await this.paperRepo.create({
    examId,
    studentId,
    isMakeup,
    status: 'DRAFT',
  });

  await Promise.all(
    finalOrder.map((q, idx) =>
      this.paperQuestionRepo.create({
        paperId: paper.id,
        questionId: q.id,
        seqNo: idx + 1,
        contentSnapshot: q.content,
        optionsSnapshot: q.options,
        answerSnapshot: q.answer,
        score: q.score,
      }),
    ),
  );

  return paper;
}
```

### 8.2 判分算法

```typescript
// grading.service.ts
grade(paper: Paper): number {
  let score = 0;
  for (const pq of paper.paperQuestions) {
    const studentAnswer = paper.answers?.[pq.seqNo] || [];
    const correctAnswer = pq.answerSnapshot;
    if (this.isCorrect(studentAnswer, correctAnswer, pq.question.type)) {
      score += pq.score;
    }
  }
  return score;
}

isCorrect(student: string[], correct: string[], type: QuestionType): boolean {
  if (type === 'JUDGE' || type === 'SINGLE') {
    return student.length === 1 && student[0] === correct[0];
  }
  if (type === 'MULTIPLE') {
    return student.length === correct.length && student.every(a => correct.includes(a));
  }
  return false;
}
```

### 8.3 证书编号生成

```typescript
// certificate.service.ts
private readonly BASE62 = '0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz';

async generateCertificateId(collegeCode: string): Promise<string> {
  const year = new Date().getFullYear();
  let attempts = 0;
  while (attempts < 10) {
    let random = '';
    for (let i = 0; i < 8; i++) {
      random += this.BASE62[Math.floor(Math.random() * 62)];
    }
    const id = `LAB-${year}-${collegeCode}-${random}`;
    const exists = await this.certificateRepo.exists(id);
    if (!exists) return id;
    attempts++;
  }
  throw new DuplicateCertificateIdException();
}
```

### 8.5 基础数据导入服务

```typescript
// data-import.service.ts
async importUsers(fileBuffer: Buffer): Promise<ImportResult> {
  const rows = await this.excelParser.parse(fileBuffer);
  const validation = this.validateRows(rows); // 检查必填字段、学院/班级存在性
  if (validation.errors.length > 0) {
    return { success: false, errors: validation.errors };
  }

  return this.prisma.$transaction(async (tx) => {
    const stats = { colleges: 0, classes: 0, users: 0, roles: 0, teachers: 0 };

    // 学院/班级通常已在系统初始化时导入，此处只做 upsert
    for (const college of validation.colleges) {
      await tx.colleges.upsert({ where: { id: college.id }, update: college, create: college });
      stats.colleges++;
    }
    for (const cls of validation.classes) {
      await tx.classes.upsert({ where: { id: cls.id }, update: cls, create: cls });
      stats.classes++;
    }

    for (const u of validation.users) {
      await tx.users.upsert({
        where: { student_no: u.studentNo },
        update: {
          name: u.name,
          collegeId: u.collegeId,
          classId: u.classId,
          entryDate: u.entryDate,
        },
        create: { ...u },
      });
      stats.users++;

      // 分配默认角色
      await tx.user_roles.upsert({
        where: { user_id_role: { user_id: u.id, role: u.role } },
        update: {},
        create: { userId: u.id, role: u.role },
      });
      stats.roles++;

      // 教师额外写入 teacher_classes
      if (u.role === 'TEACHER' && u.classId) {
        await tx.teacher_classes.upsert({
          where: { user_id_class_id: { user_id: u.id, class_id: u.classId } },
          update: {},
          create: { userId: u.id, classId: u.classId, canCreateExam: true, canProctor: true },
        });
        stats.teachers++;
      }
    }

    return { success: true, stats };
  });
}
```

## 9. 异常与断网恢复机制

### 9.1 状态机

```
DRAFT --start--> IN_PROGRESS --submit--> SUBMITTED
                              --timeout--> TIMEOUT
                              --disconnect >10min--> AUTO_SUBMITTED
                              --window end未开始--> ABSENT
```

- 补考与正常考试共用同一状态机，通过 `is_makeup` 字段区分。
- 所有终态（SUBMITTED / TIMEOUT / AUTO_SUBMITTED / ABSENT）不可再次 start。

### 9.2 断网恢复流程

```
1. 学生进入考试，前端 localStorage 记录 { paperId, answers, serverEndTime, lastSyncTime }
2. 正常答题时，每 10 秒调用 /api/papers/sync
3. 断网/刷新/退出时：
   a. 前端尝试重连，使用指数退避（1s, 2s, 4s, 8s...）
   b. 恢复网络后调用 /api/papers/resume
   c. 后端检查：
      - lastActiveTime = max(start_time, last_sync_time)
      - 如果 now - lastActiveTime <= 10min 且 now < serverEndTime：返回试卷 + 剩余时间，继续考试
      - 如果 now >= serverEndTime：返回 TIMEOUT，自动交卷
      - 如果 now - lastActiveTime > 10min：返回 AUTO_SUBMITTED，自动交卷
4. 任何自动交卷都消耗 1 次考试机会
```

### 9.3 服务端超时兜底

- 启动定时任务（每 1 分钟执行）：
  - 扫描 `IN_PROGRESS` 状态且 `server_end_time < now` 的 Paper，自动判分并标记 TIMEOUT。
  - 扫描 `IN_PROGRESS` 状态且 `last_sync_time + 10min < now`（若 last_sync_time 为空则用 start_time）的 Paper，自动判分并标记 AUTO_SUBMITTED。
- **分布式锁**：多实例部署时使用 Redis Redlock 或数据库 advisory lock，保证同一时刻只有一个实例执行兜底任务。
- **幂等性**：判分/交卷操作以事务方式执行，利用状态唯一性约束防止重复处理。

### 9.4 客户端倒计时

- 初始剩余时间从服务端获取；
- 客户端用 `serverEndTime - clientNow` 计算，与服务端定时同步；
- 如果客户端时间被篡改，服务端会在 submit/resume 时校正。

## 10. 安全设计

### 10.1 认证安全
- JWT 使用 RS256 签名，密钥由服务端保管；
- Token 有效期 2 小时，支持刷新；
- CAS ticket 只能使用一次，防止重放攻击；
- 优先使用 httpOnly Cookie + CSRF Token 存储会话。

### 10.2 接口安全
- 所有接口 HTTPS；
- 敏感接口（组卷、判分、导出）做接口级权限校验；
- 考试接口增加请求频率限制（如同一用户 1 秒内最多 5 次请求），防止刷接口；
- 导出接口限制频率，防止大文件导出被滥用。

### 10.3 数据安全
- 答案传输加密（HTTPS 已足够，关键业务可加签）；
- 成绩、证书等关键操作写审计日志（`exam_events` 表）；
- 数据库连接使用独立账号，最小权限原则。

### 10.4 防作弊
- 不强制防切屏，但记录 `page_show` / `page_hide` 事件到 `exam_events`；
- 同一账号同一时间只能有一个考试会话（用 Redis 锁）。

## 11. 性能与扩展性

### 11.1 性能优化
- **缓存策略**：
  - 用户会话缓存到 Redis（或 httpOnly Cookie 中不依赖 Redis）；
  - 题库热点数据缓存到 Redis；
  - 考试进行中的 Paper 状态优先读 MySQL，Redis 仅作锁和限流。
- **数据库索引**：关键查询字段加索引（见表结构设计）。
- **异步处理**：提醒、缺考标注、大文件导出异步执行（Bull 队列）。
- **连接池**：MySQL / Redis 使用连接池。

### 11.2 扩展性
- 服务无状态，可水平扩展；
- 组卷规则、证书编号规则配置化，未来可扩展；
- 文件存储已去除，降低运维面。

### 11.3 容量预估
- 用户：假设 2 万学生 + 1000 教师；
- 并发：高峰期 1000 人同时考试；
- 数据量：每学生平均 3 次考试，每次 25 题，一年约 150 万条 PaperQuestion 记录。

## 15. 架构师审查意见与修订说明

本次 v1.1 版本根据独立架构师审查报告进行了以下关键修订：

| 原问题 | 严重程度 | 修订内容 |
|--------|----------|----------|
| 同一场考试内正常重考机制缺失 | 高 | 每次 start 新建 Paper，使用 `student_attempts` 原子计数 |
| 证书有效期按发证日期计算，与需求冲突 | 高 | 改为 `entry_date + 4 年` |
| 考试次数与状态转换存在并发竞态 | 高 | 使用原子 UPDATE、事务内状态机守卫、分布式锁 |
| 试卷状态机未对补考闭环 | 高 | 正常/补考共用状态机，用 `is_makeup` 区分 |
| 后端生成证书图片与 Out of Scope 冲突 | 高 | 移除后端图片生成、MinIO，证书仅前端 DOM 展示 |
| 学生/教师基础数据来源未闭环 | 高 | 增加 `user-sync.service` 学校数据源同步机制 |
| 证书编号随机串不符合格式 | 中 | 改为 Base62 8 位随机串 |
| 组卷抽样不均匀 | 中 | 先查全部可用 ID，Fisher-Yates 洗牌后取前 N |
| JWT 存 localStorage 有 XSS 风险 | 中 | 推荐 httpOnly Cookie + CSRF Token |
| Redis 故障无降级 | 中 | 明确 Redis 为缓存，MySQL 为唯一状态真相源 |
| 角色用逗号字符串维护性差 | 中 | 改为 `user_roles` 关联表 |
| 10 次机会口径不清 | 中 | 方案明确为“每场发布考试 10 次”，需用户确认 |
| 断网恢复对 lastSyncTime 为空不严谨 | 中 | 规则改为 `max(start_time, last_sync_time)` |
| 切屏审计未持久化 | 中 | 新增 `exam_events` 审计表 |
