# 实验室准入考试系统 - 需求调研清单

## 项目概述

**核心流程：**
```
学生登录（统一身份认证）→ 识别专业 → 推送对应题库（通识题 + 专业题）→ 答题 → 判分 → 达标则获得实验室准入资格
```

**已知条件：**
- 题库已存在（通识题库 + 各专业题库）
- 学生身份来自统一认证，不需自建账号体系
- 按专业分流推送不同题目

**创建日期：** 2026-06-15
**状态：** 待向业务方确认

---

## 一、用户与权限

- [ ] **用户角色有哪些？** 学生（答题者）之外，是否还有：管理员（管题库）、实验室老师（审核准入）、院系领导（看数据）？
- [ ] **一个学生可能属于多个专业吗？** 比如双学位、跨专业选课的情况，需要推送多套题还是只推主修专业？
- [ ] **教师/管理员怎么登录？** 也走统一认证，还是单独账号？

---

## 二、题库与组卷

- [ ] **题库当前是什么形态？** Word文档？Excel？还是已经在某个系统里？
- [ ] **题型有哪些？** 单选、多选、判断、填空、简答？还是只有客观题？
- [ ] **通识题和专业题的比例是多少？** 比如通识20道 + 专业30道？还是固定总分？
- [ ] **组卷规则是什么？** 随机抽题（从题库中随机抽取固定数量）？固定套卷？还是两者都支持？
- [ ] **题库谁来维护？** 各专业老师各自上传自己的专业题，还是统一由一个管理员管理？

---

## 三、答题流程

- [ ] **答题有次数限制吗？** 每人每天/每周/总共可以考几次？不限制？
- [ ] **答题有时间限制吗？** 单次考试限时多久？还是不限时？
- [ ] **支持断点续答吗？** 答一半关了浏览器，下次回来是接着答还是重新开始？
- [ ] **分数线是统一的还是分专业设定？** 比如化学专业80分过，物理专业70分过？
- [ ] **通过后是永久有效还是有有效期？** 比如通过后一学期有效，下学期重新考？

## 四、防作弊

- [ ] **需要防作弊机制吗？** 比如切屏检测、人脸识别、IP限制？
- [ ] **题目顺序和选项顺序需要随机打乱吗？**

---

## 五、结果与准入

- [ ] **通过后怎么"准入"实验室？** 系统自动推送一个通过凭证（二维码/电子证），还是仅在系统里标记状态、由实验室老师人工核验？
- [ ] **没通过怎么办？** 强制学习一段时间后才能重考？还是可以立刻重考？
- [ ] **成绩需要给学生看吗？** 只告诉通过/不通过，还是显示分数+错题？

---

## 六、数据与统计

- [ ] **需要管理后台吗？** 查看各专业通过率、单个学生答题记录、导出报表？
- [ ] **需要和现有教务系统对接吗？** 比如把通过状态同步到教务系统？

---

## 七、技术与部署

- [ ] **统一认证是哪个系统？** CAS？OAuth2？学校的自研SSO？
- [ ] **部署环境有偏好吗？** 学校服务器（Windows/Linux）？云部署？需要内网访问还是公网？
- [ ] **移动端需要吗？** 学生在手机上答题？还是只在PC端？
- [ ] **预期用户量多大？** 一届学生大概多少人？峰值并发大概多少？

---

## 优先级建议

> **优先确认前6项：** 用户角色、题库形态、组卷规则、答题次数、分数线、准入方式 —— 这6项直接决定系统架构。

| 优先级 | 模块 | 影响 |
|--------|------|------|
| 🔴 高 | 用户与权限 | 决定角色模型和权限体系 |
| 🔴 高 | 题库与组卷 | 决定数据结构和管理端设计 |
| 🔴 高 | 答题流程 | 决定考试引擎核心逻辑 |
| 🟡 中 | 结果与准入 | 决定通过后的业务闭环 |
| 🟡 中 | 防作弊 | 影响前端交互复杂度 |
| 🟢 低 | 数据与统计 | 管理后台功能边界 |
| 🟢 低 | 技术与部署 | 技术选型和部署方案 |
