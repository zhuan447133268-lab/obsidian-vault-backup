# 2026-08-14 教师班级关联删除未拦截进行中考试（已修复）

## 一、问题概述

用户反馈：给 BN100009271 分配班级并发布考试后，在「学院管理员页面 → 本院教师管理」中移除该教师的班级关联，**未被拦截**，直接删除成功。

---

## 二、已确认事实

1. 测试环境 Jenkins 部署的是最新代码 `10bba34`，后端已重启。
2. 用户操作的入口实际调用的是 `removeTeacherClass`：
   - 前端页面：`web/src/views/college-admin/teachers.vue`
   - API：`DELETE /users/teacher-classes/{id}`
   - 后端：`server/src/modules/users/users.service.ts` 的 `removeTeacherClass`
3. 当前 `removeTeacherClass` 的拦截条件：
   ```ts
   where: {
     publisherId: record.userId,
     classId: record.classId,
     status: ExamStatus.PUBLISHED,
     startTime: { lte: now },
     endTime: { gte: now },
   }
   ```
4. 班级管理删除入口 `removeClass` 已修复，但本次未走该入口。

---

## 三、已定位根因

`removeTeacherClass` 只检查「发布者是该教师且班级匹配」的进行中考试，条件过窄：

- **管理员代发布场景**：`publisherId` 是管理员 id，不是教师 id，导致漏判。
- **self-publish 仍可能漏**：如果 `exam.classId` 未写入或与 `teacher_classes.classId` 不一致，条件不匹配。

更合理的语义是：**只要该班级下存在进行中考试，就禁止移除该班级的教师关联**。

---

## 四、下一步修复方案

将 `removeTeacherClass` 中的活跃考试检查从「按发布者 + 班级」改为「只按班级」：

```ts
const activeExam = await this.prisma.exam.findFirst({
  where: {
    classId: record.classId,
    status: ExamStatus.PUBLISHED,
    startTime: { lte: now },
    endTime: { gte: now },
  },
});
```

错误码保持 `code: 1303`。

## 八、修复完成

### 实际根因确认

通过数据库查询确认，被测场景的 `publisher_id` 和 `class_id` 都能对上：

| 对象 | id | 关键字段 |
|---|---|---|
| 教师用户 | `6ecc0e4e-84ad-4b7b-adde-acf8d652a8cf` | staff_no = BN100009271 |
| teacher_classes | `1abb2833-19d7-44e4-9800-0c07129c635e` | user_id / class_id 均匹配 |
| 考试 | `b100f5e9-c0c4-4c6f-af5c-2fa0ed267f6f` | publisher_id = 教师，class_id = 班级，status = PUBLISHED |

因此本次漏拦**不是** `publisherId` 不匹配，但 `publisherId` 条件仍然过窄：若出现管理员代发布、或 `self-publish` 时 `classId` 不一致，仍会漏判。统一按 `classId` 拦截语义更稳。

### 改动

- **文件**：`server/src/modules/users/users.service.ts`
- **修改**：`removeTeacherClass` 的活跃考试检查从
  ```ts
  where: { publisherId: record.userId, classId: record.classId, ... }
  ```
  改为
  ```ts
  where: { classId: record.classId, ... }
  ```
- **错误码**：保持 `1303`
- **语义**：只要该班级下有进行中考试（`PUBLISHED` 且 `startTime <= now <= endTime`），即禁止移除该班级的教师关联。
- **业务规则确认**：已发布但未开始的考试允许删除关联，方便教师删除后重新创建考试。详见 [[removeTeacherClass 进行中考试拦截规则]]。
