## 一、业务口径（用户 2026-11-25 拍板）

| 项 | 结论 |
|---|---|
| 谁进应考名单 | 学籍状态 ∈ {`在读`, `正常`} 才计入应考 |
| `正常` 是什么 | 烟台校区学生的「在读」写法（中间库 `t_xsjbxx.xsdqzt` 实连核实：哈尔滨=在读 11921 / 烟台=正常 11572） |
| 休学/停学/保留学籍/退学/其他 | 不进名单、不算缺考、不发证、不参与统计分母 |
| 复学怎么办 | 考试**每年一次** ⇒ 每日 03:10 同步后自然进入下一期，无需人工维护 |
| 考试期间刚复学 | 同步是天级延迟 ⇒ 走「手工补录」把人补进本场（不改考试范围） |
| 查不到学籍（未同步/同步失败） | **fail-open**：当「在读」处理，不因中间库故障挡住考试 |

## 二、实现要点

- **镜像表**：`student_statuses`（学号唯一、状态、年级 `XZNJ`、班级/学院/专业、`synced_at`）+ `student_status_sync_logs`（trigger/status/total/active/inactive/duration_ms/started_at/finished_at）。
- **同步**：每日 03:10 + 管理端「立即同步」；只读账号拉 `jinzhi_midd.t_xsjbxx`，条件 `SZYX LIKE '%哈尔滨剑桥学院%'`；**500 行/批** `INSERT … ON DUPLICATE KEY UPDATE`，末尾 `deleteMany(syncedAt < 本次)` 清退学籍消失者；并发点只跑一次（共享 in-flight Promise，**已加 5 分钟查询超时**）；启动时把 >30 分钟的 running 日志翻 failed。
- **快照**：发布考试时把当时的学籍状态写进试卷/名单快照；此后同步变动不影响已发布场次。
- **拦截**：组卷/补考/补录名单里出现非在读 → `1411`，点名「姓名（学号·状态）」，带 `data.inactive`；前端确认「仍要生成/仍要补录」后带 `confirmInactive: true` 重发。
- **发布**：范围内**全部**非在读 → `1406`，文案点名学籍构成 + 给出「同步学籍 / 手工补录」出路。
- **展示**：考试详情「范围内共 N 人 / 在读 X / 非在读未纳入 Y（分状态）」；学院统计明细 + 导出两个 sheet 都带「学籍状态」列。
