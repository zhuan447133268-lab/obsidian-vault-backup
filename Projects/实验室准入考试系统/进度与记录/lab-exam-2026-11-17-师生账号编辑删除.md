# 师生账号编辑/删除（仅学校管理员）

> **一句话**：学校管理员新增师生录错后，原先只能「禁用」，错号永远留着占着学号/工号。本次补齐 `PATCH /users/:id`（改姓名/学号或工号/角色/学院/专业/班级）与 `DELETE /users/:id`（**仅无业务数据的账号可硬删**），两条接口都只对 `SCHOOL_ADMIN` 开放。commit **`e18538c`（+审计补丁 `b234d9c`）已推 main**，**已部署测试环境并验收全过**；**2026-11-17 用户拍板：随下一次发版一起发，不单独 build**（按攒批节奏，见 [[待发版清单]] §二·补·3）。

## 一、需求与拍板（2026-11-17 用户）

业务触发：教师在（实际是学校管理员在）「新增师生」里把姓名/学号打错，建出一个错误账号。目前系统只有「禁用」和「重置密码」，**无法纠正也不能删除**，错号会一直占着学号。

| 议题 | 用户拍板 |
|---|---|
| 资格 | **只有学校管理员有新增师生资格**，所以错误账号也由学校管理员编辑/删除 |
| 删除策略 | **仅空账号可硬删**；已经产生过业务的账号（考过试、有证书、发过考试）**不能删，只能改对** |
| 权限范围 | **仅学校管理员**（学院管理员、教师一律不可） |
| 可编辑字段 | **姓名 + 学号/工号 + 角色 + 学院 + 专业 + 班级** 全部可改 |
| 审计 | **先落服务端日志**，不新增表、不加迁移（后续要页面可查再单开迭代） |

## 二、为什么不能直接删（关键约束）

`schema.prisma` 里多条关系是 `onDelete: Cascade`：

- `Exam.publisher`（:203）→ 删教师会**连带删掉他发布过的所有考试**
- `Paper.student`（:242）→ 删学生会连带删掉他的试卷
- `Certificate.student`（:294）→ 删学生会连带删掉他的证书

所以硬删必须先算清「有没有业务数据」。列表接口因此对每行返回 `dataCounts`（`papers` / `certificates` / `exams`）与 `canEdit` / `canDelete`，后端删除前再查一次（前端标志只是提前告知，**判定以后端为准**）。

## 三、接口与护栏

### PATCH `/api/users/:id`（`@Roles(SCHOOL_ADMIN)`）

可改：`name`、`staffNo`、`studentNo`、`role`、`collegeId`、`majorId`、`classId`。

| 场景 | 行为 |
|---|---|
| 学号/工号与他人重复 | **1501**（跨字段查重，排除自己） |
| 缺必填（教师需工号+学院；学生需学号+班级） | **1504** |
| 学院/专业/班级不存在或不自洽 | **1505**（班级为真值：服务端由 `classId` 反查学院/专业/年级并校验传入值） |
| 改自己 | **1506** |
| 目标是 `admin` 或任何 `SCHOOL_ADMIN` | **1510** |
| 改角色但账号已有试卷/证书/发布考试，或带 `COLLEGE_ADMIN` 角色 | **1509**（提示先用编辑修正资料、必要时禁用） |
| 姓名清空 | **1504** |

角色变更（`role` 变了才动）：
- 只允许 `TEACHER ⇄ STUDENT`，且**必须零业务数据**；
- 重建 `user_role_rel`（删旧角色、加新角色）；
- 教师转学生时清空 `teacher_class`（分班关系），避免残留「学生却有带班权限」；
- **`admin` 的工号不可改**：`isSystemAdmin` 由 `student_no === 'admin'` 推导（`common/constants.ts`），改了等于交出唯一钥匙。

删除 `/api/users/:id`：自己 **1506** → 不存在 **1401** → 保护账号 **1510** → 有业务数据 **1508**（消息里带「试卷 N 份 / 证书 N 张 / 发布考试 N 场」）→ 否则事务里删 `teacher_class` / `college_admin` / `user_role_rel` 再删用户。

### 审计（服务端结构化日志）

- `action: 'USER_UPDATE'`：操作人 id、目标 id、姓名/学号/工号、角色变更前后、班级/学院变更前后；
- `action: 'USER_DELETE'`：操作人、被删账号的姓名/学号/工号与删除时的 `dataCounts`。
- 走 `Logger` JSON，**不落库**；要「页面可查操作审计」需要新表 + 迁移，单开迭代。

### 列表接口新增字段

```json
{
  "canEdit": true,
  "canDelete": false,
  "dataCounts": { "papers": 3, "certificates": 1, "exams": 0 }
}
```
`canEdit = !isSelf && !isProtected`；`canDelete = canEdit && 无任何业务数据`；`isProtected = studentNo==='admin' || 含 SCHOOL_ADMIN 角色`。

## 六、已知边界 / 后续

1. **编辑班级会影响历史统计归属**：统计按用户**当前** `classId`/`userType` 分组（`statistics.service.ts`），改了班级/角色后，历史考试的分组会跟着变。这是既有口径的必然结果，不属于本次回归；若业务要求「历史归属冻结」，需在试卷/成绩表冗余班级快照（新迭代）。
2. **删除不可恢复**，且只对空账号开放；有数据账号的「改对」会保留原 `id`，成绩与证书仍挂原人。
3. **批量导入（UPSERT）不受本功能影响**：导入仍按模板覆盖字段，遇到重名/重号规则不变。李明阳那种「同一人两条教师号」仍需业务确认真实工号后手工处理（见 [[lab-exam-2026-11-17-账号与数据待办]] §一）。
4. 审计只在服务端日志，**没有页面可查**；如要「谁改了谁」可追溯，需新表 + 迁移 + 列表页。

## 十一、师生账号之外：考试能否改时间/删除（同日晚）

结论（代码 + 测试环境实测）：**考试只在「草稿」阶段可删，任何阶段都不能在界面上改时间**。

| 阶段 | 删除 | 改时间 | 只能做什么 |
|---|---|---|---|
| 草稿 DRAFT | ✅ 列表/详情都能删（级联删试卷） | ❌ 无界面入口（`PATCH /exams/:id` 后端支持 title/classId/startTime，但 `web` 里 `updateExam` 无任何调用点） | 删掉重建 |
| 已发布 PUBLISHED | ❌ 1404 | ❌ 1404 | 「关闭考试」后新建一场 |
| 已关闭 CLOSED | ❌ 1404 | ❌ 1404 | 新建一场 |

- 后端硬约束：`assertDraft` → 1404「考试已发布或已关闭，不可操作」；`remove` 同样只认 DRAFT；`Paper.exam onDelete: Cascade`。
- 时间窗口固定 3 天（`PUBLISH_WINDOW_DAYS = 3`，改开始时间时 endTime 自动 = start + 3 天）；开始时间不能早于当前（1407，60s 容差）；发布时若开始时间已过会**自动顺延到 1 分钟后**。
- 关闭只改考试状态、不动试卷（2026-11-10 起的口径），已关闭考试的未开考卷在统计里被排除，所以「关掉重建」不会给班级盖缺考。
- 测试环境实测：草稿改时间 `code=0` 且 endTime 自动 +3 天；已关闭考试改/删均 `1404`。
- 若业务需要「草稿期直接改时间而不删重建」，需在 `teacher/index.vue` 加编辑入口（复用现成 `updateExam`），属新迭代。
