## 7. 附录：CAS 接入预留设计

第一阶段不实装 CAS，但需在代码和文档层面预留接入点。以下内容基于 2026-07-06 确认的认证策略。

### 7.1 推荐方案 B：钉钉工作台内跳转 CAS

公司已有多个项目采用此方案，优先参考：

```
钉钉工作台打开应用
  ↓
前端路由守卫判断未登录
  ↓
跳转 CAS 统一身份认证登录页
  ↓
CAS 认证成功
  ↓
回调 /api/auth/cas/callback?ticket=xxx
  ↓
后端用 ticket 请求 CAS /serviceValidate
  ↓
解析 XML 获取 userId / userName / realName 等
  ↓
本地 MySQL FindOrCreate 用户（按学号/工号匹配）
  ↓
生成 JWT → URL 携带 token 重定向回前端
  ↓
前端存 token 并进入角色首页
```

### 7.2 需预留的后端接口

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/auth/cas/redirect` | 拼接 CAS 登录 URL（含 service 回调地址），重定向到 CAS |
| GET | `/api/auth/cas/callback?ticket=xxx` | 接收 CAS ticket，调 serviceValidate 校验，解析用户属性，签发 JWT |

### 7.3 需预留的配置项

```yaml
# cas.config.yaml
serverUrl: 'https://cas.school.edu.cn'
loginPath: '/login'
serviceValidatePath: '/serviceValidate'
serviceCallback: 'https://lab-exam.school.edu.cn/api/auth/cas/callback'
```

### 7.4 需预留的数据库字段

`users` 表增加：
- `cas_user_id` VARCHAR(64) nullable —— CAS 返回的用户标识
- `dingtalk_user_id` VARCHAR(64) nullable —— 钉钉用户标识（同步预留）

### 7.5 用户信息补全策略

CAS 返回的字段通常只含基础身份（学号/工号、姓名）。学院、班级、专业等信息可通过学校钉钉外部 API 补全：

| API | 地址 | 参数 | 用途 |
|-----|------|------|------|
| 学生扩展信息 | `https://dinglink.oceghome.com/DingDingLink/getStudentUserExtInfo` | `userCode` | 拿学号、班级、专业、学院 |
| 教职工扩展信息 | `https://dinglink.oceghome.com/DingDingLink/getTeacherUserExtInfo` | `userCode` | 拿工号、部门 |

> ⚠️ 这三个 API 是**数据查询接口**，不是认证协议。必须先通过 CAS/钉钉拿到 userCode/userId 才能调用。

### 7.6 备选方案 A：钉钉静默免登（待验证）

```
钉钉工作台打开应用
  ↓
前端加载 dingtalk.open.js JSAPI
  ↓
dd.runtime.permission.requestAuthCode({ corpId })
  ↓
拿到 authCode → POST /api/auth/dingtalk-login
  ↓
后端用 AppKey/AppSecret 换 access_token
  ↓
调钉钉 topapi/v2/user/getuserinfo 拿 userid
  ↓
调钉钉 topapi/v2/user/get 拿用户详情
  ↓
本地 MySQL FindOrCreate 用户 → JWT
```

**待验证点**：
1. D 盘文档里的 `userCode` 是否就是钉钉返回的 `userid`？
2. 外部系统直接调用学校钉钉 API 是否需要 token/appKey？
3. 拿到 userid 后能否直接跳转补全校内信息？

### 7.7 第一阶段落地建议

- 把认证抽象成 `AuthStrategy` 接口：
  - `LocalAuthStrategy`（第一阶段使用）
  - `CasAuthStrategy`（第二阶段实现）
  - `DingTalkAuthStrategy`（后续可选）
- 登录成功后的用户查找/创建、JWT 签发逻辑完全复用，只替换 "如何拿到学号/工号" 这一段。
- 第一阶段 `users` 表就预留 `cas_user_id` 和 `dingtalk_user_id`，避免第二阶段改表结构。
