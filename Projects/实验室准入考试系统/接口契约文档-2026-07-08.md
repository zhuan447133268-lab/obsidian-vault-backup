## 2. 基础约定

### 2.1 Base URL

| 环境 | 地址 |
|------|------|
| 本地开发 | `http://localhost:3000/api` |
| 测试环境 | `https://lab-exam-test.school.edu.cn/api` |
| 生产环境 | `https://lab-exam.school.edu.cn/api` |

### 2.2 HTTP 方法语义

| 方法 | 用途 |
|------|------|
| GET | 查询资源 |
| POST | 创建资源 / 执行动作 |
| PUT | 全量更新资源 |
| PATCH | 部分更新资源 |
| DELETE | 删除/禁用资源 |

### 2.3 认证方式（第一阶段）

**主方案：httpOnly Cookie + CSRF Token**

- 登录成功后，服务端通过 `Set-Cookie` 写入 `access_token`（httpOnly, Secure, SameSite=Lax）。
- 同时返回 `csrf_token`，前端需在后续请求头中携带 `X-CSRF-Token: <csrf_token>`。
- Token 有效期 2 小时，支持自动刷新（见 3.2）。

**备选方案：Bearer Token**

- 如果本地开发跨域调试困难，可临时切换为 `Authorization: Bearer <token>`。
- 切换方式：环境变量 `AUTH_MODE=bearer`。
- 前端需将 token 存内存（推荐）或 sessionStorage，**禁止 localStorage**。

### 2.4 通用请求头

```http
Content-Type: application/json
X-CSRF-Token: <csrf_token>    // 仅主方案需要
```

### 2.5 通用响应格式

```typescript
interface ApiResponse<T> {
  code: number;      // 业务状态码，0 表示成功
  message: string;   // 提示信息
  data: T;           // 业务数据
}
```

**成功示例：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": "uuid",
    "name": "张三"
  }
}
```

**失败示例：**

```json
{
  "code": 1001,
  "message": "用户名或密码错误",
  "data": null
}
```

### 2.6 HTTP 状态码与业务码关系

| HTTP 状态码 | 含义 |
|-------------|------|
| 200 | 请求成功 |
| 400 | 请求参数错误 |
| 401 | 未认证 / Token 过期 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 资源冲突 |
| 422 | 业务校验失败 |
| 429 | 请求过于频繁 |
| 500 | 服务端内部错误 |

> HTTP 状态码仅表示请求是否被正确处理，业务成功与否以 `code === 0` 为准。

## 3. 全局错误码

| 错误码 | 含义 | HTTP 状态码 | 触发场景 |
|--------|------|-------------|----------|
| 0 | 成功 | 200 | 一切正常 |
| 1000 | 通用错误 | 500 | 未分类的服务端错误 |
| 1001 | 用户名或密码错误 | 401 | 本地账号登录失败 |
| 1002 | Token 已过期 | 401 | access_token 过期且无法刷新 |
| 1003 | Token 无效 | 401 | Token 签名错误或格式错误 |
| 1004 | CSRF Token 缺失或错误 | 403 | 主方案下未携带或错误 |
| 1005 | 账号已被禁用 | 403 | 用户 status = 0 |
| 1006 | 账号未绑定身份信息 | 403 | CAS/钉钉登录后未匹配到本地用户 |
| 1100 | 无接口权限 | 403 | 角色不满足 `@Roles()` 要求 |
| 1101 | 数据越权 | 403 | 查询了角色范围外的数据 |
| 1200 | 请求参数校验失败 | 400 | DTO 校验失败 |
| 1201 | 资源不存在 | 404 | 根据 ID 未找到资源 |
| 1202 | 资源冲突 | 409 | 唯一约束冲突 |
| 1203 | 业务状态不允许 | 422 | 操作与当前状态机冲突 |
| 1300 | 文件解析失败 | 400 | Excel/CSV 格式错误 |
| 1301 | 导入数据校验失败 | 422 | 必填字段缺失或关联关系不存在 |
| 1400 | 请求过于频繁 | 429 | 触发限流 |

## 4. 认证接口

### 4.1 本地账号登录

**POST** `/auth/login`

#### 请求 DTO

```typescript
interface LoginRequest {
  account: string;      // 学号或工号
  password: string;     // 密码（第一阶段可为明文或 bcrypt 校验）
}
```

#### 响应 DTO

```typescript
interface LoginResponse {
  user: {
    id: string;
    name: string;
    account: string;            // 学号/工号
    roles: UserRole[];          // ['STUDENT', 'TEACHER', ...]
    collegeId?: string;
    collegeName?: string;
    classId?: string;
    className?: string;
    majorId?: string;
  };
  csrfToken: string;            // 主方案返回
  needChangePassword: boolean;  // 首次登录为 true，前端跳转修改密码页
}
```

#### 业务规则

- `account` 同时匹配 `student_no` 和 `staff_no`。
- 密码错误返回 `1001`，不暴露账号是否存在。
- 用户 status = 0 返回 `1005`。
- 登录成功后设置 httpOnly Cookie。

#### 错误码

- `1001`：用户名或密码错误
- `1005`：账号已被禁用
- `1200`：参数校验失败

---

### 4.2 刷新 Token

**POST** `/auth/refresh`

#### 说明

- 使用 httpOnly Cookie 中的 refresh_token 换取新的 access_token。
- 前端无需显式调用，由 Axios 拦截器在 401 时自动触发。

#### 响应 DTO

```typescript
interface RefreshResponse {
  csrfToken: string;            // 刷新后返回新 CSRF Token
}
```

#### 错误码

- `1002`：refresh_token 过期或无效

---

### 4.3 登出

**POST** `/auth/logout`

#### 说明

- 清除服务端会话/Redis 中的 Token 黑名单。
- 清除客户端 Cookie。

#### 响应 DTO

```typescript
interface LogoutResponse {
  success: true;
}
```

### 4.4 获取当前登录用户

**GET** `/auth/me`

#### 响应 DTO

```typescript
interface MeResponse {
  id: string;

  account: string;
  roles: UserRole[];
  dataScope: {
    type: 'ALL' | 'COLLEGE' | 'CLASS' | 'SELF';
    collegeIds?: string[];

  };
  collegeId?: string;
  collegeName?: string;
  classId?: string;
  className?: string;
  majorId?: string;
  majorName?: string;
}
```

#### 数据范围规则

| 角色 | dataScope.type | 说明 |
|------|----------------|------|
| SCHOOL_ADMIN | ALL | 全校数据 |
| COLLEGE_ADMIN | COLLEGE | 所管学院数据 |
| TEACHER | CLASS | 所带班级数据 |
| STUDENT | SELF | 仅自己数据 |

## 5. 用户与权限接口

### 5.1 用户列表

**GET** `/users`

#### 查询参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| role | UserRole | 否 | 按角色筛选 |
| collegeId | string | 否 | 按学院筛选 |
| classId | string | 否 | 按班级筛选 |
| keyword | string | 否 | 姓名/学号/工号模糊搜索 |
| page | number | 否 | 页码，默认 1 |
| pageSize | number | 否 | 每页条数，默认 20 |

#### 响应 DTO

```typescript
interface UserListResponse {
  list: UserListItem[];
  total: number;
  page: number;
  pageSize: number;
}

interface UserListItem {
  id: string;
  name: string;
  studentNo?: string;
  staffNo?: string;
  userType: 1 | 2;              // 1=教职工, 2=学生
  roles: UserRole[];
  collegeId?: string;
  collegeName?: string;
  majorId?: string;
  majorName?: string;
  classId?: string;
  className?: string;
  status: 0 | 1;
  createdAt: string;
}
```

#### 权限

- SCHOOL_ADMIN：可查看全部
- COLLEGE_ADMIN：仅查看本学院
- TEACHER：仅查看所带班级
- STUDENT：不可调用

### 5.2 批量导入用户（学院/班级/学生/教师）

**POST** `/users/import`

#### 请求 DTO

```typescript
interface UserImportRequest {
  file: File;                   // multipart/form-data 上传
  mode: 'UPSERT' | 'SKIP';      // 默认 UPSERT，遇到已存在学号/工号时更新或跳过
}
```

#### 响应 DTO

```typescript
interface UserImportResponse {
  success: boolean;
  total: number;                // 总记录数
  successCount: number;         // 成功数
  failCount: number;            // 失败数
  errors: ImportErrorItem[];
  stats: {
    colleges: number;
    classes: number;
    users: number;
    roles: number;
    teachers: number;
  };
}

interface ImportErrorItem {
  row: number;                  // Excel 行号
  field?: string;               // 出错字段
  message: string;              // 错误描述
  rawData: Record<string, any>; // 原始数据
}
```

#### 业务规则

- 仅 SCHOOL_ADMIN 可调用。
- Excel 模板字段见《基础数据导入模板说明》。
- 导入在数据库事务内执行，失败时全部回滚。
- 学生默认角色 STUDENT，教师默认角色 TEACHER。

#### 错误码

- `1100`：无权限
- `1300`：文件解析失败
- `1301`：导入数据校验失败

## 11. 已确认事项

### 确认内容（2026-07-08）

1. **密码策略**：第一阶段统一初始密码为 `123456`，首次登录强制修改密码。管理员重置密码功能延后到第二阶段。
2. **Token 刷新机制**：采用双 Token 方案。`access_token` 有效期 2 小时，`refresh_token` 有效期 7 天且存 httpOnly Cookie；本地开发阶段可临时使用 Bearer Token。
3. **CSRF 方案**：本地开发关闭 CSRF（配合 Bearer Token），测试/生产环境启用 CSRF（配合 httpOnly Cookie）。
4. **导入文件格式**：基础数据导入使用 Excel（`.xlsx`），单个文件最大 10MB。字段名先按本文档约定实现，收到学校真实导出文件后仅做字段映射调整。
