# 生产环境数据库导入完整清单

> 触发条件：用户说「导入数据库信息」时，自动调取本清单并执行全部导入，避免遗漏。
> 数据来源目录：`D:\2026准入题库\数据文档` 和 `D:\2026准入题库\题库题目`
> 目标数据库：生产环境 MySQL（连接串以生产部署后的实际为准）

## 一、导入前准备

1. 确认生产环境数据库已创建并跑完 Prisma migrations
2. **不要跑 `prisma db seed`**（seed 会插入测试数据）
3. 确认 admin 账号可用或准备创建
4. 备份生产数据库（上线前必须配置自动备份，见 [[todo_database_backup_before_launch]]）

## 五、常见问题

**Q：教师为什么无法创建考试？**
A：教师需要先在「教师分班管理」页面分配带课班级。实验教师名单 Excel 中没有班级信息，需要额外分配规则或手动分配。

**Q：学校管理员被误删怎么办？**
A：按步骤 2 重新创建。关键：管理员账号不在教师/学生名单中，必须在导入基础数据后单独恢复。

### 2026-08-28 导入方式改为 SQL 文件 + admin upsert 修复

**变更原因**：
- 运维更熟悉 SQL 文件执行方式，便于审计和回滚。
- 原 `01_user_data.sql` 只保留已有 admin，存在生产库无 admin 时系统无法初始化的风险。

**当前交付物**：

| 文件 | 路径 | 说明 |
|---|---|---|
| 人员数据 SQL | `D:\claude-work\lab-exam\01_user_data.sql` | 含学院/专业/班级/教师/学生/学校管理员/admin |

| 生成脚本 | `D:\claude-work\lab-exam\generate_import_sql.py` | 不连库，仅生成 SQL |

**执行步骤（更新）**：

1. 备份生产数据库
2. 确认已执行 `npx prisma migrate deploy`
3. 禁止执行 `npx prisma db seed`
4. 执行人员数据 SQL：
   ```bash
   mysql -u {用户名} -p{密码} -h {主机} -P {端口} {数据库名} < 01_user_data.sql
   ```
5. 执行题库数据 SQL：
   ```bash
   mysql -u {用户名} -p{密码} -h {主机} -P {端口} {数据库名} < 02_question_data.sql
   ```
6. 使用 `admin-password.txt` 中的密码登录 admin 账号

**关键修复**：
- admin 账号使用 `INSERT ... ON DUPLICATE KEY UPDATE` 创建/更新，确保无论生产库是否已有 admin，执行后都存在。
- 学校管理员沈春洋（BN100005453）、陈冰冰（IME000290）仍会恢复。
- 判断题答案格式统一为 `["TRUE"]` / `["FALSE"]`，与测试环境一致。
