## 重要业务规则

### 1. 模块名称带"学前"前缀

| 旧名（我之前的设计） | 阳阳确认名 |
|---|---|
| 集团经营看板 | **学前经营看板** |
| 预算分析表 | **学前预算分析表** |
| 出纳管理员 / 预算分析管理员 | **学前预算分析管理员** |

**业务含义**：系统专属服务于学前业务（幼儿园），未来可能扩展中小学等其他业务线，因此模块命名带"学前"前缀加以区分。

### 2. 集团管理员完全不进入本模块

- 集团管理员是余额表系统的角色，不参与经营分析
- 5 个页面全部 ❌ 无权限
- 前端不显示"经营分析"模块入口

### 3. 区域财务主管看不到"学前经营看板"

- 区域财务主管只能看自己管辖区域的数据
- 集团整体看板（学前经营看板）= 没有权限
- 园所列表、单园看板、预算分析表 = ▲ 仅看本区域

### 4. 园长权限最收敛

- 只能看 2 个页面：单园经营看板 + 学前预算分析表
- 都限制为「仅本园」
- 不能看园所列表，不能看任何集团/区域级数据

### 5. 老板/运营总监权限相同

- 5 个页面中 4 个有权限（除"数据上传"）
- 看完整集团数据，不受区域/园所限制

### 6. 学前预算分析管理员是全权角色

- 唯一有"数据上传"权限的角色
- 5 个页面全部 ✅

## 对开发的影响

### 路由权限（设计文档 06 修订）

```
路由前缀：/api/v1/analysis/

POST   /upload                       → 仅 preschool_budget_admin
GET    /gardens                      → preschool_budget_admin / boss / operation_director / region_finance(过滤区域)
GET    /garden/:code                 → preschool_budget_admin / boss / operation_director /
                                       region_finance(过滤区域) / principal(过滤本园)
GET    /preschool-dashboard          → preschool_budget_admin / boss / operation_director
GET    /budget-analysis              → preschool_budget_admin / boss / operation_director /
                                       region_finance(过滤区域) / principal(过滤本园)
```

### 前端菜单显隐

```typescript
const menuVisibility = {
  preschool_budget_admin: [upload, gardens, garden, preschoolDashboard, budgetAnalysis],  // 5 项
  boss:                   [        gardens, garden, preschoolDashboard, budgetAnalysis],  // 4 项
  operation_director:     [        gardens, garden, preschoolDashboard, budgetAnalysis],  // 4 项
  region_finance:         [        gardens, garden,                     budgetAnalysis],  // 3 项
  principal:              [                 garden,                     budgetAnalysis],  // 2 项
  group_admin:            [],                                                              // 不显示经营分析模块
}
```

### 数据过滤逻辑

- `region_finance`：所有响应数据必须按 `region` 字段过滤
- `principal`：所有响应数据必须按 `principal_company_mapping` 表过滤
