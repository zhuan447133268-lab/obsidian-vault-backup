## ⚠️ 2026-06-22 修订：V4公式完整链路

阳阳通过 `预算分析BI数据-V4.xlsx`「报表计算关系」Sheet 确认了完整的利润计算链路。

### EBITDA = 收入合计 − 成本费用合计 + 营业外收入 − 营业外支出

```
计算步骤：
1. 收入合计 = 学费 + 餐费 + 政府补助 + SUM(其他业务收入8子项)
2. 成本费用合计 = 人工 + 食堂 + 其他业务成本 + 行政费用 + 日常费用 + 市场费用 + 外部服务费
3. EBITDA = 收入合计 + 成本费用合计(负数) + 营业外收入 + 营业外支出(负数)
   → Excel原始公式: =SUM(收入合计, 成本费用合计, 营业外收入, 营业外支出)
   → 对应数据列: BO列(直接取)
```

### 税后利润 = EBITDA − 折旧摊销 − 利息 − 所得税 − 调整项

```
4. 税后利润 = EBITDA + 折旧摊销(负数) + 利息(负数) + 所得税(负数) + 调整项(负数)
   → Excel原始公式: =SUM(EBITDA:调整项)
   → 对应数据列: BS列(直接取)
   → ⚠️ v3.3新增: 调整项是独立科目，落在折旧/利息/所得税之后
```

### 最终利润 = 税后利润 + 以前年度损益调整

```
5. 最终利润 = 税后利润 + 以前年度损益调整
   → Excel原始公式: =SUM(税后利润:以前年度损益调整)
```

### 达成率

```
达成率 = 累计实际(YTD S列) ÷ 累计期间预算(期间预算表 R列)
统一口径：看板KPI、数字卡片、明细表全部使用此公式
全年预算仅作目标参考展示，不参与达成率计算
```

## 二、阶段1：文件上传（Upload Phase）

### 入口

```
POST /api/v1/analysis/upload
Content-Type: multipart/form-data

Fields:
  - period: "2026-04"
  - files: [6个Excel文件]

文件识别规则（按文件名关键词）：
  "2026年" + "1-N月" + "实际报表" → ytd_actual（当年YTD累计）
  "2025年" + "1-N月" + "实际报表" → ytd_actual_ly（去年YTD累计）
  "2026年" + "N月" + "实际报表"   → month_actual（当年单月）
  "2025年" + "N月" + "实际报表"   → month_actual_ly（去年单月）
  "全年预算[财年]"                → year_budget（全年预算）
  "期间预算[期间]"                → period_budget（期间预算）
```

### 处理流程

```go
func (s *AnalysisUploadService) HandleUpload(period string, files map[string]*multipart.FileHeader, userID uint) (uint, error) {
```

## 三、阶段2：Excel解析（Parse Phase）

### 各文件结构差异

| 文件类型 | 首列(B) | 公司名称列 | 总列数 | 示例行数 |
|---|---|---|---|---|
| 累计实际(ytd_actual) | 城市 | C 列 | 80 | 131 |
| 单月实际(month_actual) | 区域名称 | C 列 | 83 | 131 |
| 全年预算(year_budget) | 公司名称 | **B** 列⚠️ | 79 | 143 |
| 期间预算(period_budget) | 公司名称 | **B** 列⚠️ | 79 | 143 |

> ⚠️ **预算表没有"城市/区域"列，公司名称在B列**；实际报表公司名称在C列。

### 解析逻辑（⚡ 修正：按内容匹配，不按行号）

```go
func (s *AnalysisUploadService) parsePhase(uploadID uint, files map[string][]byte) ([]RawDataRow, error) {
    s.uploadRepo.UpdateStatus(uploadID, "parsing")
    var allRows []RawDataRow

    for fileKey, data := range files {
        nameCol := getNameColumn(fileKey) // 实际报表=2(C列), 预算表=1(B列)

        f, _ := excelize.OpenReader(bytes.NewReader(data))
        rows, _ := f.GetRows(f.GetSheetName(0))
        headers := rows[3] // 第4行表头

        for i := 4; i < len(rows); i++ {
            row := rows[i]
            if nameCol >= len(row) { continue }
            gardenName := strings.TrimSpace(row[nameCol])
            if gardenName == "" { continue }

            // ⚠️ 规则：按内容特征判定，严禁绑定行号
            // 因为业务方确认"只有新开园/关园增减行"，排序规则不固定
            if isAggregateRow(gardenName) {
                continue // 丢弃板块汇总行
            }

            rowMap := buildRowMap(headers, row)
            gardenCode := extractGardenCode(gardenName)
            gardenStatus := detectGardenStatus(gardenName)

            allRows = append(allRows, RawDataRow{
                GardenCode:   gardenCode,
                GardenName:   gardenName,
                GardenStatus: gardenStatus,
                DataType:     fileKey,
                Period:       period,
                RawData:      rowMap,
                RowIndex:     i + 1,
            })
        }
    }
    s.rawDataRepo.BatchInsert(uploadID, allRows)
    return allRows, nil
}

// extractGardenCode 从公司名称提取园所编码
// "1001北京市昌平区育树家幼儿园" → "1001"
// "B102上海谨蜂幼儿园有限公司（关园）" → "B102"
func extractGardenCode(name string) string {
    re := regexp.MustCompile(`^([A-Z]?\d+)`)
    return re.FindString(name)
}

// detectGardenStatus 识别园所状态（全角括号）
func detectGardenStatus(gardenName string) string {
    if strings.Contains(gardenName, "（关园）") {
        return "closed"
    }
    return "active"
}

// ⚠️ 关键：按内容特征判定，严禁绑定行号
// isAggregateRow 判定该行是否为板块汇总行
// 当前客观事实：板块汇总行公司名称为"010115学前板块幼儿园"
// 判定逻辑：名称包含"板块"字样
func isAggregateRow(gardenName string) bool {
    return strings.Contains(gardenName, "板块")
}
```

## 四、阶段3：园所识别（Identify Phase）

### 设计要点

```
基准表选择：
┌─────────────────────────────────────────────────────────┐
│  ✅ 必须以「预算表」为主表                               │
│  原因：预算表是年初做的，包含全部历史园所（含历史关园）    │
│                                                         │
│  ❌ 不能以「实际报表」为主表                              │
│  原因：实际报表只含当年实际经营的园（131个），漏历史关园  │
└─────────────────────────────────────────────────────────┘

过滤规则（内容匹配，不绑定行号）：
  IF 公司名称包含"板块"   → 丢弃（板块汇总行，不是真实园所）
  IF 公司名称包含"（关园）" → 标记 closed（不生成单体看板/Excel）
  ELSE                     → 标记 active（生成单体看板/Excel）
```

### 实现逻辑

```go
func (s *AnalysisComputeService) identifyGardens(uploadID uint, allRows []RawDataRow) (
    activeGardens, closedGardens []GardenInfo, err error,
) {
    s.uploadRepo.UpdateStatus(uploadID, "identifying")

    // 从预算表提取园所主列表（板块汇总行已在解析阶段被 isAggregateRow 丢弃）
    budgetRows := filterByDataType(allRows, "year_budget")

    // 按 garden_code 去重，按 garden_status 分类
    seen := make(map[string]GardenInfo)
    for _, row := range budgetRows {
        if _, exists := seen[row.GardenCode]; exists { continue }
        seen[row.GardenCode] = GardenInfo{
            Code: row.GardenCode, Name: row.GardenName, Status: row.GardenStatus,
        }
    }

    for _, g := range seen {
        if g.Status == "closed" {
            closedGardens = append(closedGardens, g)
        } else {
            activeGardens = append(activeGardens, g)
        }
    }

    s.uploadRepo.UpdateCounts(uploadID, len(activeGardens), len(closedGardens))

    return activeGardens, closedGardens, nil
}
```

## 五、阶段4：数据校验（Validate Phase）

```go
func (s *AnalysisComputeService) validatePhase(activeGardens []GardenInfo, allRows []RawDataRow) []ValidationError {
    var errors []ValidationError
    for _, g := range activeGardens {
        gRows := filterByGardenCode(allRows, g.Code)
        types := uniqueDataTypes(gRows)
        required := []string{"ytd_actual", "month_actual", "ytd_actual_ly", "month_actual_ly", "year_budget", "period_budget"}
        for _, req := range required {
            if !contains(types, req) {
                errors = append(errors, ValidationError{
                    GardenCode: g.Code, Reason: fmt.Sprintf("缺少数据: %s", req), Severity: "error",
                })
            }
        }
    }
    return errors
}
```

```go
func (s *AnalysisComputeService) generatePhase(uploadID uint, activeGardens, closedGardens []GardenInfo) error {
    gardens, _ := s.gardenRepo.ListByUpload(uploadID)
    for _, g := range gardens {
        cache := buildGardenDashboardCache(g)
        s.cacheRepo.Upsert(uploadID, g.GardenCode, cache)
    }
    groupCache := buildGroupDashboardCache(gardens, len(activeGardens), len(closedGardens))
    s.cacheRepo.Upsert(uploadID, "group", groupCache)
    s.uploadRepo.UpdateStatus(uploadID, "completed")
    return nil
}
```

## 八、关键约束总结（开发必读）⚡

```
1.  公司名称列位置：实际报表 C列 / 预算表 B列
2.  园所编码 = 公司名称前缀的"数字"或"字母+数字"组合
3.  关园标记 = 名称含"（关园）"（全角括号）
4.  ⚠️ 板块汇总行 = 名称含"板块"，按内容匹配筛选，**严禁绑定行号**
5.  园所主列表来源 = 预算表（不是实际报表）
6.  实际数据 LEFT JOIN 预算表园所，关园园所实际数据为NULL
7.  仅在营园所计算指标、生成看板/Excel，关园数据保留供同比
8.  取数方式：按字段名从 headerMap 查找，**禁止硬编码列号**
```
