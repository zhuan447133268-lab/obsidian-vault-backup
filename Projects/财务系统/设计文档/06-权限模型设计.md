当前 V1.0 余额表系统有 3 种角色：

| 角色值 | 角色名 | 与经营分析的关系 |
|---|---|---|
| `group_admin` | 集团管理员 | ❌ 不参与经营分析模块 |

## 五、`principal_company_mapping` 运维约定 ⭐

### 5.1 核心原则：映射只增不删

```
principal_company_mapping 的运维约束：
  ├── 园长调岗到新园     → 增加新映射（不删除旧映射）
  ├── 园长离职           → 企微停用自然失效，映射保留不动
  ├── 关园归属园长       → 映射保留不动（历史看板可读）
  └── 映射永不删除       → 避免破坏历史看板访问权
```

### 5.2 园长调岗场景完整闭环

```
场景：张园长 2026-07 从已关 1001 园调岗到 1002 园

管理员操作：
  principal_company_mapping 从 [1001] 改为 [1001, 1002]
  （只加不删，1001 映射保留）

张园长看当期（2026-07 批次）：
  1001（已关园）→ 标记"已关园"，无当期数据
  1002（在营）  → 正常看板

张园长翻阅历史（2026-04 批次）：
  1001 → ✅ 正常看，因为映射仍保留 [1001, 1002]
```

## 六、园长权限的数据过滤

```go
func (h *AnalysisHandler) ListGardens(c *gin.Context) {
    userID := c.GetUint("userID")
    userRole := c.GetString("userRole")

    var gardenCodes []string
    if userRole == "principal" {
        mappings, _ := h.principalMappingRepo.FindByPrincipalID(userID)
        for _, m := range mappings {
            gardenCodes = append(gardenCodes, m.Company.Code)
        }
        if len(gardenCodes) == 0 {
            response.Success(c, gin.H{"list": []interface{}{}, "total": int64(0)})
            return
        }
    }
    if userRole == "region_finance" {
        // 按当前用户的 region 字段过滤
        gardens, total, _ := h.analysisService.ListGardensByRegion(uploadID, currentUser.Region, page, size)
        response.Success(c, gin.H{"list": gardens, "total": total})
        return
    }
    gardens, total, _ := h.analysisService.ListGardens(uploadID, keyword, "active", gardenCodes, page, size)
    response.Success(c, gin.H{"list": gardens, "total": total})
}
```

## 七、关园后园长访问控制（依赖企微统一身份认证）

```
园所关园 → 新批次不生成该园看板
           │
           ├── 园长企微在职 → 能登录 → 看历史看板（无新数据）
           ├── 园长企微停用 → 无法 OAuth → 自动失去访问权
           └── 园长调岗     → 映射只增不删 → 旧园历史仍可看
```

系统不需要主动维护园长账号状态。企微统一身份认证是最终的访问控制闸门。

## 九、权限判断完整流程图

```
用户请求 /api/v1/analysis/garden/1001
         │
         ▼
    JWT 中间件（实时查库，企微停用即失效）
         │
         ▼
    RoleAuth 中间件（检查角色是否在路由允许列表中）
         │
         ├── group_admin → 403（不参与经营分析）
         │
         ▼
    Handler: 按角色执行数据过滤
         ├── region_finance → WHERE region = current_user.region
         ├── principal → JOIN principal_company_mapping
         └── 其他角色 → 无额外过滤
```

## 十、安全考量

1. **园长不能看其他园**：Service 层校验 `principal_company_mapping`
2. **区域财务主管不能跨区域**：Service 层按 `region` 字段过滤
3. **集团管理员完全隔离**：路由级拒绝访问（返回 403）
4. **映射只增不删**：调岗/关园时保留历史访问权，运维零负担
5. **账户停用即时生效**：JWT 实时查库，企微停用即无法登录
6. **学前预算分析管理员不访问余额表模块**：路由级隔离
7. **老板/运营总监只看不传**：前端隐藏上传入口 + 后端拒绝 POST upload
8. **角色可叠加**：一个用户可同时拥有多个角色
