### 预算负值根因待查

`PROF_002=-604458.76` 尚未确认是数据脏还是 `val()` 取错行——需查 `analysis_raw_data` 表原始值才能断定。⚠️待阳阳新数据 + 用户确认后处理。

## 二、反思：把"出勤学生"描述成"出勤趋势"

### 客观事实（grep 代码）

- 展示标题（GardenDashboard.vue:107）：`在册 vs 出勤学生` ✅ 用户说的对
- 底层变量名：`attendanceTrendRef` / `attendanceTrend` / 后端字段 `attendanceTrend` —— 全带 trend
- 另一板块（:78）：`月度收入与利润趋势` 才是真"趋势"

### 根因两层

1. **昨天改名只改了一半**：展示标题从"在册vs出勤趋势"改成"在册vs出勤学生"，但底层变量名/字段名没跟着改，代码里"趋势"和"学生"两套词并存——自己埋的雷
2. **今天描述时凭变量名 `trend` 印象翻成中文"出勤趋势"**，没去核对实际渲染标题。违反第一准则（基于客观事实判断）

### 同类错误清单

| 错误 | 本质 |
|---|---|
| "出勤趋势"vs"出勤学生" | 凭变量名印象描述UI文案，不核对 |
| 改名只改展示层、底层变量名留着 | 改一半留技术债 |
| 描述现状时引用memory旧名/旧印象而非grep当前值 | 凭记忆不凭客观事实 |

### 避免方法（改名3规则）

1. 描述任何用户可见文案/板块名，必须 grep 代码当前真实值，不凭记忆/变量名印象
2. 改名要改全：展示标题 + 变量名 + 字段名 + memory 记录，一层都不能漏
3. memory 里旧名要标注"已改名"，防止以后引用旧名
