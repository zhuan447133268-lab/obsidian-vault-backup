## 一、系统概述

余额表管理系统是一个 B/S 架构的财务数据管理平台，用于管理集团下各幼儿园的银行账户余额数据。核心流程是：从 Oracle BI 同步账面数据 → 出纳填写实际余额 → 区域管理员审核 → 集团管理员看板汇总。

### 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Go 1.26 + Gin + GORM + MySQL 8.0 |
| 前端 | Vue 3 + TypeScript + Element Plus + Vite |
| 认证 | JWT（HS256）+ 企业微信 OAuth + 密码登录 |
| 部署 | Docker Compose（后端:8094, 前端 Nginx:80） |
| 外部数据 | Oracle BI（只读，同步源） |

## 二、角色体系

### 2.1 三种角色

| 角色 | 字符串值 | 权限范围 |
|---|---|---|
| 集团管理员 | `group_admin` | 全部功能：数据同步、查看全集团数据、修改、关账、用户管理、系统配置 |
| 区域管理员 | `region_admin` | 审核本区域出纳提交的数据、汇总提交、查看本区域修改日志 |
| 出纳 | `cashier` | 填写自己负责园所的余额数据、提交 |

### 2.2 多角色机制

- `users.role` 字段存储逗号分隔的多个角色（如 `"cashier,region_admin"`）
- `User.HasRole(role)` 方法通过字符串包含判断
- JWT 中间件从数据库实时读取角色（非 JWT 快照），管理员调整角色即时生效
- 前端路由守卫按 `roles` meta 字段过滤页面可见性

### 2.3 认证流程

1. **生产环境**：企业微信 OAuth → 回调获取 wecom_userid → 匹配本地用户 → 生成 JWT
2. **开发环境**：`POST /api/v1/auth/dev-login` 直接用工号登录（仅 debug 模式）
3. **密码登录**：`POST /api/v1/auth/password-login`（仅 group_admin 可用）
4. JWT 有效期 24 小时，支持单点登录（新登录使旧 session_token 失效）
5. 账户停用后 JWT 立即失效（中间件实时查库）

## 四、核心业务流程：余额表填写与审核

### 4.1 状态机

```
                    ┌──────────┐
                    │ pending  │  ← 同步后初始状态（待填写）
                    └────┬─────┘
                         │ 出纳填写(Fill)
                    ┌────▼─────┐
                    │  draft   │  ← 已暂存（可继续编辑）
                    └────┬─────┘
                         │ 出纳提交(Submit)
                    ┌────▼─────┐
                    │submitted │  ← 已提交至区域管理员
                    └────┬─────┘
                    ┌────┴─────┐
                    │          │
              区域确认   标记异常(MarkAnomaly)
                    │          │
              ┌─────▼──┐  ┌───▼────┐
              │confirmed│  │anomaly │──→ 出纳重新填写 → submitted
              └────┬────┘  └────────┘
                   │ 区域汇总提交
              ┌────▼──────┐
              │submitted  │  ← region_submitted（已汇总）
              └───────────┘
```

**关键规则**：
- 出纳修改已提交/已确认的数据时，状态回退为 `submitted`，清除区域确认信息，重新进入审核流程
- 集团管理员修改不触发回退（越权覆盖）
- 关账后所有角色不可修改（集团管理员除外）

### 4.2 完整流程（按角色分步）

```
步骤1: 数据同步 (集团管理员)
  ┌─────────────────────────────────────────┐
  │ 集团管理员点击"同步"                       │
  │ → 后端连接 Oracle BI，查询 ai_bank_fact   │
  │ → 按园所编码+账号匹配，写入 balance_records │
  │ → fill_status = "pending"                │
  │ → 记录 sync_batches 批次                  │
  │ → 可发送企微通知给相关人员                  │
  └─────────────────────────────────────────┘

步骤2: 出纳填写 (出纳)
  ┌─────────────────────────────────────────┐
  │ 出纳登录 → 看到自己负责的园所列表            │
  │ （通过 cashier_company_mapping 关联）      │
  │ → 选择账期(月份) + 类型(半月报/月报)        │
  │ → 查看账面金额(book_amount)               │
  │ → 填写实际金额(actual_amount)             │
  │ → 如有差异，必填差异说明(diff_reason)       │
  │ → 保存为草稿(fill_status = "draft")      │
  │ → 可以继续编辑                             │
  │ → 确认无误后"提交"（单条或批量）             │
  │ → fill_status = "submitted"             │
  └─────────────────────────────────────────┘

步骤3: 区域审核 (区域管理员)
  ┌─────────────────────────────────────────┐
  │ 区域管理员登录 → 看到本区域的已提交数据      │
  │ （通过 regions.admin_user_id 关联）       │
  │ → 核对实际金额 vs 账面金额                 │
  │ → 确认无误 → RegionConfirm              │
  │   → fill_status = "region_confirmed"    │
  │ → 数据有误 → MarkAnomaly                │
  │   → fill_status = "anomaly"             │
  │   → 出纳重新填写后回到 submitted          │
  │ → 全部审核完毕后"汇总提交"                  │
  │   → 写入 region_submissions 表           │
  └─────────────────────────────────────────┘

步骤4: 集团总览 (集团管理员)
  ┌─────────────────────────────────────────┐
  │ 集团管理员查看全集团数据                    │
  │ → 可按区域/状态/关键词筛选                 │
  │ → 可直接修改任何记录(Modify)              │
  │ → 可清除异常状态(ClearAnomaly)           │
  │ → 可导出CSV                              │
  │ → 可关账/开账(PeriodClosure)             │
  └─────────────────────────────────────────┘

步骤5: 数据看板 (集团管理员)
  ┌─────────────────────────────────────────┐
  │ 选择账期+类型 → 查看汇总卡片+明细表         │
  │ → 汇总卡片: 账面总额 / 已确认实际总额 / 差异  │
  │ → 明细表: 支持合并/非合并视图               │
  │ → 支持排序(账面/实际/差异)                  │
  │ → 支持按区域/园所筛选                      │
  └─────────────────────────────────────────┘
```

## 七、关键业务规则

### 7.1 权限校验

1. **出纳只能看到自己负责的园所数据**：通过 `cashier_company_mapping` 表 JOIN 查询
2. **区域管理员只能看到本区域数据**：通过 `regions.admin_user_id` 匹配
3. **区域停用后区域管理员无法查看/操作**：`region.Status != 1` → 返回空列表或拒绝
4. **区域管理员账号停用后出纳无法提交**：防止数据提交后无人审核
5. **多角色用户按优先级校验**：先按 cashier 校验，不通过再按 region_admin

### 7.2 关账机制

- 关账后，所有非集团管理员无法修改数据
- 关账以 `period + sync_type` 为粒度（如 "2026-06" + "half"）
- 集团管理员不受关账限制

### 7.3 操作日志

- 所有写操作（fill/submit/confirm/modify/anomaly 等）都记录到 `operation_logs`
- 包含操作前后数据快照（before/after JSON）
- 支持按目标记录查询修改历史

## 九、新增模块可复用的部分

为经营分析看板模块迭代，以下是现有系统中可以直接复用或参考的部分：

| 复用项 | 说明 |
|---|---|
| 用户模型 `users` | 新增角色只需在 role 字段中加入新值，`HasRole()` 自动支持 |
| 角色中间件 `RoleAuth` | 传入新角色名即可控制权限 |
| 园所模型 `companies` | 已有 `code`（园所编码）和 `name`，可直接关联 |
| 园所编码体系 | 现有系统用 `code` 字段（如 "1001"），与原始表中的园所编码对应 |
| JWT 认证体系 | 完全复用，无需修改 |
| 统一响应格式 | `response.Success/Error` 直接使用 |
| Layout 侧边栏 | 在 `allModules` 中新增模块定义即可 |
| 路由守卫 | 在 `meta.roles` 中加新角色即可 |
| 前端 API 封装 | `utils/request.ts` 的 `get/post/put/del` 直接使用 |
| 操作日志 | 可复用 `operation_logs` 表记录上传操作 |
| Pinia Store | 可扩展 `user.ts` 增加新角色的计算属性 |
| Element Plus 组件 | 完整可用 |
