## 一、需求背景

**阳阳 0623 原话需求：**
> 学前预算分析表那页的表里面，现在有 YTD实际列、期间预算列、期间预算达成率，并排的。想加单月预算达成率，算法就是单月实际除以单月预算。

**口径确认（6/24 全部定稿）：**
- 每月阳阳上传 **7 张表**（原 6 张 + 新增「单月预算」表）
- 累计达成率 = 累计实际 ÷ 累计期间预算（现有，**不动**）
- 单月达成率 = 单月实际 ÷ 单月预算（**本次新增**）
- 期间预算 = 累计1-N月预算（阳阳6/24下午补传，验证通过）
- 单月预算 = 仅N月单月预算（02.单月预算表）

**对称 4 指标**（与累计达成率一致）：总收入 / EBITDA / 成本费用 / 延时服务利润

## 二、现有代码情况（已逐文件核实）

### 2.1 上传入口 `analysis_upload_service.go:24`
```go
if len(files) != 6 {
    return 0, fmt.Errorf("请上传恰好6个文件（当前%d个）", len(files))
}
```
**硬编码 6**，必须放开为 6 或 7（单月预算可选，兼容未传场景）。

### 2.2 文件类型识别 `analysis_parser.go` `IdentifyFileType`
- 现识别 6 类：`year_budget / period_budget / ytd_actual / month_actual / ytd_actual_ly / month_actual_ly`
- **无 `month_budget`**，需新增
- `parseExcelSheet`：预算表（year_budget/period_budget）走 `nameCol=1`（B列），单月预算表结构与期间预算完全一致，**复用即可，无需改 parseExcelSheet 主体**

### 2.3 数据模型 `analysis_garden.go` `AnalysisGardenData`
现有预算字段（累计期间预算，带 PBudget 后缀）：
```
SRevTotalPBudget / SCost001PBudget / SProf002PBudget / SProf010PBudget / SKpi001PBudget / SKpi002PBudget
```
**无单月实际 / 单月预算字段，需新增。**

### 2.4 计算逻辑 `analysis_compute.go` `computeOneGarden`
- line 49: `periodBudget := filterByType(rows, "period_budget")`
- line 165-168: 单月实际**只存了人数类**（SKpi001-004 取自 monthActual）
- **收入/EBIT/成本/延时利润的单月实际值未存**，需新增
- 现有累计达成率分母取 `periodBudget` 的 PROF_006 等

### 2.5 达成率展示 `BudgetAnalysis.vue`（学前预算分析表页）
现有列：编码/园所名/YTD收入/YTD EBITDA/YTD税后利润/YTD折旧摊销/全年预算收入/期间预算EBITDA/收入达成率/EBITDA率/EBITDA达成率/税后利润达成率/学生/员工
- 达成率用前端 `fmtPct(actual, budget)` 算：`((actual||0)/budget*100).toFixed(1)+'%'`
- `fmtW(v)` 万元换算

### 2.6 接口 `GetBudgetAnalysis` handler
直接返回整行 `AnalysisGardenData`（`ListGardenData` → `response.Success`），**新增字段自动随 JSON 返回，handler 不用改**。

### 2.7 GORM AutoMigrate
`AnalysisGardenData` 加字段后，启动时 AutoMigrate 自动加列，**无需手写 SQL**。

## 五、注意事项 ⚠️

### 5.1 代码范围规范（精准修改原则）
- **只碰必须碰的**：5 个文件，每行改动可追溯到"单月达成率"需求
- **不动**：累计达成率逻辑、其他看板图表、EAV解析主体、科目字典、关园识别
- **不重构**：不顺手改相邻代码风格

### 5.2 数据格式规范
- 所有金额字段 **decimal(18,2)**，与现有字段一致
- 成本/费用类在源数据中为**负数**，计算时**直接带符号相加**，不用 abs()
- 延时利润 = REV_005 + COST_004（COST_004 负数），结果正=盈利负=亏损
- 收入合计 = REV_001+002+003+004 求和（**无 REV_TOTAL 独立科目**，这是之前修过的 bug，见 memory）

### 5.3 科目存在性待校验（开发第一步必做）
单月预算表的 PROF_006/PROF_002 是否为独立科目，**需上传后查库验证**：
```sql
SELECT DISTINCT subject_code FROM analysis_raw_data 
WHERE upload_id=<新> AND data_type='month_budget';
```
- 若有 PROF_006 → 直接取
- 若无 → 用公式重算（EBITDA=收入+成本+营业外收支，与 compute.go line 147 V4 公式一致）

### 5.4 文件名识别（关键）
阳阳的单月预算表文件名需含 `单月预算` 或 `month_budget` 才能被识别。
- 当前磁盘文件名：`02.学前教育-单月预算（5月）.xlsx` ✅ 含"单月预算"可识别
- 注意：不能让"单月预算"被"期间预算"抢先匹配 → 识别顺序 month_budget 在 period_budget 之前

### 5.5 兼容性
- 单月预算可选传（6 or 7 文件），未传时单月预算字段=0，前端 fmtPct 返回"-"，不报错
- 老上传记录无新字段，AutoMigrate 后默认0，不影响历史数据展示

### 5.6 代码风格（匹配现有）
- Go：字段对齐、GORM tag 风格一致、注释用中文行内 `// xxx`
- Vue：el-table-column 结构与现有一致，复用 fmtW/fmtPct 不新造函数
- 命名：单月实际用 `Month` 后缀，单月预算用 `MBudget` 后缀（与现有 PBudget 累计预算后缀对称）
