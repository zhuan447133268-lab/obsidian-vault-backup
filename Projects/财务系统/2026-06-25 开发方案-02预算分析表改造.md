## 三、数据能取到吗？

### 根本策略改变

`AnalysisGardenData` 是预计算宽表（手写赋值每个字段），要做 70 科目×多数据块 = **必须绕开宽表，直接查 `analysis_raw_data`（EAV 表）**。

EAV 表结构：`(upload_id, garden_code, subject_code, data_type, value)`，天然支持 `GROUP BY subject_code` 聚合。

### 逐列数据源

| # | 列 | 数据源 | 能取？ | 说明 |
|---|---|---|---|---|
| 1 | 报表项目 | subject_code → 科目字典名称 | ✅ | 已有 `subject_dict` |
| 2 | 全年预算 | `year_budget` from raw_data | ✅ | GROUP BY subject 聚合 |
| 3 | 累计期间预算 | `period_budget` from raw_data | ✅ | 同上 |
| 4 | YTD累计实际 | `ytd_actual` from raw_data | ✅ | 同上 |
| 5 | 去年累计实际 | `ytd_actual_ly` from raw_data | ✅ | 同上，同比分母 |
| 6 | 累计达成率 | = 列4 ÷ 列3 | ✅ | 前端 fmtPct |
| 7 | 累计同比 | = (列4 − 列5) ÷ \|列5\| × 100% | ✅ | 前端算 |
| 8 | 单月预算 | `month_budget` from raw_data | ❌ | **上传页方案做完才有** |
| 9 | 单月实际 | `month_actual` from raw_data | ✅ | raw_data 有，GROUP BY 即得 |
| 10 | 单月达成率 | = 列9 ÷ 列8 | ⏳ | 等列8就绪 |

### 降级判断逻辑

```typescript
const hasMonthBudget = computed(() => {
  // 任意科目有单月预算值即认为已传
  return list.value.some((row: any) =>
    row.month_budget && row.month_budget !== 0
  )
})
```

## 四、需要后端新增的 API

当前 `GET /analysis/budget-analysis` 返回 `AnalysisGardenData[]`（园所为行），结构不对。

需新增或改造为返回 **按科目聚合的数据**：

```
GET /analysis/budget-analysis?scope=group&uploadId=xxx

返回:
{
  list: [
    { subjectCode: "REV_001", subjectName: "学费收入", group: "收入类",
      yearBudget: 1200, periodBudget: 500, ytdActual: 440, ytdActualLy: 520,
      monthBudget: 100, monthActual: 90 },
    ...
  ]
}
```

后端逻辑：查 `analysis_raw_data`，按 `subject_code` + `data_type` 聚合（集团=SUM所有在营园，单园=WHERE garden_code），一次查询覆盖所有 data_type。

## 五、三个待用户确认的决策

### ⚠️ ① 单月同比要不要？

```
单月同比 = (单月实际 − 去年单月实际) ÷ |去年单月实际| × 100%
```

- 数据源 `month_actual_ly` 在 raw_data 里存在 ✅
- 加就 **11 列**（多一列"单月同比"）
- 不加就保持 10 列

### ⚠️ ② 70 行全展示 or 分组折叠？

- **方案 A**：70 行全部展示（忠实 V3，但很长要滚动）
- **方案 B**：分组折叠（默认展开小计行如收入合计/成本费用合计/EBITDA/税后利润，明细可展开）
- 建议 B，跟 V3 分组一致

### ⚠️ ③ 默认集团汇总 or 单园？

- V3 是单园视角
- 原型如果给阳阳看的是集团汇总 → 默认集团
- 顶部加园所下拉切换（集团 / 具体园所）
- 建议默认集团 + 下拉切单园
