## 三、业务理解（1分钟）

袁阳阳每月从 NC 导出 6 张 Excel → 手动拆分 142 个园所 → 手动做预算分析表 → 邮件分发。

**解决方案**：上传 6 张表 → 系统自动处理 → 98 个在营园看板 + 1 个集团看板 + Excel 导出 → 按角色分发。关园 44 个不生成单体看板。

## 五、核心设计亮点（2分钟）

### 5.1 三层防御体系

```
第一道：每表独立 headerMap     → 消除列号依赖
第二道：字段名匹配取值         → 消除 `row[67]` 硬编码
第三道：SubjectCode 归一化     → 消除跨表列偏移 + 表头微调影响
```

### 5.2 内容匹配筛选（非位置绑定）

关园识别、板块汇总过滤全部按**字段内容**判定，禁止绑定行号/列号——因为业务方确认存在增删行/列的可能。

### 5.3 企微自然失效

园长访问控制不靠系统主动禁用，靠企微统一身份认证。关园/调岗场景由"映射只增不删"运维约定覆盖，无需复杂状态管理。

### 5.4 编码化字段体系

`analysis_subject_dict` 字典表：80 个报表项目的自定义编码。科目改名仅改字典，无需迁移数据。前端通过编码渲染中文。

### 5.5 预算分析表（杀手功能）

替代阳阳每月手动做表+发邮件。预算达成率 = 累计实际 / 累计期间预算。

## 八、风险与应对

数据脱敏 → **三阶段验证**：A.阳阳确认维度规范（已完成）/ B.导入时内置等式 warning 日志 / C.真实数据时对汇总数字。

核心思想：代码写校验卡点（做），最终准确性交还给真实数据（验）。与 Comet 方法论"做验分离"一脉相承。
