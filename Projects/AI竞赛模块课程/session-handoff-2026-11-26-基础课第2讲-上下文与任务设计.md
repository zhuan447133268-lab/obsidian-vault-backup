## 1. 上下文那半边：为什么管 / 什么时候压 / 压完怎样

用户给了四个方案，并要求补别的方案 + 讲清「为什么管、什么时候压、压完会怎样」。以下均已查证，**别再从头查**。

### 1.1 为什么管：三道墙
- **容量硬截断**：最早的消息先丢——**开头立的规矩最先没**。
- **成本墙**：每轮重发全部历史，加速涨；大窗口 ≠ 便宜。
- **准确度墙**：「迷失在中段」、杂音稀释注意力。
- **「越聊越笨」有研究支撑**（context rot，长会话准确率可测下降），不是学生错觉。
- 术语（context rot / lost-in-the-middle / compaction）**只进老师 note，不上屏幕**。

### 1.2 什么时候动手（动手时机）
- 60% 用量还撑得住，不用管。
- **85% 开始绕圈、重复问同一件事 = 该主动整理的信号**。
- 等到报错或被强制截断就晚了——那时系统裁掉的恰恰是最前面的规矩。
- 讲法落点：**别等爆了才整理，看到绕圈就动手**。

### 1.3 压完会怎样（代价，最容易被讲成「让它总结就行」）
- 摘要**保框架丢细节**：任务、做过什么决定、还有什么没做完留得住；精确数字、原话、事件顺序会丢。
- 摘要是**生成的**：它总结错了，后面每一轮都基于错的往下走。
- 摘要**不可逆**：压完找不回原话；只有存成文件 / 放进知识库，原文才还在。
- **数字、代码、日期这类逐字敏感内容，宁可整段留或整段丢，别压一半**——压一半最危险。
- 真正要紧的规矩（格式、目标、关键约束）**钉在压缩预算之外**，不能跟着对话历史一起被压。

## 2. 六个办法分三档（用户的四个都收进来了）

| 档 | 办法 | 适用 |
|---|---|---|
| 应急 | ①快满时让它总结（先交接再续） | 会话已经很长，当下救急 |
| 稳 | ②新会话先读背景文件（推荐主推） | 常规续活；**把一个固定「背景.md」养成习惯** |
| 稳 | ③项目根目录写文件 | ⚠ 讲法有坑，见下 |
| 稳 | ④存知识库、新会话先读 | 背景多、跨会话反复用 |
| 补 | ⑤把规矩钉在头尾（不进压缩区） | 格式/目标/关键约束 |
| 补 | ⑥一个任务一个会话 | 从源头减少上下文堆积 |
| 补 | ⑦固定交接文件（下一步承接） | 长任务换会话时 |

**课堂演示脚本（用户认可）**：用第 1 讲学生亲手做过的**赛事日历**——聊到二十几轮，故意问「我一开始要筛哪几项来着」，让它当场答不上来；学生自己撞墙后，再现场演一遍「开新会话 → 先读背景文件 → 接着做」，前后对照。

### ⚠ 两个工具坑（必须在课上拦掉）
- **`AGENTS.md` 是 Claude Code / Codex / Cursor 读的开放标准（Linux Foundation Agentic AI Foundation），WorkBuddy 不认**。用户提的「根目录写 agent.md」不能照讲，否则学生回去做不生效。落地一律换成：**写一个「背景.md」，每次新会话开头先让它读**。AGENTS.md 只作老师口头补一句，不进板书、不要求学生做。
- 用户已确认**上机工具按 WorkBuddy 排**（第 1 讲定的），AGENTS.md 留补充。

## 3. 任务设计那半边：核心是别重复第 1 讲

**分工判断（解释为什么两半边放一讲）**：
- **上下文 = 给它什么**（输入侧：资料够不够、会不会撑爆、聊久了怎么续）
- **任务设计 = 怎么把活派出去**（输出侧：要它做什么、交出什么样、怎么算合格）

第 1 讲 **P11 已经埋过种子**：「做什么 / 怎么做 / 给谁用」+「需求越清楚，交付越好」。第 2 讲不能重复发现象，要往上长一层——**从「发一句话」升级成「一张能反复用的任务卡」**。

**讲三件事就够**：
1. **别描述材料，直接贴进去**——它不知道你的具体情况，只知道你给它的那屏。「我的材料是关于 X 的」没用。
2. **输出规格写全，否则必返工**——给谁看、多长、什么格式、不要什么，四项缺一项等着重做。
3. **留痕，才能复现、才能说清是你做的**——资料、提示、版本一起存，命名 `日期_任务_v1`。

**课堂演示用「只改一项」**：同一份材料，受众从「新生」改成「家长」，当场看输出整体变——学生一眼懂「输出规格不是废话」。通用案例用《6讲基础课-单课结构设计》§2.7 那份：**学校图书馆借阅规则改写成一页**。

**和 P11 的区别要说破**：上次是发一句话，这次是写一张卡；上次管一次对话，这次管**跨会话的一整趟活**。

## 4. 《任务设计卡》一卡三用（本讲核心设计）

这张卡恰好是上下文那半边的答案——**既是任务设计的产物，又是新会话开头要读的「背景文件」**。两半边由此接上。

**一卡三用**：
- 发任务时 = **要求**
- 换会话时 = 先读的**背景**
- 交作业时 = **留痕**

**六行**：背景资料 / 要做什么 / 输出规格四项 / 怎么验收 3 条 / 拿不准的标出并反问 3 个问题。

## 5. 「信息不够先反问」——用户口径与落地

**用户的口径比「让 AI 标不确定」更对**：
> 不确定不是甩给 AI 猜，是**人去查了再补给它**；真正难的是「我自己都不知道该补什么」——这时候要有一套能直接照做的反问引导。

**grill-me 调研结论（别讲成学生能用的东西）**：Matt Pocock 的开源 skill（MIT，**非 Anthropic 官方**），反过来一轮轮追问到每个决策分支定死才动手。硬门槛：要安装，且是 Claude Code / Codex 的 skill，**WorkBuddy 不认**。→ 不进学生作业，只作口头「有这招」。
