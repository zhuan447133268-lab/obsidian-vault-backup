# 赛事图 · 打赛线路图 —— 产品定义与 12 天排期

> **参赛赛事**：2026 Qoder 高校创造力大赛 · StudyHack 赛道
> **一句话**：把一年的比赛画成一张地铁图，学生选自己的身份，地图告诉他该在哪一站上车。
> **关联**：[[2026-11-18 Qoder高校创造力大赛-赛事档案与个人参赛评估]] · [[2026-11-03 参赛校历-2026秋至2027夏]] · [[2026-11-09 赛事适配验证-哪些能当课程锚点]] · [[2026-11-03 赛事锚定方法-判据与课次节奏]]

## 0 为什么是这个题

学生参赛的第一道门槛不是能力，是信息差：不知道一年有哪些赛、哪个够得着、什么时候报名、要交什么。市面上的赛事日历是列表，看完仍然不知道"我该打哪个"。

地铁图解决的是"路线选择"：线路 = 能力方向，站点 = 比赛，换乘 = 同一件作品可以改投，时间轴 = 学期。选完身份，不能上的线变灰，能上的站高亮，点站出倒排。

**差异化来源**：赛事数据、四关适配判定、D−35 倒排方法，都是课程项目里已经跑通的东西，不是现场编的。

## 2 核心流程（4 步闭环）

1. **选身份**：年级 / 方向（设计·代码·数据·写作）/ 每周可投入时间 / 是否有队友 / 是否只打免费赛；
2. **看线路**：地图实时筛选，不可行的线路与站点变灰，够得着的 3 站高亮；
3. **点站看详情**：报名窗口、组队规则、资格、费用、交付物、官网、匹配理由；
4. **生成我的路线**：加入站点 → 按时间排序 → 从截止日倒推 4 周计划 → 打印 / 导出日历。

## 3 信息架构（4 屏）

| 屏 | 内容 | 关键交互 |
|---|---|---|
| S1 地图首页 | 页头一句话 + 身份选择条 + 地铁图 + 图例 + 数据截止说明 | 选择即筛选；站点 hover 出站牌；点击开抽屉 |
| S2 站点详情 | 抽屉/底部弹层：站名、线路、时间、组队、资格、费用、交付物、官网、匹配理由 | 「加入我的路线」；「查看官网」 |
| S3 我的路线 | 已选站点按时间排序；每站 4 周倒排；合计投入时间 | 删除站点；打印；导出 .ics |
| S4 数据说明 | 数据来源、核实状态、免责声明、反馈入口 | 返回地图 |

## 4 数据模型（每站 22 个字段）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 稳定标识 |
| `name` | string | 赛事全称 |
| `short` | string | 站牌短名（≤8 字） |
| `line` | enum | 作品线 / 数据线 / 创新线 / 练手支线 |
| `pos` | number | 图上横坐标：0 = 9 月，11 = 次年 8 月，可带小数（如 6.5 = 3 月中） |
| `applyStart` / `applyEnd` | date|null | 报名或提交窗口；未知填 null |
| `eventDate` | string | 校赛/省赛/国赛时间，允许"3 月中—4 月中"这类区间 |
| `teamSize` | string | 如 "2—9 人"、"1—3 人"、"单人可报" |
| `minTeam` | number | 最低成队人数；硬过滤用它判断"单人能不能上" |
| `crossSchool` | bool|null | 是否允许跨校组队 |
| `grades` | number[] | 可报年级，1—4 本科、5 研究生；硬过滤用它判年级 |
| `eligibility` | string | 学籍/年级/专业限制 |
| `fee` | string | 报名费；未知写"通知未列" |
| `feeAmount` | number|null | 报名费数值（元）；null = 未知，0 = 免费 |
| `deliverable` | string[] | 交付物 1—3 项 |
| `workload` | number | 每周建议投入小时 |
| `tags` | string[] | 设计 / 代码 / 数据 / 写作 / 答辩 |
| `link` | string | 官网 |
| `status` | enum | 已核实 / 推断 / 待定 |
| `gate` | string | 报名闸门（学校统一报名 / 个人报名 / 校级赛点） |
| `note` | string | 一句话提醒 |

> `pos`、`minTeam`、`grades`、`feeAmount` 四个字段是原型阶段补的：图上位置、最低人数、可报年级、费用数值如果靠解析 `teamSize` / `fee` 这类中文串来取，改一个字就崩，所以拆成结构化字段，中文串只用于展示。

## 6 匹配规则（前端可算，不用模型）

**硬过滤（不满足即变灰）**

- 年级/学籍不在范围；
- 只打免费赛，且 `fee` 明确收费；
- 单人，且 `teamSize` 最低人数 > 1；
- `workload` > 用户每周时间 × 1.2。

**排序分（0—100）**

| 项 | 权重 | 算法 |
|---|---|---|
| 方向匹配 | 40 | 用户方向命中 `tags` 得满分，部分命中按比例 |
| 时间可行 | 30 | 截止日距今天 ≥ 4 周满分，2—4 周减半，<2 周为 0 |
| 投入匹配 | 20 | `workload` 与用户时间越接近越高 |
| 信息可靠 | 10 | 已核实 10 / 推断 6 / 待定 3 |

**输出**：分数前 3 标"现在能上"，第 4—5 标"下一站"。

## 8 技术边界

- **纯静态**：HTML + CSS + 原生 JS，无框架、无后端、无外部 CDN。
- 数据放 `data.js`，一个数组；改数据不改逻辑。
- 状态存 `localStorage`：`racemap.profile`、`racemap.route`。
- `.ics` 用 Blob 在前端生成，每站两个事件：**报名开始**、**报名·提交截止**；日期未核实的站点在事件标题后加「（按往年推断）」。
- 打印用 `@media print`，隐藏导航与地图，只留路线。
- 无 API Key、无上传、无登录。

## 10 作品帖结构

**标题**：【StudyHack】赛事图 RaceMap——把一年的比赛画成一张地铁图

1. **自我介绍**：在校生 + 做竞赛课设计，见过太多学生"想参赛但不知道打什么"。
2. **作品是什么**：一句话——选 4 个条件，地图告诉你这一年该在哪几站上车。
3. **为什么做**：赛事信息散在各校通知里，列表式日历解决不了"我该打哪个"。
4. **怎么用**（4 步）：选身份 → 看高亮 → 点站 → 加入路线并导出。
5. **用 Qoder 怎么做出来的**：模板建站 → 对话改地图布局 → 站点设计画布调版式 → 发布；每步配截图。

**截图清单**：地图全貌 / 筛选前后对比 / 站点抽屉 / 我的路线与导出。

## 11 风险与减法

| 风险 | 处理 |
|---|---|

| 被判定为"赛前已有项目" | 全部代码在 11-18 后新建；作品帖贴出 Qoder 对话与提交记录 |
