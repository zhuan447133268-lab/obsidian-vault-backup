# 高校教师 AI 数字素养培训完整方案（2026 年 9-12 月）

> 版本：2026-07-14
> 状态：9-10 月四次课程 + 学分认证已确认；11-12 月课程框架待填充

---

## 一、项目背景与目标

### 1.1 背景

高校教师已普遍具备通用 AI 工具使用能力（通义、DeepSeek、Kimi、即梦、ima 等），但尚未系统掌握将 AI 深度工具化、产品化的能力。

### 1.2 核心目标

让教师从"会用 AI 工具"进阶到"能用 AI 改造工作与课程"，并形成可验收、可展示的过程性成果。

**不是**教教师"用更好的 LLM 写东西"，**而是**教教师"用 AI Agent 把反复做的事变成可运行的工具/网页"。

### 1.3 培训理念

- **体验优先**：每节课让老师带走一个能用的东西。
- **真实场景**：全部案例来自教学/办公真实痛点。
- **成果可见**：每阶段有保底成果，最终有认证证书。
- **不依赖前置**：单次课可独立参加，降低参与门槛。

### 2.1 设计原则

1. **递进但不强制连贯**：每节课可独立参加，不依赖上一节课的具体产物。
2. **第一次课教授 WorkBuddy 基础操作**，后续课程不再重复教工具。
3. **强调 Agent 能做 LLM 做不到的事**：操作电脑、接系统、发钉钉。
4. **成果导向**：每节课有保底成果，每阶段有认证考试。

## 三、第一阶段：9 月培训课程详情（已确认）

### 3.1 课程总览

| 课次 | 主题 | 一句话说明 | 形式 | 时长 |
|---|---|---|---|---|
| 第一次 | AI Agent 全景体验 + WorkBuddy 入门 | **体验 AI 的"手"和"脚"**：让 AI 帮你整理文件、查证资料 | 机房实操 | 2.5 h |
| 第二次 | 用 WorkBuddy 做教学/办公小工具 | **作业提交、随机点名等小工具开发体验**：用自然语言生成可运行网页 | 机房实操 | 2 h 20 min |

### 3.2 第一次课：AI Agent 全景体验 + WorkBuddy 入门

**核心目标**：让老师知道 Agent 能干什么，并掌握 WorkBuddy 基础操作。

#### 两个体验式案例

**案例一：文件整理（AI 能动手）**

- 课前预置 `样例_学生作业` 文件夹，内含 11 个文件名混乱的学生作业文件。
- 老师使用 WorkBuddy 执行整理：按【学号_姓名】重命名、新建 `学生作业_已整理` 文件夹、生成 `名单.xlsx`。

**案例二：调研报告（AI 能查证）**

- 先让纯 LLM（网页版 Kimi/DeepSeek）生成调研报告并现场点链接验证，展示 LLM 链接可能编造。
- 再用 WorkBuddy 生成带真实来源链接的 Markdown 报告，现场点击验证。
- 老师自选专业课题（教改政策、竞赛政策、专业认证、课程建设等）生成带链接简报。

#### 课堂流程

| 阶段 | 时长 | 内容 |
|---|---|---|
| 开场 + 目标介绍 | 10 min | 今天体验 AI 的两个超能力：动手 + 查证 |
| 能力全景秀 | 15 min | 快速展示 WorkBuddy 能做什么 |
| 案例一：整理文件 | 60 min | 演示乱文件 → AI 整理 → 老师上手 → 展示成果 |
| 案例二：调研报告 + LLM 对比 | 60 min | LLM 对比演示 → 老师自选主题调研 → 点链接验证 → 展示讨论 |
| 总结 Agent vs LLM | 15 min | 两个案例共同说明 Agent 的不可替代性 |
| 下节课预告 | 5 min | 下次用 WorkBuddy 做一个自己的教学工具 |

#### 保底成果

- 一个整理后的学生作业文件夹 + 名单表
- 一页带真实来源链接的 Markdown 调研简报

#### 进阶成果

- 把文件整理规则保存为可复用的 WorkBuddy 提示词，课后能直接用于真实班级作业整理。
- 把调研简报扩展为一份可直接提交给领导/教务处的完整调研报告（含封面、目录、3-5 个权威来源引用）。
- 能够独立识别"AI 能动手做"和"AI 能查证"两类工作场景，并写出对应提示词。

### 3.3 第二次课：用 WorkBuddy 做教学/办公小工具

**核心目标**：让老师体验"用自然语言生成可运行工具"，并处理真实工作材料。

#### 三大模块

| 模块 | 主题 | 产出 |
|---|---|---|
| **M1** | 作业提交网页工具（前后端分离） | 一个可运行的作业提交前端页面 |
| **M2** | 课堂随机点名工具 | 可本地运行的随机点名网页 |
| **M3** | 零散报名信息整理成总表 | 从截图/Word/PDF 提取的报名总表 Excel |

#### M1：作业提交网页工具

- 讨论收作业痛点（5 min）
- 讲师演示前端生成（10 min）
- 老师上手做前端（20 min）
- 后端真实效果演示（10 min）
- 成果展示（5 min）

**课后延展**：提供后端代码模板（Python Flask / Node.js）和部署说明，老师可选补全后端。

#### M2：课堂随机点名工具

生成网页版随机点名工具，支持：
- 上传 Excel/CSV 班级名单或手动输入
- "开始随机点名"按钮，随机抽取并高亮显示
- 显示抽取记录，可导出 CSV
- 进阶：已抽过的短期内不重复、可设置一次抽几人、显示总人数和已抽取人数

#### M3：零散报名信息整理成总表

- 课前桌面预置 `报名` 文件夹，内含微信截图、Word、PDF
- 老师用提示词提取报名信息，整理成 `报名总表.xlsx`
- 列包括：姓名、联系电话、报名志愿、信息来源文件名
- 识别不清的标注"需人工核对"

#### 课堂流程

| 阶段 | 时长 |
|---|---|
| 开场 + 回顾第一次课 | 10 min |
| M1：作业提交网页工具 | 50 min |
| M2：随机点名工具 | 35 min |
| M3：报名信息整理 | 35 min |
| 总结 + 下节课预告 | 10 min |
| **合计** | **2 h 20 min** |

#### 保底成果

- 一个作业提交前端页面
- 一个随机点名工具
- 一张报名总表

#### 进阶成果

- 作业提交工具对接真实后端并部署到内网/服务器，下学期可直接用于收作业。
- 随机点名工具增加"一次抽 N 人"、"历史记录统计"、"黑名单/白名单"等功能。
- 把报名信息整理流程写成可复用提示词，后续新报名一键生成总表。
- 基于课堂所学，额外为自己做一个教学/办公小工具（如成绩录入页、会议室预约页等）。

|---|---|---|---|---|
| 第三次 | ima 知识库 + 钉钉跨系统办公 | **AI 的外接大脑生成活动方案**：让 AI 读知识库、读钉钉文档、自动发文件 | 机房实操 | 2.5 h |
| 第四次 | AI Agent 工作流方法论工作坊 | **从真实痛点到可运行工具 + 颁证**：分组做一个能用的 AI 工具并路演 | 分组 workshop + 路演 | 半天 |

### 4.2 第三次课：ima 知识库 + 钉钉跨系统办公

**核心目标**：AI 接入个人知识库（ima）和办公系统（钉钉），跨系统取资料、生成方案、真实交付。

#### 三个核心认知

1. **持久记忆**：ima 是长期留存、跨设备可调的资料库。
2. **跨系统取数**：AI 能从 ima 读资料，也能从钉钉读文档。
3. **真实动作与交付**：成果落到电脑，还能通过 WorkBuddy 发到钉钉成员。

#### 四段任务

| 任务 | 主题 | 时长 |
|---|---|---|
| A | 接入 ima + 检索：从知识库找出指定主题内容并标注来源 | 20 min |
| B | 基于 ima 生成项目方案：生成 PBL 项目方案，引用知识库具体文件 | 40 min |
| C | 接入钉钉取数：读取钉钉文档内容，补充进方案 | 25 min |
| D | 真实交付：把生成的文件通过钉钉发给指定成员 | 25 min |

#### 关键调整

- **不碰钉钉群聊记录**，只读取钉钉文档，规避隐私和权限风险。
- **统一做 PBL 项目方案**，更通用，避免部分老师无申报经验。
- **以样例知识库为主**，老师自备文件为辅，避免现场找文件的混乱。

#### 课堂流程

| 阶段 | 时长 | 内容 |
|---|---|---|
| 开场 + 9 月回顾 | 15 min | 回顾前两次课，引出"AI 接入系统和知识库" |
| 准备 | 20 min | ima 登录绑定 + 钉钉连接确认 |
| Task A：ima 检索 | 20 min | 从知识库找内容并标注来源 |
| Task B：生成 PBL 方案 | 40 min | 基于知识库生成方案，引用具体文件 |
| Task C：接入钉钉取数 | 25 min | 读取钉钉文档，补充进方案 |
| Task D：发钉钉 | 25 min | 把文件发到指定测试成员 |
| 收尾 | 10 min | 分享 + 边界提醒 |

#### 保底成果

- 一份基于 ima 知识库生成的 PBL 项目方案
- 一次把生成的文件发送到钉钉的真实体验

#### 进阶成果

- 建立一个自己课程/专业的 ima 知识库，并把生成的方案迁移进去持续迭代。
- 生成的 PBL 项目方案被真实用于课程申报、教改项目或教研室讨论。
- 完成一次真实的跨系统办公任务（如：读钉钉审批表 → 生成汇总 → 发钉钉通知）。
- 把"ima + 钉钉"工作流写成标准操作文档，分享给同教研室其他老师。

### 4.3 第四次课：AI Agent 工作流方法论工作坊

**核心目标**：9-10 月培训收官，分组研讨 + 协作生成工具 + 小组路演 + 颁发认证证书。

#### 让老师带走三样东西

1. 一套可复用的 **AI Agent 工作流方法论**：找痛点 → 拆任务 → 描述给 AI → 验证迭代。
2. 一个 **小组共同完成的可运行工具**。
3. 一份 **AI Agent 能力认证证书**。

#### 分组与角色

- 每组 3-4 人，跨学院/跨专业分组。
- 每组至少配 1 位会用 WorkBuddy 的老师。
- 角色分工：
  - **组长**：把控方向，协调讨论，拍板题目。
  - **痛点分析师**：把问题拆成 AI 能做的步骤。
  - **提示词工程师**：把任务写成 WorkBuddy 提示词。
  - **测试汇报员**：测试工具并准备路演。

#### 完整流程

| 阶段 | 时长 | 内容 |
|---|---|---|
| 开场 + 方法论串讲 | 30 min | 回顾 9-10 月三次课，讲解四步工作流 |
| 分组研讨找痛点 | 30 min | 小组填 AI Agent 工作画布，确定题目 |
| 用 WorkBuddy 生成工具 | 80 min | 小组写提示词、生成、测试、迭代 |
| 准备路演 | 20 min | 每组准备 5 分钟展示材料 |
| 小组路演 + 互评 | 60 min | 每组 5 分钟展示 + 2 分钟提问 |
| 颁证 + 总结 | 20 min | 颁发证书、宣布优秀小组、11 月预告 |

#### 路演评分标准

满分 40 分，四个维度各 10 分：
1. **痛点真实性**：是否是真实工作场景中的问题。
2. **AI 适用性**：AI 是否比传统方法明显更好。
3. **工具完成度**：现场能否跑通，功能是否完整。
4. **展示清晰度**：问题、方案、演示是否讲清楚。

**加分项**：使用 ima/钉钉（+3）、跨系统完成真实动作（+3）、有课后使用计划（+2）。

#### 认证证书规则

- **发放标准**：完成 9-10 月培训至少 **3 次出勤** + 参加第四次 workshop 并完成小组任务。
- **额外激励**：优秀小组奖、最佳创意奖、最佳技术奖、最佳展示奖。
- 证书建议加盖总部/学校印章，增强仪式感。

#### 保底成果

- 小组完成一个现场可运行的 AI 工具。
- 每位成员获得 AI Agent 能力认证证书（9-10 月出勤 ≥3 次 + 完成小组任务）。
- 掌握"找痛点 → 拆任务 → 描述给 AI → 验证迭代"四步工作流。

#### 进阶成果

- 小组工具在课后真实工作中持续使用 ≥1 个月。
- 工具被学院/学校采纳并推广给其他老师使用。
- 产出校级优秀案例，参评教学创新/教改项目。
- 以本工具为基础，申请中级/高级认证考试或 12 月独立项目。
- 在 workshop 路演中获得优秀小组/最佳奖项。

#### PLAN B 兜底机制

如果小组找的痛点不适合 AI：
1. **AI 适合解决的痛点菜单**：从菜单里勾选或改编。
2. **通用改造题库**：提供 6-8 个可直接做的题目。
3. **9-10 月工具箱模板改造**：从第一次/第二次/第三次课模板选一个改造。
4. **助教快速分流**：每组填完画布后，助教 1-2 分钟判断是否适合 AI。

## 七、学分认证体系（已确认）

### 7.1 核心设计

建立 **"学分累计 + 等级认证 + 绩效考核"三位一体** 激励机制。

### 7.2 年度学分上限

- **100 分/年**

### 7.3 学分获取规则

| 行为 | 学分 |
|---|---|
| 参加线下培训 | 5 分/次 |
| 参加 AI 沙龙 | 2 分/次 |
| 完成理论学习模块 | 3 分/模块 |
| 提交保底成果 | 3 分/次 |
| 提交优秀案例 | 5 分/次（优秀再加 3 分） |
| 通过初级/中级/高级认证考试 | 10/15/20 分 |
| 通过阿里云认证 | 15 分 |
| 带动其他老师完成初级认证 | 3 分/人 |

### 7.4 四级认证

| 认证 | 学分要求 | 其他条件 |
|---|---|---|
| **初级认证** | ≥ 30 学分 | 完成 9-10 月课程 + 通过初级考试 |
| **中级认证** | ≥ 60 学分 | 完成 11 月课程 + 通过中级考试 |
| **高级认证** | ≥ 85 学分 | 完成 12 月课程 + 通过高级考试 + 独立项目 |
| **骨干认证** | 获得高级认证 | 带领 ≥ 3 人完成初级 + 产出校级优秀案例 |

### 7.5 认证证书

- 初级/中级/高级：完成对应课程 + 通过考试后发放。
- 骨干认证：在高级认证基础上，满足带动他人和产出优秀案例条件后发放。

## 八、绩效考核挂钩（已确认）

### 8.1 考核占比

### 8.2 考核分构成

```
AI 素养考核分 = 基础分（60%）+ 激励分（40%）
```

- **基础分**：获得初级认证即满分 60 分。
- **激励分**：中高级认证、成果、分享等，上限 40 分。

### 8.3 全员参与策略

- 初级认证全员必修，未完成者年度考核 AI 素养项不得分。
- 分学院/分批次推进。

- 建立学分看板，每月通报各学院进度。
