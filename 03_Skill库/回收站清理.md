# 回收站清理（删文件走回收站，可恢复）

## 适用场景

需要**删除或整理个人目录下的文件**，但希望操作**可恢复**（走回收站而非永久删）。典型触发：
- 清掉工作区里的一次性脚本 / 调试日志 / 探测输出
- 整理 `01_原料库` / `04_输出库` 等散落文件
- 打包/归档前清掉 `_bak`、`_tmp`、`__pycache__` 等中间产物

**不适用**：
- 已确认可永久删且不涉数据安全的目录（如构建产物）——此时可直接 `[System.IO.File]::Delete()` 回收站更快。
- 跨盘 / 网络盘 / 回收站本身——`SHFileOperationW` 的 `FOF_ALLOWUNDO` 只保证**本地盘**进回收站。

## 触发条件

用户说以下任意一种表达：
- 「清一下」「删掉」「整理散文件」「清 tmp」
- 「这些文件还有必要吗」「根目录有没有垃圾」

## 核心原则（不可违反）

1. **先判定再动手**：全量清点 → 逐文件定性 → 核产物是否固化 → grep 查引用 → 才允许删。
2. **只删「零引用 + 产物已固化」的文件**：任何一个环节存疑，列出来让用户拍板，不擅动。
3. **走回收站，不永久删**：`SHFileOperationW` + `FOF_ALLOWUNDO`，可恢复。
4. **批量用 `"\0".join` 一次传**：扛得住中文路径，比逐个删稳定。
5. **判据是 `os.path.exists` 而非返回码**：`SHFileOperationW` 多文件删除时尾项状态会让 `rc=2`，但文件实际已进回收站。

## 执行步骤

### 第一步：清点（listdir 全量）

```python
import os
ROOT = r"D:\培训temp"
for f in sorted(os.listdir(ROOT)):
    p = os.path.join(ROOT, f)
    if os.path.isfile(p):
        print("%-30s %10d B" % (f, os.path.getsize(p)))
```

### 第二步：定性（逐文件读内容）

对每个候选文件，读前 40 行判定：
- 一次性脚本（`_patch_xxx.py`、`_probe.txt`）→ 通常可删
- 常驻工具（`pack_skill.py`、`check_deliverables.py`）→ **不删**
- 调试日志（`_fivecheck.log`、`_gen.log`）→ 可删
- 探测输出（`_find_*.txt`）→ 可删（产物 grep 验证后）

### 第三步：核产物 + 查引用

```bash
# grep 全工作区，确认没有任何文件引用该脚本
grep -rn "_patch_skill_v141" D:\培训temp\ --include="*.md" --include="*.py"
# 若命中 0 条，确认脚本的一次性产物已固化在别处
```

### 第四步：走回收站删除（`SHFileOperationW`）

```python
import ctypes, os
from ctypes import wintypes

class SHFILEOPSTRUCTW(ctypes.Structure):
    _fields_ = [
        ("hwnd", wintypes.HWND),
        ("wFunc", wintypes.UINT),
        ("pFrom", wintypes.LPCWSTR),
        ("pTo", wintypes.LPCWSTR),
        ("fFlags", ctypes.c_uint16),
        ("fAnyOperationsAborted", wintypes.BOOL),
        ("hNameMappings", ctypes.c_void_p),
        ("lpszProgressTitle", wintypes.LPCWSTR),
    ]

def send_to_recycle(paths, log):
    """一次传多文件，可恢复。"""
    for p in paths:
        assert os.path.exists(p), "文件不存在: " + p
    pfrom = "\0".join(paths) + "\0\0"
    op = SHFILEOPSTRUCTW()
    op.wFunc = 3  # FO_DELETE
    op.pFrom = pfrom
    op.fFlags = 0x40 | 0x10 | 0x4 | 0x400  # FOF_ALLOWUNDO|NOCONFIRMATION|SILENT|NOERRORUI
    rc = ctypes.windll.shell32.SHFileOperationW(ctypes.byref(op))
    gone = all(not os.path.exists(p) for p in paths)
    log.write("rc=%d gone=%s\n" % (rc, gone))
    assert gone, "仍有文件未进回收站"
```

**关键点**：
- `op.wFunc = 3`（`FO_DELETE`）+ `op.fFlags` 含 `0x40`（`FOF_ALLOWUNDO`）= 移入回收站，**不是永久删**。
- 多文件用 `"\0".join(paths) + "\0\0"` 一次传，比逐个调用稳定且快。
- **判据看 `os.path.exists` 全为 False**，不要信 `rc`（多文件时 `rc=2` 属正常）。
- 删除前每个文件先 `assert os.path.exists`，避免误删不存在的文件导致整个批次失败。

### 第五步：回收站核对（可选）

回收站条目枚举受安全策略限制（COM 实例化、Bash 调 PS 均被拦），无法在工具里截图核对。`SHFileOperationW` + `FOF_ALLOWUNDO` 即 Windows 官方「移入回收站」机制，本地盘默认生效，`rc=0` + `os.path.exists=False` 为充分证据。**用户可自行开回收站确认**，不必在工具里硬核对。

### 第六步：清诊断件 + 写日志

删完顺带清掉本次自己留下的临时侦察件（`_scan_xxx`、`_probe.txt` 等），日志留在 `_skill_tools/` 下，命名 `cleanup_YYYYMMDD_*.log`。

## 注意事项

- **回收站容量**：一次清 40 MB 没问题，但单次清 2 GB+ 时提醒用户磁盘剩余空间。
- **跨盘**：`D:` 和 `C:` 的回收站**独立**，`FOF_ALLOWUNDO` 只在**源盘**的回收站里可见。
- **不删 `.workbuddy/`、`.git/`、`.obsidian/`** 等系统/版本管理目录。
- **常驻工具不删**：`pack_skill.py`、`check_deliverables.py`、`contact_sheet.py` 这类被其他 skill 引用的，**无论多乱都不删**。
- **`_bak` / `_old_scripts` 先读再定**：旧版脚本有时是回滚锚点，grep 查引用后判断。
