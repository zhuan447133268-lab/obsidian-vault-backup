# nsfc-roadmap：把技术路线文字变成能送印刷的纵向路线图

## 一句话定义

一个**自研 skill**：把「总体思路 + 若干条路径 + 收口性格」的技术路线文字，生成 NSFC / 国自然风格的**纵向技术路线图**——虚线分组框、圆角卡片两级文字、正交分支汇合、段间粗蓝下箭头、底部综合结果框。一次出**纯矢量 SVG + 可编辑 Draw.io + 单页印刷 PDF + 2×/4× PNG + 预览 HTML**。

最关键的不是出图，是**改字通道**：所有文案抽到一个纯中文 `文案.py`，非程序员改完双击 `一键重出.bat`，全套图件自动刷新。

> 本机安装位置：`~/.workbuddy/skills/nsfc-roadmap/`

## 它适合 / 不适合什么

- ✅ 适合：申报书 / 答辩展板 / 结题材料的技术路线图、研究方案图、技术框架图；要求「可拉伸、送印刷、字少、评委一眼看懂」。
- ✅ 适合：内容还会反复改、且改字的人不懂代码（教师、同事、组委会对接人）。
- ⚠️ 不适合：横向三/四栏分栏式路线图（走 `nsfc-agent-skills/nsfc-figure` 自带生成器）；数据图表（走 `scientific-figure-making`）；科研插画（走 `scansci-svg-skill`）。
- ⚠️ 不适合：阶段数量要频繁增删。当前固定 4 段，增删要改生成器的纵向坐标。

## 为什么另写一份（关键判断）

`njzjz/nsfc-agent-skills` 的 `nsfc-figure` 规范很硬：**信息骨架 → 两级文本 → 正交连线 → 未压缩 `.drawio` 源 → 结构验证 → 导出视觉验收**，这套照搬。
但它自带的 `generate_roadmap.py` 只能出**横向三/四栏**分栏图，跟评委常见的「竖向分组 + 段间粗箭头 + 底部收口」不是一路。硬套会四不像 ⇒ 按它的规范另写纵向布局，并**真跑**它的两个校验脚本（`validate_drawio.py` → OK，`check_export_metadata.py` → CLEAN）。

## 版式骨架

```
页眉   主标题 / 英文副题 / 右上两行信息
每段   虚线分组框（标签骑在上边框）→ 阶段色主标题条 → 难点虚线框（可空）
       → 并列圆角卡片（标题 20px + 小注 15px，左上角三轨色标）
       → 正交母线分支 / 汇合 → 阶段产出条（可空）
段间   粗蓝渐变下箭头
收口   深墨蓝综合结果框（彩色大字 + 注句 + 标签 + 双轨闸门示意）
页脚   三轨图例 + 左右脚注
```

三轨语义色固定：橙 `#FF6A2A` 确定性计算 / 蓝 `#165DFF` 模型生成 / 青 `#00A98F` 人机校验。段色用低饱和浅色，避免跟语义色抢。连线**只许正交**，零斜线。每格只放「标题 + 一行小注」——**别把报告塞进图里**，字一多就不像路线图。

## 改字规则（这是它最值钱的部分）

| 想做什么 | 在 `文案.py` 里怎么改 |
|---|---|
| 删一句话（难点 / 产出 / 右上角一句） | 引号里清空写成 `""`，引号留着 → 整框消失、不留断线 |
| 只删卡片小注 | 第二个引号清空 → 标题自动垂直居中 |
| 删整张卡片 | 删掉那一行（连括号带逗号）→ 剩余 2~5 张自动等宽均分 |
| 删底部标签 | 从 `tags` 列表删掉那一项 |
| 改措辞 / 缩短 | 直接改引号里的中文 |

别动：4 个阶段数量、`no` 编号、`rule/model/check` 色标标记。
已做过删字压力测试（删难点框 + 3 卡减 2 卡 + 删小注 + 删产出 + 删标签）：不报错、不塌陷、卡片自动均分。

## 复现步骤

1. 把 `scripts/` 四个文件（`文案.py` / `make_roadmap.py` / `build.py` / `一键重出.bat`）复制到一个空目录。
2. 改 `文案.py`，保存。
3. 双击 `一键重出.bat`（Linux/macOS：`python build.py --no-open`）。

Python 3.9+ 纯标准库，只需 Chrome 或 Edge 做 headless 导出。无 pip 依赖。

## 交付件与用途

| 文件 | 用途 |
|---|---|
| `...svg` | **主交付**，纯矢量，文字全是 `<text>`，无限拉伸 |
| `...drawio` | 可编辑源，拖进 diagrams.net 改布局 |
| `...矢量印刷版.pdf` | **送印厂用这个**，单页 400×600mm、字体嵌入、0 位图对象 |
| `...展板4800x7200.png` / `...预览2400x3600.png` | 位图备份；印刷别用 PNG |
| `...预览.html` | 双击即看，内联 SVG 不依赖外部文件 |

## 关键事实（避坑，全部实测过）

1. **Chrome `--print-to-pdf` 用 `<img src="x.svg">` 会把整图光栅化**。必须把 SVG **内联**进 HTML 再打印，文字才是矢量文本。
2. SVG 的 `<pattern>` 网格仍会被转成位图 XObject → 网格改显式 `<line>` 循环，PDF 才彻底 0 位图对象。
3. **中文路径**：Chrome 写中文路径易报「拒绝访问」→ 先渲染到 `%TEMP%` 纯英文目录再拷回来。
4. **PDF/PNG 被预览器占用时** `shutil.copy2` 抛 `WinError 32` → `safe_copy` 重试 6 次 + 人话提示，别让人以为图坏了。
5. **`.bat` 必须 CRLF 行尾、内容全 ASCII**（中文文件名交给 `%~dp0` 和 Python），否则 cmd 代码页乱码。
6. `.drawio` 是**同源几何/文案**生成的可编辑源，不是官方 CLI 导出件；本机没装 Draw.io Desktop，在 diagrams.net 重新导出可能因字体替换产生换行差异 ⇒ **交印刷以本 skill 的 PDF/SVG 为准**。
7. 图上尽量不放会漂移的存量数字（条数 / 格数 / 版本口径）。这版刻意一个数字都没放：工作区与决赛最终版两套口径，写死会跟视频、PPT、现场界面打架。
